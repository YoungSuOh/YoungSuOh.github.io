OPay

이벤트 기반 이커머스 결제 시스템 (Idempotency · Concurrency · Stock Consistency)

💡 Topic

대규모 트래픽 환경을 가정하여, 중복 결제 방지 · 동시성 제어 · 재고 정합성을 해결한 이벤트 기반 이커머스 결제 시스템을 설계 및 구현했습니다. 개인 프로젝트인 OPay를 통해 결제 시스템의 확장성과 안정성을 구축하는 것을 목표로 진행했습니다.

⚠️ 문제 정의

  • 중복 요청(재시도, 네트워크 오류)으로 인한 이중 결제 발생 가능성
  • 동시 결제 요청 시 지갑 잔액 불일치 및 음수 잔액 문제
  • 재고 확정 이전 결제 진행으로 인한 데이터 정합성 깨짐
  • 주문 ~ 재고 ~ 결제 전체를 동기 처리할 경우 성능 병목 및 확장성 한계

🛠 핵심 설계 전략

  1. Idempotency Key 기반 요청 식별
    • DB Unique 제약 조건 + 트랜잭션으로 중복 결제 차단
  2. 지갑 정합성 보장(Concurrency Control)
    • Version 기반 낙관적 락 적용
  3. 재고 처리 비동기화(Event-Driven)
    • Transactional Outbox 패턴 적용
    • Apache Kafka 기반 이벤트 전달
  4. 상태 전이 기반 설계
  5. 운영 관측 및 검증
    • k6 부하 테스트로 TPS, Latency, 병목 구간 분석
    • Spring Actuator + Prometheus + Grafana로 메트릭 수집/시각화
