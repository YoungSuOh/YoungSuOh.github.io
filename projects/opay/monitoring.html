┌─────────────────────────────────────────────────────────────────────────────┐

2️⃣ 각 설정/코드의 역할

  1. OPay Backend 쪽

application.yml - management (Actuator + Prometheus)

# Actuator + Prometheus (모니터링)
management:
  endpoints:
    web:
      exposure:
        include: health, metrics, prometheus
      base-path: /actuator
  endpoint:
    health:
      show-details: when-authorized
  metrics:
    tags:
      application: ${spring.application.name}
    distribution:
      # Enable histogram buckets required by histogram_quantile() queries in Prometheus/Grafana.
      percentiles-histogram:
        http:
          server:
            requests: true
      # Optional direct percentile series (can be used without histogram_quantile).
      percentiles:
        http:
          server:
            requests: [0.95, 0.99]
  • "무엇을(health/metrics/prometheus), 어떤 경로(/api/actuator)로, 어떤 이름(application)으로 노출할지"를 정의하는 설정
    • 실제 열리는 엔트포인트
    • /actuator/health
    • /actuator/metrics
    • /actuator/prometheus ⭐ (제일 중요)
  • health 상세 정보 설정 
    endpoint:
  health:
    show-details: when-authorized
  • health endpoint에서 DB, Redis 등 상태를 얼마나 자세히 보여줄지 결정
    • 옵션
    값 의미
    never UP/DOWN만
    always 모든 상세 정보 노출
    when-authorized 인증된 요청만 상세
  • 공통 태그 설정 
    metrics:
  tags:
    application: ${spring.application.name}
    • 모든 Metric에 공통 label 추가
    • 예시
    http_server_requests_seconds_count{application="opay-backend"}
    • 왜 중요하냐
    • Prometheus/Grafana에서:
    • 서비스별 필터링
    • 멀티 인스턴스 구분
  • historgram 설정 
    distribution:
  percentiles-histogram:
    http:
      server:
        requests: true
    • HTTP 요청 시간을 버킷(bucket) 형태로 저장
    • Historgram이 있어야 p95, p99까지 계산 가능
    percentiles:
  http:
    server:
      requests: [0.95, 0.99]
    • Spring이 직접 P95, P99 계산해서 메트릭으로 제공

implementation 'org.springframework.boot:spring-boot-starter-actuator'

  1. Prometheus 쪽

monitoring/prometheus/prometheus.yml

global:
  scrape_interval: 15s      # 기본 수집 주기
  evaluation_interval: 15s  # 알람 규칙 평가 주기 (현재 규칙 없음)

scrape_configs:
  - job_name: 'opay-backend'                    # 수집 대상 이름 (메트릭에 job="opay-backend" 붙음)
    metrics_path: /api/actuator/prometheus    # 스크래핑할 URL 경로
    static_configs:
      - targets: ['host.docker.internal:8080'] # Backend 주소 (Docker 안에서 호스트 = host.docker.internal)
    scrape_interval: 10s                        # 이 job만 10초마다 수집
  • 전체 연결 흐름
[Prometheus 컨테이너]
        ↓
http://host.docker.internal:8080
        ↓
[Spring Boot 앱]
  1. Grafana 쪽

monitoring/docker-compose.yml

services:
  prometheus:
    image: prom/prometheus:v2.47.0 # Prometheus 공식 이미지
    container_name: opay-prometheus # 컨테이너 이름
    ports:
      - "9090:9090" # 호스트 9090 -> 컨테이너 9090
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml # A -> B로 scrape(Prometheus) 설정이 들어감
      - prometheus_data:/prometheus # TSDB 저장 위치
    command:
      - '--config.file=/etc/prometheus/prometheus.yml' # 어떤 설정 파일 쓸지
      - '--storage.tsdb.path=/prometheus' # 메트릭 저장 위치
      - '--web.enable-lifecycle' # 핫 리로드 가능 (?)
    restart: unless-stopped # 컨테이너 자동 재시작

  grafana:
    image: grafana/grafana:10.2.0 # Grafane 버전
    container_name: opay-grafana
    ports:
      - "3000:3000" # 호스트 3000 -> 컨테이너 3000
    environment:
      - GF_SECURITY_ADMIN_USER=admin # 계정 설정
      - GF_SECURITY_ADMIN_PASSWORD=admin
      - GF_USERS_ALLOW_SIGN_UP=false # 회원 가입 막기
      - GF_SERVER_ROOT_URL=http://localhost:3000
    volumes: # 대시보드, 설정 저
      - grafana_data:/var/lib/grafana
      - ./grafana/provisioning:/etc/grafana/provisioning
    depends_on: # Grafana는 Prometheus 이후 실행
      - prometheus
    restart: unless-stopped

volumes:
  prometheus_data:
  grafana_data:
  • Docker로 Prometheus + Grafana를 각각 컨테이너로 띄우고 연결하는 구성
[Spring Boot]
      ↑ (scrape)
[Prometheus]  →  [Grafana]

monitoring/grafana/provisioning/datasources/datasources.yml

Grafana가 “어디에서 데이터를 가져올지” 자동으로 등록하는 설정

앞에서 본 docker-compose의 provisioning이 바로 이 파일을 읽어서 Grafana 시작 시 자동으로 datasource를 생성

즉, Grafana가 Prometheus를 데이터 소스로 자동 연결하는 설정

apiVersion: 1

datasources:
  - name: Prometheus
    type: prometheus
    uid: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    editable: false

monitoring/grafana/provisioning/dashboards/dashboards.yml

Grafana 대시보드를 “자동으로 로딩하고 유지관리하는 설정”

즉, 화면 UI 자동 구성

apiVersion: 1

providers:
  - name: 'OPay Default'
    orgId: 1 # Grafana 조직 ID (멀티 조직ID)
    folder: 'OPay'
    type: file
    disableDeletion: false
    updateIntervalSeconds: 30
    options:
      path: /etc/grafana/provisioning/dashboards/json
