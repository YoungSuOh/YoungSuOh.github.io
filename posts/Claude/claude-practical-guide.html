Claude 실전 사용법

Claude Code CLI 명령어, 슬래시 커맨드, CLAUDE.md, MCP 연결, Hooks 자동화, 권한 제어, 비용 최적화까지 — 개발자가 실무에서 바로 써먹을 수 있는 패턴을 정리합니다.

0. 이 글의 목적

이 글은 Claude와 Claude Code를 실제 개발 워크플로우에서 어떻게 쓰는가에 집중합니다. 설치·개념 설명보다는 "오늘 당장 써먹을 수 있는" 명령어, 단축키, 설정, 패턴을 중심으로 정리합니다.

전제 환경
Claude Code CLI가 설치되어 있고, API Key 또는 Claude.ai Pro/Max 구독이 활성화된 상태를 기준으로 합니다. 설치는 npm install -g @anthropic-ai/claude-code.

1. Claude Code CLI 기본 흐름

1.1 대화 시작

# 현재 디렉토리에서 Claude Code 실행
claude

# 특정 프롬프트를 바로 전달
claude "현재 브랜치에서 바뀐 파일 요약해줘"

# 파이프 입력 — stdin을 컨텍스트로 사용
git diff | claude "이 변경사항을 PR 설명으로 만들어줘"

# 특정 파일을 읽어서 시작
claude --file src/UserService.java "이 클래스의 문제점 리뷰해줘"

1.2 세션 관리

# 이전 세션 이어서 시작 (--continue)
claude --continue

# 특정 세션 ID로 재개
claude --resume <session-id>

# 세션 목록 확인
claude sessions list

1.3 출력 모드

# JSON 형태로 출력 (파이프 처리에 유용)
claude --output-format json "현재 디렉토리 파일 구조 설명해줘"

# 스트리밍 없이 한 번에 받기 (--no-stream)
claude --no-stream "README 초안 작성해줘"

2. 슬래시 명령어 (Slash Commands)

Claude Code 세션 안에서 /로 시작하는 명령어를 사용해 도구를 제어합니다.

명령어설명
/help사용 가능한 명령어 전체 목록
/clear대화 컨텍스트 초기화 (토큰 절약)
/compact대화 히스토리를 요약해서 토큰 줄이기
/status현재 세션 상태, 모델, 토큰 사용량 확인
/model모델 전환 (opus / sonnet / haiku)
/config설정 파일 열기
/add-dir <path>추가 디렉토리를 컨텍스트에 포함
/review현재 브랜치 코드 리뷰 실행
/initCLAUDE.md 초기화 (프로젝트 가이드 자동 생성)
/cost현재 세션 비용 확인

커스텀 슬래시 명령어 만들기

.claude/commands/ 디렉토리에 Markdown 파일을 놓으면 /파일명으로 호출됩니다.

# .claude/commands/daily-review.md
---
description: 오늘 변경한 파일을 요약하고 개선점을 리포트한다
---

git log --since="midnight" --oneline 결과와 git diff HEAD 내용을 바탕으로
오늘 작업 내용을 한국어로 요약하고 개선이 필요한 부분 3가지를 제안해줘.

이후 Claude Code 세션에서 /daily-review 로 실행.

3. CLAUDE.md — 프로젝트 지식 파일

프로젝트 루트(또는 ~/.claude/)에 놓는 CLAUDE.md는 Claude가 매 세션마다 자동으로 읽는 컨텍스트입니다.

잘 쓰는 CLAUDE.md 구조

# CLAUDE.md

## 프로젝트 개요
Spring Boot 3.x 기반 이커머스 결제 서비스.
MySQL 8 + Redis 7. 패키지 구조는 도메인 중심(DDD lite).

## 빌드 & 실행
```bash
./gradlew bootRun            # 로컬 실행
./gradlew test               # 전체 테스트
./gradlew test --tests "*Wallet*"  # 특정 테스트만
```

## 코드 컨벤션
- 영어 메서드명, 한국어 주석 허용
- 서비스 레이어는 반드시 트랜잭션 경계를 명시
- 테스트는 Given-When-Then 형식

## 하면 안 되는 것
- git push --force 금지
- .env 파일 커밋 금지

→ Claude가 이 내용을 항상 알고 있으므로 매번 설명할 필요 없음.

4. MCP (Model Context Protocol) 실전 연결

MCP는 Claude Code에 외부 도구를 플러그인처럼 연결하는 프로토콜입니다. claude mcp add 명령 또는 설정 파일로 등록합니다.

자주 쓰는 MCP 서버

MCP 서버용도등록 명령
GitHubPR·Issue·코드 검색claude mcp add github
PostgresDB 스키마·쿼리 실행claude mcp add postgres postgresql://...
Filesystem지정 경로 파일 읽기claude mcp add filesystem /path/to/dir
Slack채널 메시지 읽기/쓰기claude mcp add slack
Notion페이지 읽기/쓰기claude mcp add notion

MCP 상태 확인

claude mcp list          # 등록된 MCP 목록
claude mcp get github    # 특정 MCP 상세 확인

settings.json에서 직접 등록

// .claude/settings.json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]
    }
  }
}

5. Hooks — 자동화 트리거

Hook은 Claude Code의 특정 이벤트(도구 실행 전/후, 세션 시작/종료 등)에 셸 명령을 자동 실행합니다.

주요 Hook 이벤트

이벤트발생 시점
PreToolUseClaude가 도구(파일 수정, 명령 실행 등) 호출하기 직전
PostToolUse도구 호출 완료 후
StopClaude가 응답을 마쳤을 때
UserPromptSubmit사용자가 메시지를 전송할 때

실전 Hook 예시

// .claude/settings.json
{
  "hooks": {
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude가 완료했습니다\" with title \"Claude Code\"'"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": "git add -A && git diff --cached --stat"
          }
        ]
      }
    ]
  }
}

→ Stop Hook: 작업 완료 시 macOS 알림 발송.
→ PostToolUse(Edit) Hook: 파일 수정 후 자동으로 git add 실행.

7. 권한 제어 (Permission Mode)

Claude Code는 파일 수정·명령 실행 같은 민감한 작업 전에 사용자 승인을 요청합니다. 프로젝트 성격에 따라 수준을 조정합니다.

settings.json 권한 설정

// .claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(git *)",
      "Bash(npm run *)",
      "Bash(./gradlew *)",
      "Read(*)",
      "Edit(*)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push --force*)"
    ]
  }
}

→ allow에 등록된 패턴은 승인 없이 자동 실행.
→ deny에 등록된 패턴은 절대 실행하지 않음.

8. 실전 워크플로우 패턴

8.1 PR 설명 자동 생성

git diff main...HEAD | claude "이 변경사항을 기반으로 GitHub PR 설명을 작성해줘.
- ## Summary (3줄 이내)
- ## Changed files
- ## Test plan
형식으로, 한국어로 작성해줘."

8.2 코드 리뷰 보조

# 특정 파일 집중 리뷰
claude "src/payment/PaymentService.java를 리뷰해줘.
보안 취약점, 트랜잭션 경계, 예외 처리를 중심으로."

# 변경된 파일만 리뷰
git diff --name-only HEAD~1 | xargs -I{} claude "{}를 리뷰해줘"

8.3 테스트 작성

claude "src/wallet/WalletService.java의 charge() 메서드에 대한
JUnit 5 + Mockito 테스트를 작성해줘.
Given-When-Then 형식, 성공/잔액부족/동시성 케이스 포함."

8.4 디버깅 보조

# 스택 트레이스 붙여넣기
cat error.log | claude "이 에러의 원인과 해결법을 분석해줘"

# 특정 커밋에서 발생한 문제 추적
git log --oneline -20 | claude "이 커밋 중 DB 스키마를 변경한 커밋을 찾아줘"

8.5 문서화

# API 엔드포인트 문서 자동 생성
claude "src/controller/ 디렉토리의 모든 컨트롤러를 읽고
OpenAPI 3.0 스펙(YAML)으로 문서를 만들어줘"

9. 비용 최적화 팁

모델 선택 전략

상황추천 모델이유
간단한 코드 수정, 파일 검색Haiku 4.5빠르고 저렴
일반 코딩 작업, PR 리뷰Sonnet 4.6성능/비용 균형
복잡한 아키텍처 설계, 디버깅Opus 4.7최고 성능 필요 시

컨텍스트 관리

  • 대화가 길어지면 /compact로 압축 → 토큰 크게 절약
  • 새 작업은 /clear로 컨텍스트 초기화 후 시작
  • 불필요한 파일을 .claudeignore에 추가 (node_modules, dist 등)

.claudeignore 예시

node_modules/
dist/
build/
.gradle/
*.class
*.jar
*.log
.env

10. 팀 설정 공유

설정 파일 위계

~/.claude/settings.json          # 개인 전역 설정 (팀과 공유 안 함)
.claude/settings.json            # 프로젝트 공유 설정 (git 커밋)
.claude/settings.local.json      # 개인 프로젝트 설정 (gitignore)

.gitignore에 추가할 항목

.claude/settings.local.json
.env.claude

팀 공용 CLAUDE.md 관리 포인트

  • 빌드/실행 명령어를 명확히 기재
  • 코드 컨벤션, 금지 패턴 명시
  • 자주 참조하는 설계 결정(ADR) 요약 포함
  • PR/이슈 링크 형식, 브랜치 네이밍 규칙 기재
