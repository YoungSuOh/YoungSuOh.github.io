0. 이 문서를 읽는 법

이 문서가 다루는 것

이 가이드는 Anthropic의 두 가지 주요 개발자 접점인 Claude(대화형 AI 어시스턴트, 웹/데스크톱/모바일/API)와 Claude Code(터미널과 IDE에서 동작하는 에이전트형 코딩 도구)를 처음 도입하는 개발자에게 필요한 모든 기초를 한 권에 담는 것을 목표로 합니다. 단순한 “이런 게 있다” 수준이 아니라, 실제 업무에 들이기 전에 알아두면 좋은 모델 특성, 컨텍스트 다루는 법, 권한 관리, 비용·보안 트레이드오프까지 포함합니다.

표기 규칙

  • Claude 표시는 대화형 제품(웹·데스크톱·API)을 가리킵니다.
  • Claude Code 표시는 CLI/IDE 에이전트 제품을 가리킵니다.
  • 코드체는 명령어·식별자·파일 경로 등을, Cmd+K 같은 박스는 키보드 단축키를 의미합니다.
  • 회색 인용 박스는 주의, 파란색 박스는 참고, 초록색 박스는 실전 팁입니다.

전제하는 환경

독자는 git, 터미널 기본 명령(cd, ls, cat), 자신의 주력 언어(JS/TS, Python, Go 중 하나 이상)에 익숙하며, macOS 또는 Linux 셸을 사용한다고 가정합니다. Windows 사용자는 WSL2 환경을 권장하며, 본문 곳곳에 Windows에 해당하는 보강 설명을 함께 적었습니다.

버전 차이에 대한 주의
이 문서는 2026년 4월 기준의 최신 모델 라인업(Opus 4.6 / Sonnet 4.6 / Haiku 4.5)과 Claude Code의 최신 안정 버전을 전제로 합니다. 명령어 이름이나 플래그는 마이너 업데이트로 바뀔 수 있으므로, claude --help와 공식 문서를 항상 함께 참조하세요.

이 문서를 다 읽고 나면 할 수 있는 일

  1. Claude와 Claude Code 중 업무에 맞는 도구를 선택할 수 있다.
  2. 두 도구 모두를 자신의 컴퓨터에 설치하고 첫 작업을 끝낼 수 있다.
  3. 모델 선택(Opus / Sonnet / Haiku)의 트레이드오프를 이해하고 비용을 통제할 수 있다.
  4. 슬래시 명령·MCP·훅(hook)을 활용해 자기 워크플로우에 맞게 도구를 확장할 수 있다.
  5. 팀에 안전하게 도입하기 위한 권한·시크릿·CI 정책을 설계할 수 있다.

1. Claude란 무엇인가

“Claude”는 사람마다 가리키는 것이 조금씩 다릅니다. 어떤 사람에게는 모델 자체를, 어떤 사람에게는 웹사이트(claude.ai)를, 또 어떤 사람에게는 API를 의미하지요. 이 챕터는 그 층위를 정리하는 것에서 시작합니다.

1.1 세 가지 층위 — 모델, 제품, 인터페이스

① 모델 (Model)

실제로 텍스트를 생성하는 신경망 그 자체입니다. Anthropic이 학습·배포하며 이름으로 식별됩니다(예: claude-opus-4-6, claude-sonnet-4-6, claude-haiku-4-5).

② 제품 (Product)

모델을 감싸 사용자에게 전달하는 패키지입니다. 대화형 챗(claude.ai), Claude Code, Claude in Chrome, Claude in Excel 등이 여기에 속합니다.

③ 인터페이스 (Interface)

같은 제품을 어떤 입출구로 만나는가입니다. 웹, 데스크톱 앱, 모바일 앱, REST API, SDK 등이 모두 인터페이스입니다.

개발자가 “Claude를 쓴다”고 말할 때 보통은 제품 + 인터페이스 조합을 가리킵니다. 예를 들어 “회사에서 Claude 데스크톱을 쓴다”는 “Claude(대화형 제품)를 데스크톱 앱(인터페이스)으로 쓴다”는 뜻이고, “Claude API를 호출한다”는 “모델을 직접 REST/SDK로 호출한다”는 뜻이지요.

1.2 모델 라인업 — Opus, Sonnet, Haiku

모델대표 식별자특징주된 용도
Opusclaude-opus-4-6가장 추론력이 강하고 길고 복잡한 작업에 강함. 비용·지연 시간이 가장 큼.설계, 마이그레이션, 깊은 디버깅, 연구
Sonnetclaude-sonnet-4-6품질·속도·비용의 균형이 좋아 “기본 모델”로 가장 자주 쓰임.일상 코딩, 리뷰, 문서화
Haikuclaude-haiku-4-5가장 빠르고 저렴. 짧은 작업·도구 호출·라우팅에 강점.분류, 요약, 라이트한 자동화

버전 숫자는 시간이 지나며 올라가지만 이름(Opus/Sonnet/Haiku)이 가리키는 “포지셔닝”은 그대로 유지됩니다. 비용 민감도가 낮고 품질이 중요하면 Opus, 보통은 Sonnet, 양이 많고 단순하면 Haiku를 떠올리세요.

실무 가이드
개인 개발자라면 90%의 작업을 Sonnet으로 처리하고, 어려운 마이그레이션이나 아키텍처 토론에서만 Opus로 “승급”시키는 패턴이 비용 대비 효율이 가장 좋습니다.

1.3 Claude(대화형 제품)가 잘하는 일

대화형 Claude는 “긴 글을 읽고 추론하는” 작업에 특히 강합니다. 코드 한 줄을 자동완성하기 위한 도구가 아니라, 의도를 듣고 맥락을 종합해 답을 만드는 협업 파트너에 가깝습니다.

  • 긴 문서 이해 — 사양서·논문·계약서·로그 수만 줄을 읽고 핵심을 정리.
  • 설계와 검토 — 시스템 설계 검토, 트레이드오프 토론, 아키텍처 다이어그램 글로 설명.
  • 코드 생성과 리뷰 — 새 모듈 초안 작성, 리팩터 제안, PR 리뷰의 1차 패스.
  • 데이터 정리 — CSV·JSON·표를 받아 변환·요약·시각화 코드까지 묶어 제공.
  • 커뮤니케이션 — 이슈 글, 사후 분석, 기술 블로그, 이메일 톤 다듬기.

1.4 인터페이스별 차이

인터페이스특징언제 쓰면 좋은가
claude.ai (웹)가장 빠르게 시작할 수 있는 진입점. 파일 업로드, 프로젝트 단위 컨텍스트 보관, 아티팩트(코드/문서 미리보기) 지원.탐색·학습·문서 작업
데스크톱 앱웹과 거의 동일한 기능에 더해 OS 단축키·파일 시스템 권한·로컬 도구 연동(Cowork 등) 가능.매일 쓰는 메인 도구
모바일 앱이동 중 짧은 질문, 음성 입력, 사진을 찍어 바로 묻기.아이디어·메모·번역
APISDK(Python/TS/Go 등)로 직접 호출. 스트리밍, 도구 호출(tool use), 비전 입력 등 세밀한 제어.제품 빌딩·자동화
Claude in Chrome브라우저 안에서 페이지를 읽고 양식을 채우거나 작업을 수행.웹 리서치·반복 업무

1.5 “스킬”과 “프로젝트” — 컨텍스트를 재사용하는 두 축

Claude를 효과적으로 쓰는 핵심은 매번 처음부터 설명하지 않는 것입니다. 두 가지 장치가 이를 도와줍니다.

프로젝트 (Project)

대화 묶음 + 공유 시스템 프롬프트 + 첨부 파일을 한 묶음으로 보관하는 단위입니다. “회사 코드베이스 Q&A”, “블로그 작성”처럼 도메인을 분리하면 매 대화에서 같은 맥락이 자동으로 들어갑니다.

스킬 (Skill)

특정 작업 유형(예: pptx 생성, pdf 처리)에 대해 베스트 프랙티스를 모아둔 폴더 형식의 “플레이북”입니다. 작업 종류만 인식되면 알아서 해당 스킬의 지침을 읽고 따라옵니다.

1.6 토큰, 컨텍스트 윈도우, 비용의 관계

모든 LLM은 입력과 출력을 토큰(token) 단위로 다룹니다. 한국어는 대체로 1자당 1.5~2토큰, 영어는 1단어당 약 1.3토큰 수준으로 환산하면 큰 오차 없이 추정할 수 있습니다. 컨텍스트 윈도우는 한 호출에 입력+출력으로 들어갈 수 있는 토큰 총량의 상한입니다.

  • 입력 토큰은 시스템 프롬프트 + 대화 이력 + 첨부 파일 텍스트로 구성됩니다.
  • 출력 토큰은 모델이 새로 만들어내는 응답입니다.
  • 비용은 보통 입력보다 출력이 더 비싼 구조이며, Opus > Sonnet > Haiku 순으로 비쌉니다.
실전 팁 — 컨텍스트 다이어트
같은 답을 받기 위해 굳이 파일 전부를 넣을 필요는 없습니다. 관련된 함수·테스트·관련 문서 일부만 전달하면 답 품질은 거의 같으면서 비용이 절반 이하가 되는 경우가 흔합니다.

1.7 도구 사용(Tool Use)과 멀티모달

Claude는 단순한 텍스트 생성기를 넘어, 외부 도구를 호출해서 결과를 받아 다시 추론에 쓰는 것이 가능합니다(이를 “tool use”라고 부릅니다). 검색, 계산기, 사내 API, 파일 시스템 등 어떤 함수든 도구로 등록하면 모델이 필요할 때 알아서 호출합니다.

// (개념 예시) TypeScript SDK
const response = await client.messages.create({
  model: "claude-sonnet-4-6",
  tools: [
    { name: "search_orders", input_schema: { /* JSON Schema */ } },
    { name: "refund_order",  input_schema: { /* JSON Schema */ } },
  ],
  messages: [{ role: "user", content: "주문번호 1234 환불해줘" }],
});

이미지도 동일한 메시지에 붙여 넣을 수 있고, 일부 인터페이스에서는 PDF·오디오까지 직접 받습니다. 이 “모델이 도구를 잡고 일하는” 패턴이 다음 챕터에서 다룰 Claude Code의 본질이기도 합니다.

1.8 “Claude”라고 부를 때 흔한 오해 정리

  • 오해 1. “Claude = 단일 모델”이다. → 아닙니다. Opus/Sonnet/Haiku 등 라인업이 있고 버전이 갱신됩니다.
  • 오해 2. claude.ai에서 본 답과 API 답이 같다. → 시스템 프롬프트·도구·온도 설정이 다르므로 같은 모델이라도 차이가 납니다.
  • 오해 3. Claude Code는 별도 모델이다. → 같은 Claude 모델을 쓰지만 “에이전트 루프 + 도구”로 감싼 별개의 제품입니다.
  • 오해 4. 토큰은 글자 수다. → 단어/형태소 기반의 BPE 단위라 한글은 자모/음절 단위로 분리되어 한 글자가 2토큰 이상이 되기도 합니다.

2. Claude Code란 무엇인가

한 줄로 말하면 Claude Code는 “당신의 코드베이스 안에서 일하는 에이전트 형태의 Claude”입니다. 터미널에서 claude 명령으로 띄우거나, IDE 통합으로 띄울 수 있습니다. 채팅 한 번에 답을 받고 끝나는 게 아니라, 여러 단계의 도구 호출(파일 읽기·쓰기·검색·테스트 실행)을 직접 수행하면서 일을 끝냅니다.

2.1 “에이전트”라는 단어가 뜻하는 것

여기서 “에이전트”란, 모델이 한 번의 응답만 내고 끝나는 것이 아니라 관찰 → 계획 → 행동 → 다시 관찰의 루프를 자기 주도로 도는 형태를 말합니다. Claude Code는 다음과 같은 도구를 기본 장착하고 있습니다.

  • 파일 도구 — Read / Write / Edit / Glob / Grep
  • 실행 도구 — Bash (셸 명령 실행)
  • 웹 도구 — WebFetch / WebSearch
  • 태스크/서브에이전트 — 큰 작업을 하위 에이전트에 위임
  • MCP 도구 — 외부 시스템(깃허브, 슬랙, Linear, 자체 API 등)을 자유롭게 연결

2.2 어디서 어떻게 동작하는가

실행 위치

Claude Code는 당신의 컴퓨터(또는 컨테이너) 위에서 직접 동작합니다. 모델 호출은 Anthropic 서버에 가지만, 파일과 명령은 모두 로컬에서 실행됩니다. 즉, 코드가 어디에도 업로드되지 않고도 분석할 수 있습니다(필요한 부분의 텍스트만 모델에 전달됩니다).

인터페이스

기본은 터미널 TUI입니다. JetBrains/VS Code 플러그인이 있어 IDE 사이드바에서도 같은 세션을 다룰 수 있고, 워크플로우 자동화를 위한 SDK(에이전트 SDK)도 제공됩니다.

2.3 핵심 기능을 한 번에 보기

기능설명

2.4 안전 모델 — 권한, 샌드박스, 승인

에이전트가 여러분의 컴퓨터에서 셸 명령을 실행한다는 건 강력하지만, 동시에 위험할 수 있는 능력입니다. Claude Code는 다음 세 가지 장치로 이를 통제합니다.

  1. 권한 프롬프트 — 파괴적이거나 외부에 영향을 주는 명령(예: rm, git push, 네트워크 호출)은 실행 전에 사용자 확인을 요청합니다.
  2. 허용 목록(allowlist) — 자주 쓰는 안전한 명령(npm test 등)은 ~/.claude/settings.json에 미리 등록해 묻지 않게 할 수 있습니다.
  3. 플랜 모드 / 드라이런 — 실제 실행 없이 “했다면 어떻게 됐을지” 계획만 보여주고 끝냅니다.
// ~/.claude/settings.json (예시)
{
  "permissions": {
    "allow": ["Bash(npm test)", "Bash(npm run lint)", "Read(./**/*)"],
    "deny":  ["Bash(rm -rf *)", "Bash(git push --force*)"]
  },
  "model": "claude-sonnet-4-6"
}

2.5 컨텍스트와 메모리

Claude Code는 현재 디렉터리를 작업 컨텍스트의 출발점으로 삼습니다. 그리고 두 종류의 “기억”을 가집니다.

프로젝트 메모리 — CLAUDE.md

리포지토리 루트의 CLAUDE.md는 매 세션 시작 시 자동으로 읽힙니다. 코드베이스 개요, 테스트 명령, 코딩 컨벤션, 절대 건드리면 안 되는 영역 등을 적어두면 모든 작업의 “북극성” 역할을 합니다.

사용자 메모리 — ~/.claude/CLAUDE.md

모든 프로젝트에 공통으로 적용되는 개인 선호(언어, 스타일, 기본 모델, 자주 쓰는 디렉터리 등)를 적어 둡니다. 회사 노트북에 있는 “나의 작업 환경 상수”라고 보면 됩니다.

2.6 Claude Code가 잘 어울리는 작업

  • 여러 파일에 걸친 리팩터·이름 변경: 의존성과 테스트까지 함께 갱신.
  • 대형 마이그레이션: ESM 전환, Webpack→Vite, Express→Hono 같은 다단계 작업.
  • 디버깅: 로그를 받아 원인을 찾고, 패치를 적용하고, 테스트로 검증까지.
  • 테스트 작성: 누락된 분기에 대한 단위/통합 테스트 자동 작성.
  • 코드베이스 탐색·문서화: 새로 합류한 리포에서 “이 모듈이 뭐 하는 거야?”에 답하기.
  • 리뷰: /review, /security-review로 PR 1차 검토.

2.7 잘 어울리지 않는 작업

  • 의도가 모호한 “알아서 해줘” 류 — 사람이 한 번 의도를 정리해 넘기는 편이 효율적.
  • 도메인 지식이 매우 좁고 비공개여서 컨텍스트 제공이 어려운 경우(예: 사내 사양서가 종이뿐).
  • 실행 가능한 검증(테스트·타입체크·빌드)이 전혀 없는 환경 — 에이전트는 “피드백 루프”에 강합니다.

4.6 비용 통제 — 첫 주에 해 둘 일

  1. 워크스페이스 단위로 월 사용 한도(usage limit)를 설정합니다.
  2. 모델별로 알림 임계치(예: 한도의 50%, 80%)를 켭니다.
  3. 가능한 곳은 Sonnet로 시작해 “필요할 때만 Opus”로 승급하도록 코드에서 모델을 변수화합니다.

훅은 특정 이벤트(예: 도구 호출 전, 도구 호출 후, 세션 시작)에서 실행되는 셸 스크립트입니다. 다음은 “파일 쓰기 직후 자동으로 lint·format을 돌려주는” 훅의 예시입니다.

// ~/.claude/settings.json (일부)

        "match": { "tool": "Write|Edit" },
        "command": "npm run -s lint:fix && npm run -s format"

    ]
  }
}

이렇게 해 두면 모델이 코드를 만들 때마다 사람이 따로 “lint 돌려줘”라고 시키지 않아도 자동으로 정리됩니다.

Claude Code는 GitHub Actions 같은 CI에서 비대화형으로 실행할 수 있습니다. 다음은 PR이 열리면 자동으로 1차 리뷰 코멘트를 남기는 예시입니다.

# .github/workflows/claude-review.yml
name: Claude PR Review
on: { pull_request: { types: [opened, synchronize] } }
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - name: Install Claude Code
        run: npm i -g @anthropic-ai/claude-code
      - name: Run review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          claude --print --no-tty \
            --command "/review" \
            --output-format markdown > review.md
      - name: Comment PR
        uses: marocchino/sticky-pull-request-comment@v2
        with: { path: review.md }

8. 슬래시 명령·플러그인·MCP — 확장하기

Claude Code의 진짜 강점은 “기본 기능”보다 자기 워크플로우에 맞게 확장 가능하다는 점에 있습니다. 세 가지 개념을 차근차근 살펴봅니다.

8.1 슬래시 명령 만들기

슬래시 명령은 본질적으로 이름이 붙은 프롬프트입니다. ~/.claude/commands/ 또는 ./.claude/commands/에 마크다운 파일을 두면 자동 등록됩니다.

---
당신은 이 리포의 릴리즈 매니저이다.
git diff main...HEAD 의 변경을 읽고
- 추가된 기능
- 수정된 버그
- 호환성 깨지는 변경
세 섹션의 마크다운 항목을 만들어라. PR 번호 가능한 곳에 인용.

# 사내 마켓플레이스 추가

# 플러그인 검색·설치
claude plugin search adr
claude plugin install adr-toolkit

8.3 MCP — Model Context Protocol

MCP는 “모델이 호출할 수 있는 도구”를 표준 JSON-RPC로 정의한 규약입니다. 등록 → 발견 → 호출의 3단계로 동작하며, 한 번 등록하면 Claude·Claude Code·Claude in Chrome 등 어떤 인터페이스에서도 같은 방식으로 쓰입니다.

# 자주 쓰는 MCP 서버 예시
claude mcp add github   npx @modelcontextprotocol/server-github
claude mcp add slack    npx @modelcontextprotocol/server-slack
claude mcp add linear   npx @modelcontextprotocol/server-linear
claude mcp add postgres npx @modelcontextprotocol/server-postgres
claude mcp list   # 등록 현황 확인
왜 표준이 중요한가? 같은 MCP 서버 코드 한 벌이면 채팅·CLI·IDE·CI 어디에서나 동일한 도구가 모델에 노출됩니다. “어디서 쓸지”를 미리 정하지 않아도 됩니다.

8.4 자체 MCP 서버 30분 만에 만들기

// my-time-mcp/server.ts (TypeScript, 약식)
import { Server } from "@modelcontextprotocol/sdk/server";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio";

const server = new Server({ name: "time", version: "1.0.0" });

server.tool("now", { description: "현재 ISO-8601 시각 반환" }, async () => {
  return { content: [{ type: "text", text: new Date().toISOString() }] };
});

server.tool("addMinutes", {
  description: "주어진 시각에 분을 더한다",
  inputSchema: {
    type: "object",
    properties: {
      iso: { type: "string" },
      minutes: { type: "number" }
    },
    required: ["iso","minutes"]
  }
}, async ({ iso, minutes }) => {
  const t = new Date(iso); t.setMinutes(t.getMinutes() + minutes);
  return { content: [{ type:"text", text: t.toISOString() }] };
});

await server.connect(new StdioServerTransport());

등록 후 모델 입장에선 단지 now(), addMinutes(...)가 “쓸 수 있는 함수”로 보입니다. 사내 도메인에 특화된 검색·작업 보드·배포 트리거 등을 같은 패턴으로 노출하면 됩니다.

9.1 Git과 함께 쓰기

12. FAQOnboarding Guide

12. 자주 묻는 질문 (FAQ)

Q1. Claude와 ChatGPT, 어떤 차이가 있나요?

둘 다 대화형 AI 어시스턴트라는 점은 같지만, Anthropic의 Claude는 긴 컨텍스트 처리와 형식이 정해진 출력의 일관성이 강점으로 평가받습니다. Claude Code처럼 로컬 코드베이스에서 동작하는 에이전트형 도구를 같은 모델 라인업으로 함께 제공한다는 점도 특징입니다. 어느 쪽이 “좋다”기보다 자기 워크플로우에 맞는 쪽을 고르세요.

Q2. Claude Code는 인터넷이 끊겨도 동작하나요?

아니오. 모델 호출 자체가 Anthropic 서버와의 통신이라 네트워크는 필요합니다. 다만 코드와 명령은 모두 로컬에서 실행됩니다.

Q3. 회사 정책상 코드 외부 전송이 어렵습니다.

완전 오프라인 환경에서 모델을 쓰는 것은 어렵습니다. 다만 (1) 송신 데이터의 마스킹, (2) Workspace 단위의 데이터 보존 옵션, (3) 일정 기간 학습 미사용 옵션 등을 통해 위험을 줄일 수 있습니다. 보안팀과 함께 데이터 처리 부속서(DPA)를 검토하세요.

Q4. Opus와 Sonnet, 언제 골라야 하나요?

대부분 Sonnet이 답입니다. Opus는 긴 추론·여러 단계의 설계·미묘한 코드 마이그레이션처럼 “생각”을 많이 해야 하는 작업에서 차이를 보입니다. 비용을 통제하고 싶다면 “기본은 Sonnet, 어렵다고 느낄 때만 Opus”로 코드에서 모델을 변수화하세요.

Q5. Claude Code가 만든 코드의 저작권은 누구 것인가요?

일반적으로 사용자(또는 그 사용자의 조직)가 보유합니다. 다만 회사의 라이선스/약관과 자사 정책에 따라 명확히 해두는 것이 안전합니다. 의심스러우면 법무팀과 정책 문서(서비스 약관)를 함께 검토하세요.

Q6. 한국어로 써도 잘 동작하나요?

네. 한국어 입력·출력 모두 자연스럽게 처리됩니다. 다만 코드 식별자는 영어로 두는 것이 깃 협업·검색 측면에서 유리합니다.

Q7. Claude API는 OpenAI API와 호환되나요?

완전 호환은 아닙니다. 메시지 구조와 도구 호출 표현이 다릅니다. 다만 SDK 추상화(Anthropic 공식 SDK 또는 LangChain 같은 프레임워크)를 쓰면 마이그레이션 비용이 크지 않습니다.

Q8. 모델이 이상한 답을 합니다. 어디서 시작하면 좋을까요?

(1) 컨텍스트가 너무 길지 않은가, (2) 출력 포맷이 모호하지 않은가, (3) 모델이 너무 작은 모델은 아닌가, (4) 같은 프롬프트가 시간차로 다른 답을 내는가의 4가지를 점검하세요. 대부분의 “이상함”은 컨텍스트와 형식 지정에서 해결됩니다.

Q9. Claude Code의 Plan Mode를 항상 켜야 하나요?

익숙해지기 전 1~2주는 권장합니다. 이후에는 “파괴적 작업(파일 삭제·git push·외부 네트워크)에만 켜기”가 일반적인 균형점입니다.

Q10. Plug-in과 MCP는 무엇이 다른가요?

MCP는 “도구를 모델에 어떻게 노출할지의 프로토콜”이고, Plugin은 “슬래시 명령·MCP·스킬을 묶어 배포하는 패키지 단위”입니다. MCP는 ‘부품’, Plugin은 ‘완제품’에 가깝다고 보면 쉽습니다.
