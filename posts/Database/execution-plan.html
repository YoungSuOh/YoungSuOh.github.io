실행 계획(Execution Plan)

실행 계획(Execution Plan) 정리

Database

실행 계획은 옵티마이저가 쿼리를 실제로 수행하는 경로를 보여준다. 튜닝의 시작점이다.

먼저 보는 항목

  • Access Type: ALL, range, ref, eq_ref
  • rows: 예상 처리 건수
  • Extra: Using filesort, Using temporary
  • key: 실제 사용 인덱스

해석 팁

  • 예상 rows가 과도하게 크면 조건절/인덱스 재검토
  • 정렬/임시 테이블 발생은 비용 급증 신호일 수 있음
  • 예상치와 실제치가 다르면 통계 최신화 필요
EXPLAIN ANALYZE
SELECT o.id, o.user_id
FROM orders o
JOIN users u ON u.id = o.user_id
WHERE o.status = 'PAID'
ORDER BY o.created_at DESC
LIMIT 50;
