Atomic Update

Read-modify-write 경쟁 조건(Lost Update)과, 검증·갱신을 한 번의 UPDATE로 묶는 Atomic Update 및 지갑·버전 조건까지 정리합니다.

SQLConcurrencyTransaction

1️⃣ Atomic의 의미

어떤 작업 전부 성공하거나, 전부 실패하는 특성

  • 예시
A → 성공
B → 실패

이런 상태가 아니라

A + B 둘 다 성공
또는
A + B 둘 다 실패

2️⃣ 문제: 일반적인 업데이트 방식

Wallet wallet = walletRepository.findByUserId(userId);

if(wallet.getBalance() >= amount){
    wallet.setBalance(wallet.getBalance() - amount);
}

SQL 흐름

1. SELECT balance (조회)
2. Java에서 검증 (검증)
3. UPDATE balance (수정)

⚠️ 여기서 발생하는 문제 (Race Condition)

동시에 두 요청이 들어온다.

지갑 상태

balance = 10000

요청

A → 7000 결제
B → 5000 결제

흐름

A SELECT balance → 10000
B SELECT balance → 10000

A 실행

UPDATE balance = 3000

B 실행

UPDATE balance = 5000

최종 결과

balance = 5000

하지만 실제 결제 금액

7000 + 5000 = 12000

그래서 2000원이 공짜 결제된다.

⇒ 이걸 Lost Update + Race Condition

3️⃣ 해결 방법: Atomic Update

Atomic Update는 검증 + 수정을 한 번의 SQL로 처리하는 방식이다.

예시

UPDATE wallet
SET balance = balance - 5000
WHERE user_id = 1
AND balance >= 5000

이 쿼리는 DB 내부에서 이렇게 동작한다.

  1. balance >= 5000 검증
  2. balance 차감

⇒ 두 작업이 한 번의 연산으로 실행된다.

4️⃣ 지갑 시스템에서의 Atomic Update

UPDATE Wallet w
SET w.balance = w.balance - :amount,
    w.version = w.version + 1
WHERE w.user.id = :userId
AND w.balance >= :amount
AND w.version = :version

이 쿼리는 한 번에 다음을 수행한다.

  1. DB 확인
    • 버전이 동일한가?
    • 잔액이 충분한가?
  2. DB 업데이트
    • 잔액 차감
    • 버전 증가
