인덱스(Index)

인덱스(Index) 정리

Database

인덱스는 데이터를 빠르게 찾기 위한 보조 자료구조다. 대부분의 RDBMS에서 B-Tree 계열로 구현된다.

왜 필요한가?

  • 인덱스가 없으면 조건 검색 시 테이블 전체를 순회(Full Scan)해야 하는 경우가 많다.
  • 인덱스는 탐색 범위를 줄여 I/O를 줄인다.

핵심 트레이드오프

  • 읽기 성능: 좋아짐
  • 쓰기 성능: 나빠질 수 있음 (인덱스 유지 비용)
  • 저장 공간: 인덱스만큼 추가 사용

복합 인덱스 설계 포인트

  • 선두 컬럼이 가장 중요하다. (Left-most Prefix 규칙)
  • 선택도(카디널리티)가 높은 컬럼을 앞에 두는 것을 우선 고려
  • WHERE + ORDER BY 패턴을 함께 만족하도록 설계하면 정렬 비용도 줄일 수 있다.

예제

-- 조회 패턴:
-- WHERE user_id = ? AND status = ? ORDER BY created_at DESC
CREATE INDEX idx_orders_user_status_created
ON orders (user_id, status, created_at DESC);

실무 체크리스트

  • 슬로우 쿼리 상위 N개부터 인덱스 검토
  • 중복/유사 인덱스 정리
  • 실행 계획에서 실제 인덱스 사용 여부 확인
  • 인덱스 추가 후 쓰기 TPS 영향 측정
