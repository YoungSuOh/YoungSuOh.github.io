[Network] TCP (3 Way Handshake) + MultiProcess

TCP 통신 과정, 소켓 시스템 콜(socket·bind·listen·accept), 3 Way Handshake, 서버의 멀티 프로세스/멀티 스레드 처리를 정리합니다.

Computer ScienceNetwork
TCP
네트워크에서 신뢰적인 연결방식. unreliable network에서 reliable network를 보장하는 프로토콜

데이터 송수신 과정

📨
송신: Application → Sockets → 네트워크 스택 → NIC
수신: NIC → Driver → 네트워크 스택 → Socket → Application

TCP 소켓 시스템 콜

1socket()
소켓 생성. IPv4/IPv6, TCP/UDP 결정. File Descriptor 반환
2bind()
소켓에 IP 주소·포트번호 부여 (서버 전용)
3listen()
클라이언트 연결 요청 수신 + backlog queue 크기 설정
4accept()
backlog queue에서 연결 요청을 선입선출로 수립. 새 소켓 반환

TCP 3-Way Handshake

클라이언트와 서버 간 신뢰성 있는 통신을 위해 서로 준비됐는지 확인하는 과정.

Client Server |---- SYN ---------->| |<--- SYN+ACK -------| |---- ACK ---------->| |===Established=====|
1단계 SYN
클라이언트 → 서버. listen 상태 서버에 연결 요청
2단계 SYN+ACK
서버 → 클라이언트. accept 시스템 콜 이후 진행
3단계 ACK
클라이언트 → 서버. Established 상태로 데이터 송수신 시작

서버 성능 — 멀티 프로세스

🚧
하나의 서버가 연결 요청을 받고 응답까지 다 주고 다시 다음 요청을 받는 구조면 엄청난 병목 발생

해결: 연결 받는 부분과 응답 주는 부분을 분리

while (1) {
  int client_socket = accept(server_socket, ...);
  if (fork() == 0) {           // 자식 프로세스
    // 응답 처리
    send(client_socket, response, ...);
    close(client_socket);
    exit(0);
  }
  close(client_socket);        // 부모는 다시 accept
}
부모 프로세스
연결 요청만 받아주고 자식에게 위임. 새 요청 받기 위해 다시 accept
자식 프로세스
잔여 3-way handshake + 데이터 송수신 → exit(0) 종료
핵심: 서버는 연결을 받는 부분과 응답을 주는 부분이 병렬적으로 이루어져 있다
