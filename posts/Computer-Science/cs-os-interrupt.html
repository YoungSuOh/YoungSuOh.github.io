[OS] 인터럽트

폴링 vs 인터럽트, 외부·내부·소프트웨어 인터럽트 종류와 처리 과정(문맥 교환)을 정리합니다.

Computer ScienceOS
인터럽트란?
프로그램을 실행하는 도중 예기치 않은 상황이 발생할 경우, 현재 실행 중인 작업을 즉시 중단하고 발생된 상황의 우선 처리가 필요함을 CPU에게 알리는 것

인터럽트의 종류

외부 인터럽트
입출력, 외부 신호, 전원 이상 등 (하드웨어 신호)
내부 인터럽트 (Trap)
0으로 나누기, 오버플로우, 명령어 오용 등 (잘못된 명령/데이터)
소프트웨어 인터럽트
명령어 수행에 의해 발생, 사용자가 프로그램 실행 시

🔄 인터럽트 발생부터 처리까지 전체 흐름

Polling vs Interrupt — 왜 인터럽트인가?

Polling
CPU가 일정 간격으로 자원 상태를 주기적으로 확인. 아무 일이 없어도 CPU 시간 낭비 → 치명적 단점

비유: 교수님이 10분마다 학생들에게 "질문 있니?" 물어보기
Interrupt
자원이 능동적으로 변화를 CPU에 알림. CPU는 따로 시간 안 들여도 됨 → 신속 대응

비유: 학생들이 질문 생길 때마다 교수님께 손 들기
💡
인터럽트는 발생 시기를 예측하기 힘든 경우에 컨트롤러가 가장 빠르게 대응할 수 있는 방법이다. 하드웨어 지원이 필요하다는 제약이 있지만, 폴링에 비해 신속하다.

📋 인터럽트 벡터 테이블 (IVT)

CPU가 인터럽트 원인을 식별하면 어떤 ISR을 실행해야 할지 알아야 한다. 이를 위해 인터럽트 벡터 테이블이 존재한다.

📚 시스템 스택의 역할

인터럽트 처리 시 현재 작업을 안전하게 저장하고 복원하는 핵심 메커니즘이다.

인터럽트 처리 과정 (상세)

1현재 명령어 완료
실행 중인 명령어는 끝까지 마침 (원자성 보장)
2PC 저장
다음 실행할 명령어 주소를 시스템 스택에 push
3레지스터 저장
EAX, EBX, FLAGS 등 모든 CPU 상태를 스택에 push
4IVT 조회
IRQ 번호로 인터럽트 벡터 테이블에서 ISR 주소 찾기
5ISR 실행
PC를 ISR 주소로 변경, 인터럽트 처리 루틴 수행
6레지스터 복원
스택에서 pop하여 원래 레지스터 값 복원
7PC 복원
중단된 명령어 다음 위치로 PC 복원
8실행 재개
원래 프로그램을 마치 아무 일도 없었던 듯 계속 실행
🔄
이 일련의 과정 — 현 상태의 정보를 임시 저장해두고 다시 복원하는 과정 — 을 문맥 교환(Context Switch)이라고 부른다. 프로세스 간 스위칭도 동일한 메커니즘으로 동작한다.

🎯 실전 예시: 키보드 인터럽트

[T = 0ms]  사용자가 문서 편집 중
           CPU: 워드프로세서 코드 실행
           PC = 0x1000

[T = 5ms]  사용자가 'A' 키 누름!
           키보드 컨트롤러 → CPU IRQ 1 신호 전송

[T = 5.001ms]  CPU 인터럽트 감지
           ① 현재 명령어 완료 (mov eax, ebx)
           ② PC(0x1004), 레지스터 스택 push
           ③ IVT[1] = 0x80102500 (키보드 ISR)
           ④ PC ← 0x80102500

[T = 5.002ms]  키보드 ISR 실행
           - 키보드 포트에서 스캔코드 읽기
           - 'A' = 0x1E를 입력 버퍼에 저장
           - 운영체제에 입력 알림

[T = 5.003ms]  ISR 종료
           ⑤ 스택에서 레지스터, PC pop
           ⑥ PC ← 0x1004 (원래 자리)
           ⑦ 워드프로세서 코드 계속 실행

[T = 5.004ms]  사용자 화면에 'A' 표시
           워드프로세서는 인터럽트가 있었는지조차 모름!
핵심: 인터럽트는 발생 시기를 예측할 수 없는 비동기 이벤트를 효율적으로 처리하는 메커니즘. 컨텍스트 저장/복원으로 원래 프로그램은 인터럽트 발생을 모르고 계속 실행된다.

⚡ 다중 인터럽트 & 우선순위

인터럽트 처리 중에 또 다른 인터럽트가 발생하면 어떻게 될까?

Non-Nested (비중첩)
현재 ISR 종료까지 다른 인터럽트는 대기. 단순하지만 응답성↓
Nested (중첩)
더 높은 우선순위 인터럽트가 현재 ISR을 중단시킬 수 있음. 응답성↑
⚠️
임계 구역 (Critical Section): ISR 내에서 데이터 무결성이 중요한 코드는 cli(인터럽트 비활성화) → 작업 → sti(다시 활성화)로 보호. 너무 길게 비활성화하면 다른 중요 인터럽트를 놓칠 수 있다.
