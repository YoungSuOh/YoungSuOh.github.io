[Architecture] Cache

캐시의 동작 원리, 계층 구조(L1·L2·L3), 캐시 교체 알고리즘(LRU·LFU·FIFO), Write 정책 4가지 조합을 정리합니다.

Computer ScienceArchitecture
Cache
자주 사용하는 데이터를 빠르게 접근할 수 있도록 임시 저장하는 메모리 공간. CPU와 RAM 간 속도 차이를 줄이기 위해 사용

왜 캐시가 필요한가?

⚡
CPU 연산 속도는 ns 단위로 빠르지만 RAM 접근 속도는 µs 단위. CPU가 매번 RAM에서 가져오면 성능 크게 저하 → CPU 내부에 빠른 캐시로 자주 쓰는 데이터 미리 저장

동작 원리

1CPU 데이터 요청
먼저 캐시 확인
2Cache Hit
캐시에 있으면 바로 가져옴 (매우 빠름)
3Cache Miss
캐시에 없으면 RAM에서 가져와 캐시에 저장 후 사용

캐시 메모리 계층 구조

L1
가장 빠르고 작음
L2
중간
L3
가장 크고 느림

L1 → L2 → L3 순으로 검색하여 데이터를 빠르게 가져옴.

캐시 교체 알고리즘

LRU
Least Recently Used — 가장 오랫동안 사용되지 않은 데이터 제거
LFU
Least Frequently Used — 가장 적게 사용된 데이터 제거
FIFO
First In First Out — 먼저 들어온 데이터 제거

활용 분야

CPU 캐시
L1/L2/L3로 RAM 속도 차이 해결
웹 브라우저
이미지·CSS·JS를 로컬 저장
DB 캐시
Redis, Memcached로 쿼리 결과 캐싱
CDN
전세계 캐시 서버로 콘텐츠 제공

Write 정책

Write-Through
캐시 + RAM 동시 기록. 일관성 ✓, 속도 ✗
Write-Back
캐시만 먼저 → 제거될 때 RAM. 속도 ✓, 일관성 관리 어려움

블록 할당 정책

Write Allocate
Miss 시 캐시에 먼저 로드 후 쓰기. Write-Back과 함께
No-Write Allocate
Miss 시 RAM에 직접 쓰기. 캐시는 그대로

조합 정리

조합특징사용
Write-Back + No-Write AllocateRAM 접근 최소, 쓰기 향상가장 일반적
Write-Back + Write Allocate적중률 향상일부 CPU
Write-Through + Write Allocate일관성 유지DB 등 일관성 중요
Write-Through + No-Write Allocate캐시 오염 방지특수 경우
