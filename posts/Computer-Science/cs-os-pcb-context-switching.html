[OS] PCB & Context Switching

PCB(Process Control Block)의 구조와 관리 방식, Context Switching이 발생하는 시점과 오버헤드를 정리합니다.

Computer ScienceOS

Process Management

CPU가 프로세스가 여러 개일 때 CPU 스케줄링을 통해 관리하는 것. CPU는 각 프로세스가 누군지 알아야 관리가 가능.

PCB (Process Control Block)

PCB
프로세스 메타데이터들을 저장해 놓는 곳. 한 PCB 안에는 한 프로세스의 정보가 담김
Process ID
식별 번호
Process State
new, ready, running, waiting, terminated
Priority
우선순위
Registers
CPU 레지스터 값
Owner
소유자
CPU/Memory Usage
리소스 사용량

PCB가 왜 필요한가?

🔄
CPU에서는 프로세스 상태에 따라 교체 작업이 일어난다 (interrupt 발생 등). 다시 수행할 대기 중인 프로세스의 저장 값을 PCB에 저장해두는 것이다.

관리 방식

Linked List 방식. PCB List Head에 PCB들이 생성될 때마다 붙음. 주소값 연결이므로 삽입·삭제 용이.

Context Switching

Context Switch
CPU가 이전 프로세스 상태를 PCB에 보관하고, 또 다른 프로세스의 정보를 PCB에 읽어 레지스터에 적재하는 과정

발생 시점

  • 인터럽트 발생
  • CPU 사용 허가시간 모두 소모
  • 입출력을 위해 대기

즉, Ready → Running, Running → Ready, Running → Waiting 상태 변경 시.

Context Switching의 오버헤드

💡
오버헤드는 보통 안 좋은 말이지만, 프로세스 작업 중에는 감수해야 한다. I/O 이벤트로 대기 상태가 된 프로세스 대신 다른 프로세스를 수행시키는 것이 효율적. CPU가 놀지 않게 하고 사용자에게 빠르게 응답하기 위함.
