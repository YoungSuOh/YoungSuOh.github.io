[OS] 데드락 (DeadLock)

교착 상태의 4가지 발생 조건과 예방/회피/탐지·회복 처리 방법을 정리합니다. 은행원 알고리즘과 자원 할당 그래프 포함.

Computer ScienceOS
데드락
두 개 이상의 프로세스나 스레드가 서로 자원을 얻지 못해 다음 처리를 하지 못하는 상태. 무한히 다음 자원을 기다리게 되는 상태

주요 용어

Race Condition
2개 이상의 프로세스/스레드가 하나의 공유 자원에 동시 접근
Critical Section
공유 데이터에 접근하려는 코드
Mutex
하나의 스레드만 공유자원에 접근하도록 함
Semaphore
임계 구역에 여러 스레드 진입 허용 + counter
Busy Waiting
특정 조건이 만족될 때까지 계속 CPU 사용 (낭비) → block & wake up으로 해결
Monitor
공유 자원 접근 제어 코드 블록. 한 번에 하나의 프로세스만 접근 가능

발생 조건 (4가지 모두 충족 시)

1상호 배제
자원은 한번에 한 프로세스만 사용
2점유 대기
자원 점유한 상태로 다른 자원 대기
3비선점
자원 사용 끝날 때까지 강제로 빼앗을 수 없음
4순환 대기
자원 대기가 원형 구조 형성

처리 방법

예방 (Prevention)

발생 조건 중 하나를 제거. 자원 낭비 심함

상호배제 부정
여러 프로세스가 공유 자원 사용 → 동시성 문제
점유대기 부정
실행 전 모든 자원 할당 → 자원 비효율
비선점 부정
다른 자원 요구 시 가진 자원 반납 → 작업 중단 반복
순환대기 부정
자원에 고유번호 → 설계 복잡

회피 (Avoidance)

은행원 알고리즘
시스템이 안정 상태인지 확인 후 자원 할당. 안정 상태가 아니면 다른 프로세스 자원 해제 대기
자원 할당 그래프
요청 간선과 할당 간선으로 표현, 사이클 발생 여부 확인. 단일 인스턴스만 사이클 = 데드락 확정

탐지 & 회복

프로세스 종료
교착 상태의 프로세스 모두 중지 or 하나씩 중지
자원 선점
우선순위 낮은 프로세스의 자원을 선점
