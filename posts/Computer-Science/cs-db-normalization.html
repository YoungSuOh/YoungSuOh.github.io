[Database] 정규화 & 반정규화

제1·2·3·BCNF 정규형의 단계별 변환 과정과 반정규화(테이블 병합·중복 컬럼 추가)의 트레이드오프를 정리합니다.

Computer ScienceDB
정규화
데이터의 중복을 줄이고 데이터 무결성을 유지하기 위해 데이터를 구조화하는 과정

정규화의 목적

데이터 중복 제거
데이터 무결성 유지
갱신 이상 최소화
삽입/삭제/갱신 anomaly 감소
확장성 향상

정규화 단계

1NF — 원자값

1️⃣
도메인이 원자값(atomic value)만 포함하도록 변환
학생 ID이름수강
1홍길동수학, 영어

→ 1NF로 변환 (한 행에 하나의 과목)

학생 ID이름수강
1홍길동수학
1홍길동영어

2NF — 부분 함수 종속 제거

2️⃣
기본키의 일부에만 종속된 컬럼이 있으면 제거. 완전 함수 종속 보장

3NF — 이행 함수 종속 제거

3️⃣
기본키가 아닌 컬럼이 다른 비키 컬럼을 결정하면 분리

BCNF — 모든 결정자가 후보 키

🅱️
강화된 3NF. 모든 결정자(Determinant)가 후보 키여야 함

정규화 판단 기준

상황정규화 수준
읽기 많음 (대시보드)비정규화 일부 허용
쓰기 많음 (금융, 거래)높은 정규화
스키마 고정 (회계)높은 정규화
수평 확장 필요비정규화 허용

반정규화 (Denormalization)

정규화된 DB의 일부를 의도적으로 정규화 원칙에서 벗어나게 설계하여 읽기 성능 최적화.

테이블 병합
여러 테이블을 하나로 통합. 조인 비용 감소
중복 컬럼 추가
자주 조회되는 데이터를 다른 테이블에 중복 저장
계산 컬럼 추가
자주 계산되는 값(예: total_price)을 미리 저장
중복 테이블 추가
요약 데이터를 별도 테이블로 관리
반정규화 장점
읽기 성능 개선, 쿼리 단순화, 응답 속도 향상
반정규화 단점
저장 공간 증가, 데이터 일관성 유지 어려움, 쓰기 비용 증가, 유지보수 복잡
