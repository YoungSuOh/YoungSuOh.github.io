[OS] Memory

MMU의 역할, 가상 메모리, 메모리 과할당과 페이지 교체, 캐시 메모리의 지역성과 Write 정책을 정리합니다.

Computer ScienceOS
메인 메모리
CPU가 직접 접근할 수 있는 기억장치. 프로세스가 실행되려면 프로그램이 메모리에 올라와야 함

MMU (Memory Management Unit)

역할
논리 주소를 물리 주소로 변환. CPU가 메모리에 접근하는 것을 총 관리하는 하드웨어
가상 주소
사용자가 보는 주소 공간. MMU가 가상 → 물리 주소 변환을 빠르게 처리
메모리 보호
base + limit 레지스터로 합법적 영역(base ≤ x < base+limit) 외 접근 시 trap 발생
🛡️
base와 limit 레지스터는 안전성을 위해 커널 모드에서만 수정 가능하도록 설계

메모리 과할당 (Over Allocating)

실제 메모리 사이즈보다 더 큰 사이즈를 프로세스에 할당. 페이지 기법 등으로 사용자가 눈치채지 못하게 처리.

과할당 발생 시

  1. 프로세스 실행 중 페이지 폴트 발생
  2. 페이지 위치를 디스크에서 찾음
  3. 메모리의 빈 프레임에 페이지를 올려야 하는데 빈 프레임이 없음 → 문제!

해결: 페이지 교체

1페이지 부재 발생
2디스크에서 페이지 위치 찾기
3빈 프레임 확인
없으면 victim 프레임 선정 → 디스크 기록
4새 페이지를 빈 프레임에 올림

오버헤드 감소법

변경 비트
victim 페이지가 수정되지 않았으면 디스크 기록 생략
교체 알고리즘
FIFO, OPT, LRU 등 상황에 맞는 선택

캐시 메모리

Cache
주 기억장치 내용 일부를 임시 저장. CPU와 주 기억장치의 속도 차이로 인한 성능 저하 방지

지역성의 원리

시간 지역성
최근 참조된 주소가 곧 다시 참조됨 (반복문 인덱스 i)
공간 지역성
참조 주소와 인접한 주소가 다시 참조됨 (배열 순회)

Write 정책

구분Write ThroughWrite Back
방식캐시+주기억 동시 업데이트블록 해제 시 메모리 저장
장점일관성 유지빠름
단점속도 저하일관성 깨질 수 있음
실무 조합: Write-Back + Write Allocate가 일반적
