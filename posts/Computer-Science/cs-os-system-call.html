[OS] System Call

운영체제 커널 서비스를 응용 프로그램에 제공하는 인터페이스. 시스템 콜이 필요한 이유와 6가지 유형, fork/wait/exec 예제를 정리합니다.

Computer ScienceOS
System Call
운영체제의 커널이 제공하는 서비스에 대해, 응용 프로그램의 요청에 따라 커널에 접근하기 위한 인터페이스

사용자 프로그램이 디스크 파일에 접근하거나 화면에 출력하는 등 특권 명령을 수행해야 할 때, 운영체제에게 대행을 요청하는 것이 시스템 콜이다.

시스템 콜이 필요한 이유

🛡️
유저 레벨 함수만으로는 많은 기능을 구현하기 힘들기 때문에 커널의 도움을 반드시 받아야 한다. 권한이 없으면 해커가 악의적으로 시스템 콜을 사용하거나 초보 사용자가 함수를 잘못 호출해 시스템을 망가뜨릴 수 있다.

커널 명령어는 커널 모드에서만 실행되며, 유저 모드에서 호출 시 운영체제가 trap을 발생시킨다.

시스템 콜의 6가지 유형

프로세스
fork, wait, exec, exit, 메모리 할당
파일
open, read, write, close
디바이스
디바이스 요청·해제, 속성 확인/지정
정보 관리
시간 확인/지정, 시스템 데이터 확인
통신
커뮤니케이션 연결 생성/삭제, 메시지 송수신
보안
Permission 획득/설정

대표 예제: fork()

int rc = fork();
if (rc < 0) { exit(1); }              // 실패
else if (rc == 0) { /* child */ }     // 자식 (fork 반환 0)
else { /* parent of rc */ }           // 부모 (fork 반환 = child pid)
🔀
fork()가 실행되면 자식 프로세스(Child)는 부모(Parent)와 거의 동일한 복사본을 갖는다. OS는 두 프로그램이 동시에 동작한다고 보고, fork()가 return될 차례라 생각한다. Parent는 child의 pid, Child는 0을 반환받는다.

wait & exec

wait
자식 프로세스가 종료될 때까지 부모가 대기
exec
현재 프로세스의 code segment를 다른 실행 파일로 덮어씌움. 새 프로세스 생성 없이 현재 프로그램이 다른 파일 실행
