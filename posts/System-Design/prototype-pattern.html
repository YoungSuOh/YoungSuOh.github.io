Prototype 패턴

Prototype 패턴 정리

System Design

한 줄 정의

새 객체를 만드는 대신 기존 객체를 복제(clone)해서 생성하는 패턴.

왜 쓰는가?

  • 생성 비용이 큰 객체를 빠르게 복제해야 할 때
  • 초기 상태가 비슷한 객체를 많이 만들어야 할 때

주의할 점: 얕은 복사 vs 깊은 복사

  • 얕은 복사: 참조 타입 필드를 공유할 수 있어 부작용 위험
  • 깊은 복사: 내부 참조 객체까지 새로 복제해 안전하지만 비용 증가

Java 예제

import java.util.ArrayList;
import java.util.List;

class Profile implements Cloneable {
    String name;
    List<String> skills;

    Profile(String name, List<String> skills) {
        this.name = name;
        this.skills = skills;
    }

    @Override
    protected Profile clone() {
        // 깊은 복사: 리스트를 새로 생성
        return new Profile(this.name, new ArrayList<>(this.skills));
    }
}

장점 / 단점

  • 장점: 객체 생성 속도 개선, 반복 초기화 코드 감소
  • 단점: 복사 정책을 잘못 잡으면 공유 참조 버그가 생김

실무 사용 예

  • 기본 템플릿 문서 복제
  • 게임 캐릭터/아이템 기본 속성 복제
  • 복잡한 설정 객체의 기준본(prototype) 복사
