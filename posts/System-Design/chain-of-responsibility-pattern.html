Chain of Responsibility 패턴

한 줄 정의

요청을 여러 핸들러 체인에 순차 전달해, 처리 가능한 핸들러가 담당하도록 하는 패턴.

문제 상황

  • 인증 → 인가 → 로깅 → 검증처럼 순차 처리 단계가 있는 요청 파이프라인
  • 조건문으로 처리 순서를 한 클래스에 몰아넣으면 유지보수가 어려워짐

Java 예제

class Request {
    boolean authenticated;
    boolean authorized;
}

abstract class Handler {
    private Handler next;

    public Handler linkWith(Handler next) {
        this.next = next;
        return next;
    }

    public final void handle(Request req) {
        process(req);
        if (next != null) next.handle(req);
    }

    protected abstract void process(Request req);
}

class AuthHandler extends Handler {
    protected void process(Request req) {
        if (!req.authenticated) throw new RuntimeException("unauthenticated");
    }
}

class PermissionHandler extends Handler {
    protected void process(Request req) {
        if (!req.authorized) throw new RuntimeException("forbidden");
    }
}

장점 / 단점

  • 장점: 처리 단계 분리, 체인 조립 유연성
  • 단점: 디버깅 시 실제 처리 흐름 추적이 어려울 수 있음

실무 포인트

  • Servlet Filter, Spring Security Filter Chain이 대표 사례
  • 핸들러 순서가 곧 정책이므로 체인 순서 관리가 중요
