Abstract Factory 패턴

한 줄 정의

서로 연관된 객체군을 일관된 규칙으로 생성하기 위한 팩토리 패턴.

Factory Method와 차이

  • Factory Method: 보통 제품 1종의 생성 지점을 분리
  • Abstract Factory: 관련된 여러 제품군을 한 번에 생성

문제 상황

UI 테마(라이트/다크)마다 버튼, 모달, 입력창을 같은 스타일로 맞춰 생성해야 할 때 유용하다.

Java 예제

interface Button { String render(); }
interface Dialog { String open(); }

class LightButton implements Button {
    public String render() { return "LightButton"; }
}
class DarkButton implements Button {
    public String render() { return "DarkButton"; }
}

class LightDialog implements Dialog {
    public String open() { return "LightDialog"; }
}
class DarkDialog implements Dialog {
    public String open() { return "DarkDialog"; }
}

interface UIFactory {
    Button createButton();
    Dialog createDialog();
}

class LightUIFactory implements UIFactory {
    public Button createButton() { return new LightButton(); }
    public Dialog createDialog() { return new LightDialog(); }
}

class DarkUIFactory implements UIFactory {
    public Button createButton() { return new DarkButton(); }
    public Dialog createDialog() { return new DarkDialog(); }
}

장점 / 단점

  • 장점: 제품군 일관성 유지, 클라이언트 코드 단순화
  • 단점: 제품 타입(인터페이스) 추가 시 모든 팩토리에 수정이 전파됨

실무 포인트

  • 멀티 플랫폼(Web/Mobile/Desktop)별 컴포넌트 생성
  • DB 벤더별 객체 생성 정책 분리
  • 테스트 환경별 Mock 제품군 교체
