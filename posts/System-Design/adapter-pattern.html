Adapter 패턴

Adapter 패턴 정리

System Design

한 줄 정의

호환되지 않는 기존 인터페이스를, 클라이언트가 기대하는 인터페이스로 변환해 연결하는 패턴.

문제 상황

  • 새 시스템은 Target 규격을 기대하는데, 기존 레거시 모듈은 다른 메서드 시그니처를 제공
  • 레거시 코드를 직접 수정하기 어렵거나 위험할 때

구성 요소

  • Target: 클라이언트가 기대하는 인터페이스
  • Adaptee: 기존(레거시) 클래스
  • Adapter: 변환 로직을 담아 두 인터페이스를 연결

Java 예제

interface PaymentProcessor {
    void pay(int amount);
}

class LegacyPaymentApi {
    void executePayment(String money) {
        System.out.println("legacy pay: " + money);
    }
}

class PaymentAdapter implements PaymentProcessor {
    private final LegacyPaymentApi legacy = new LegacyPaymentApi();

    @Override
    public void pay(int amount) {
        legacy.executePayment(String.valueOf(amount));
    }
}

장점 / 단점

  • 장점: 기존 코드 재사용, 변경 범위 최소화
  • 단점: 어댑터 계층이 많아지면 구조 복잡도 증가

실무 포인트

  • 외부 결제/지도/메시징 SDK 교체 시 도메인 인터페이스를 유지하는 데 유리
  • Hexagonal Architecture의 outbound adapter 개념과 연결해 생각하면 이해가 쉽다.
