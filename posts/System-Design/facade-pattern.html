Facade 패턴

Facade 패턴 정리

System Design

한 줄 정의

복잡한 하위 시스템의 사용 절차를 단순한 진입점 하나로 제공하는 패턴.

문제 상황

  • 클라이언트가 여러 서비스 호출 순서를 모두 알아야 하는 경우
  • 호출 순서가 바뀌면 곳곳에서 수정이 필요한 경우

Java 예제

class InventoryService { void check(long productId) {} }
class PaymentService { void pay(long userId, int amount) {} }
class ShippingService { void reserve(long orderId) {} }

class OrderFacade {
    private final InventoryService inventory = new InventoryService();
    private final PaymentService payment = new PaymentService();
    private final ShippingService shipping = new ShippingService();

    void placeOrder(long userId, long orderId, long productId, int amount) {
        inventory.check(productId);
        payment.pay(userId, amount);
        shipping.reserve(orderId);
    }
}

장점 / 단점

  • 장점: 클라이언트 단순화, 의존성 축소
  • 단점: Facade가 과도하게 비대해질 수 있음 (God Object 주의)

실무 포인트

  • 도메인 유스케이스 단위 API를 제공할 때 유용
  • Facade 내부는 orchestration, 세부 비즈니스는 하위 서비스가 담당하도록 분리
