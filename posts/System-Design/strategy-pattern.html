Strategy 패턴

한 줄 정의

동일한 목표를 가진 여러 알고리즘(전략)을 캡슐화하고 런타임에 교체 가능한 패턴.

문제 상황

  • 결제 방식(카드/포인트/쿠폰)마다 처리 로직이 다른데, if-else가 계속 늘어나는 상황

구성 요소

  • Strategy: 공통 알고리즘 인터페이스
  • ConcreteStrategy: 실제 알고리즘 구현체
  • Context: 현재 전략을 선택해 실행

Java 예제

interface PayStrategy {
    void pay(int amount);
}

class CardPay implements PayStrategy {
    public void pay(int amount) { System.out.println("card pay: " + amount); }
}

class PointPay implements PayStrategy {
    public void pay(int amount) { System.out.println("point pay: " + amount); }
}

class CheckoutContext {
    private PayStrategy strategy;

    void setStrategy(PayStrategy strategy) { this.strategy = strategy; }

    void checkout(int amount) {
        if (strategy == null) throw new IllegalStateException("strategy required");
        strategy.pay(amount);
    }
}

장점 / 단점

  • 장점: 알고리즘 교체 용이, 분기문 감소, 테스트 용이
  • 단점: 전략 클래스가 많아질 수 있음

State 패턴과 차이

  • Strategy는 외부에서 전략을 선택
  • State는 내부 상태 전이에 따라 행동이 바뀜
