Singleton 패턴

한 줄 정의

애플리케이션에서 특정 클래스의 인스턴스를 오직 하나만 유지하고, 그 인스턴스에 전역 접근점을 제공하는 패턴.

왜 필요한가?

  • 설정 객체, 로거, 캐시 매니저처럼 애플리케이션 전체에서 동일 상태를 공유해야 할 때
  • 객체를 여러 개 만들면 데이터 불일치나 리소스 낭비가 생기는 경우

구현 포인트

  • 생성자를 private으로 막는다.
  • 정적(static) 인스턴스를 클래스 내부에서 관리한다.
  • getInstance()로만 접근하도록 강제한다.

Java 기본 구현 (Eager Initialization)

public class Singleton {
    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {}

    public static Singleton getInstance() {
        return INSTANCE;
    }
}

Lazy + Thread-safe 구현 (Double-Checked Locking)

public class LazySingleton {
    private static volatile LazySingleton instance;

    private LazySingleton() {}

    public static LazySingleton getInstance() {
        if (instance == null) {
            synchronized (LazySingleton.class) {
                if (instance == null) {
                    instance = new LazySingleton();
                }
            }
        }
        return instance;
    }
}

장점 / 단점

  • 장점: 인스턴스 중복 생성 방지, 전역 상태 일관성 유지
  • 단점: 전역 상태로 인해 테스트가 어려워질 수 있고, 과도하게 쓰면 결합도가 높아진다.

실무 메모

  • Spring에서는 기본 Bean scope가 singleton이므로 직접 Singleton 클래스를 만드는 경우가 줄어든다.
  • 멀티 스레드 환경이라면 반드시 동시성 안전성을 확인해야 한다.
