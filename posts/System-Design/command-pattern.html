Command 패턴

한 줄 정의

요청을 객체로 캡슐화해 실행자(Receiver)와 호출자(Invoker)를 분리하는 패턴.

왜 쓰는가?

  • 요청 큐잉, 재시도, 로깅, undo/redo 같은 부가 기능을 붙이기 좋다.
  • 호출자 코드를 변경하지 않고 새로운 요청을 추가할 수 있다.

Java 예제

interface Command {
    void execute();
}

class PaymentService {
    void pay(long userId, int amount) {
        System.out.println("pay " + amount + " for user " + userId);
    }
}

class PayCommand implements Command {
    private final PaymentService service;
    private final long userId;
    private final int amount;

    PayCommand(PaymentService service, long userId, int amount) {
        this.service = service;
        this.userId = userId;
        this.amount = amount;
    }

    public void execute() {
        service.pay(userId, amount);
    }
}

class CommandInvoker {
    void run(Command command) {
        command.execute();
    }
}

장점 / 단점

  • 장점: 요청 처리 파이프라인 확장 용이, 실행 이력 관리 쉬움
  • 단점: 작은 요청에도 클래스가 늘어나는 경향
