Notion → GitHub Blog 자동 임포트 파이프라인 구축

Notion API로 100개 이상의 학습 노트를 GitHub Pages 블로그에 자동 임포트한 과정을 정리합니다. Page ID 추출, 블록 타입별 HTML 변환, 이미지 만료 문제 해결, 배치 처리까지 파이프라인 전 단계를 다룹니다.

NotionAutomationGitHub PagesNode.jsDev

1. 배경

노션에 정리해둔 네이버 클라우드 부트캠프 학습 노트(OOP, DB, Front-End, 서버, 클라우드, 리눅스, TDD, 프로젝트 등)를 GitHub Pages 블로그에 옮기고 싶었다. 문제는 두 가지였다.

  • 노션 이미지 URL은 S3 서명 URL이라 약 1시간 후 만료된다 → 직접 복붙하면 이미지가 깨진다.
  • 페이지가 100개를 넘어서 수동 작업은 현실적으로 불가능하다.

그래서 Notion API를 활용해 완전 자동화 임포트 파이프라인을 구축했다.

2. 전체 파이프라인 흐름

① Page ID 추출

Notion URL에는 두 가지 형태가 있다.

https://www.notion.so/JDBC-6931fcb8fc204cdeba85b221617661d8   ← 제목 포함
https://www.notion.so/6931fcb8fc204cdeba85b221617661d8        ← UUID만

두 경우 모두 URL 뒤쪽 32자리 hex가 Page ID다. 정규식으로 추출한 뒤 UUID 형식(8-4-4-4-12)으로 변환해 API에 넘긴다.

const m = url.match(/([a-f0-9]{32})(?:[?#]|$)/i);
// "6931fcb8fc204cdeba85b221617661d8"
// → "6931fcb8-fc20-4cde-ba85-b221617661d8"

② 페이지 메타데이터 fetch

GET /v1/pages/{page_id}로 제목과 생성 날짜를 가져온다. 노션은 페이지 제목을 properties.title 배열로 반환하므로 rich text를 이어붙여 문자열로 만든다.

GET https://api.notion.com/v1/pages/6931fcb8-fc20-4cde-ba85-b221617661d8
Notion-Version: 2022-06-28
Authorization: Bearer {API_KEY}

③ 블록 fetch — 페이지네이션 처리

Notion API는 한 번에 최대 100개 블록만 반환한다. 응답의 has_more: true이면 next_cursor를 다음 요청의 start_cursor로 넘겨 반복 호출한다. Rate Limit(3 req/s)을 피하기 위해 요청 사이에 350ms 딜레이를 추가했다.

do {
  const res = await notionGet(
    `blocks/${blockId}/children?page_size=100${cursor ? `&start_cursor=${cursor}` : ""}`
  );
  blocks.push(...res.results);
  cursor = res.has_more ? res.next_cursor : undefined;
  if (cursor) await sleep(350);
} while (cursor);

④ 블록 타입별 HTML 변환

Notion 블록은 타입별로 다른 구조를 가진다. 핵심은 리스트 그룹화와 리치텍스트 변환 두 가지다.

리스트 자동 그룹화

Notion은 bulleted_list_item을 독립 블록으로 반환하지만 HTML은 <ul>로 묶어야 한다. 연속된 같은 타입 블록을 만나면 하나의 리스트로 합친다.

if (type === "bulleted_list_item") {
  out.push("<ul>");
  while (i < blocks.length && blocks[i].type === "bulleted_list_item") {
    out.push(`  <li>${rt(blocks[i].bulleted_list_item.rich_text)}</li>`);
    i++;
  }
  out.push("</ul>");
  continue;  // i를 이미 증가시켰으므로 continue
}

리치텍스트 변환

Notion의 텍스트는 rich_text[] 배열로 구성되며, 각 항목에 annotations(bold, italic, code 등)과 href(링크)가 붙는다.

function rt(richTexts) {
  return richTexts.map((r) => {
    let t = r.plain_text
      .replace(/&/g, "&amp;")
      .replace(/</g, "&lt;")
      .replace(/>/g, "&gt;");
    if (r.href)               t = `<a href="${r.href}">${t}</a>`;
    if (r.annotations.code)   t = `<code>${t}</code>`;
    if (r.annotations.bold)   t = `<strong>${t}</strong>`;
    if (r.annotations.italic) t = `<em>${t}</em>`;
    return t;
  }).join("");
}

⑤ 이미지 자동 다운로드

Notion 이미지 URL은 AWS S3 서명 URL이라 약 1시간 후 만료된다. 따라서 임포트 시점에 즉시 다운로드해 블로그 저장소에 보관해야 한다.

photo/
  posts/
    Naver-Cloud-Camp/
      ncc-jdbc/
        img_001.png
        img_002.png
      ncc-redis/
        img_001.png

다운로드 후 HTML에는 생성될 포스트 파일 기준 상대 경로를 삽입한다.

<!-- posts/Naver-Cloud-Camp/ncc-jdbc.html 기준 -->
<img src="../../photo/posts/Naver-Cloud-Camp/ncc-jdbc/img_001.png">

Notion 이미지 URL은 리다이렉트(302)가 포함된 경우가 있어 Location 헤더를 따라가도록 처리했다.

function get(u) {
  const mod = u.startsWith("https") ? https : http;
  mod.get(u, (res) => {
    if (res.statusCode >= 300 && res.statusCode < 400) {
      return get(res.headers.location);  // 리다이렉트 추적
    }
    res.pipe(file);
  });
}

⑥⑦ body 파일 저장 & posts.json 등록

변환된 HTML은 data/body/naver-cloud-camp/<slug>.html에 저장하고, posts.json에는 bodyFile 참조 형태로 등록한다. 이미 같은 slug가 있으면 덮어쓰고(재임포트), 없으면 맨 앞에 추가한다.

  "bodyFile": "body/naver-cloud-camp/ncc-jdbc.html"
}

⑧ 빌드

npm run build(scripts/build.mjs)가 posts.json을 읽어 각 entry마다 posts/<CategoryDir>/<slug>.html을 생성하고, 블로그 프론트에서 읽는 site-data.js를 갱신한다.

3. Notion Integration 설정

Notion API를 사용하려면 내부 통합(Internal Integration)을 만들어 API Key를 발급받고, 접근할 페이지에 해당 Integration을 연결해야 한다.

  1. notion.so/my-integrations → 새 통합 만들기
  2. 이름 입력, 내부 통합 선택 → API Key 복사 → .env에 저장
  3. 대상 페이지 → ··· → 연결 추가 → Integration 선택
주의 — 최상위 페이지에 한 번만 연결하면 하위 페이지 전체에 접근 가능. API Key는 반드시 .gitignore에 추가.
