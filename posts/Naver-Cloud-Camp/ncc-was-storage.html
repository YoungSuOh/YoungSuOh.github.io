WAS 스토리지

WAS 스토리지 — Naver Cloud Camp 정리 노트.

Front-EndNaver Cloud Camp

WAS(Web Application Server)에는 다양한 스토리지 옵션이 존재해, 주로 애플리케이션의 상태를 관리하거나 데이터를 저장하는 데 사용돼. 다음은 일반적인 WAS 스토리지 종류야:

1. 세션 저장소

  • 사용자의 세션 데이터를 저장하기 위해 사용돼.
  • WAS 자체 메모리에서 관리하거나, 외부 스토리지를 활용해.
    • WAS 메모리 세션: 가장 빠르지만, 서버가 다운되거나 클러스터 환경에서는 비효율적.
    • 외부 세션 저장소: Redis, Memcached, DB 등에 저장해 세션을 유지.
  • 예시: Tomcat에서 PersistentManager를 설정하거나, Spring Session으로 Redis를 연동.

2. JNDI 기반의 데이터 소스

  • 데이터베이스 연결을 관리하기 위해 사용돼.
  • WAS에 설정된 JNDI(Java Naming and Directory Interface)를 통해 데이터베이스 연결 정보를 가져와 효율적으로 관리.
  • 예시: java:comp/env/jdbc/myDataSource

3. JMS 큐 및 토픽

  • 메시지 기반 애플리케이션에서 데이터(메시지)를 저장하는 곳.
  • 일반적으로 ActiveMQ, RabbitMQ 등을 WAS와 함께 사용해 메시지를 관리.

4. 캐시

  • 애플리케이션 성능 향상을 위해 자주 사용되는 데이터를 저장.
  • WAS의 내장 캐시 또는 외부 캐시 도구를 사용해.
    • 내장 캐시: WAS의 메모리를 활용.
    • 외부 캐시: Redis, Ehcache, Hazelcast, Memcached 등.
  • 예시: Spring Cache를 이용한 캐싱 설정.

5. 파일 스토리지

  • 업로드된 파일이나 WAS에서 생성된 데이터를 임시로 저장하는 곳.
  • 파일시스템을 직접 사용할 수도 있고, 클라우드 스토리지(AWS S3, Naver Object Storage)와 연동.
  • 예시: java.io.File API나 Spring Boot의 MultipartFile 처리.

6. 로그 스토리지

  • WAS에서 발생하는 로그 데이터를 저장.
  • 디스크에 로컬 로그를 저장하거나, 로그 서버로 전송.
  • 예시: Logback, Log4j로 설정된 로그 저장소.

7. JPA 또는 Hibernate 2차 캐시

  • ORM 도구를 사용할 때 엔티티의 쿼리 결과를 캐싱.
  • 데이터베이스와의 트랜잭션 부하를 줄이기 위해 사용.
  • 예시: Hibernate와 Ehcache 또는 Redis 연동.

8. 기타

  • 쿠키 기반 스토리지: 세션 데이터를 쿠키에 저장해 클라이언트와 교환.
  • 클러스터링된 스토리지: WAS 클러스터 환경에서 세션과 같은 공유 데이터를 관리하기 위해 사용.
