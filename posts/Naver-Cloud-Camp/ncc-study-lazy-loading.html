지연 로딩 문제

지연 로딩 문제 — Naver Cloud Camp 정리 노트.

프로젝트Naver Cloud Camp

지연 로딩(Lazy Loading)

  • 지연 로딩은 엔티티의 연관 객체를 실제로 사용하려고 할 때까지 데이터베이스에서 해당 데이터를 가져오지 않고 미루는 전략이다.
  • 즉, 객체를 처음 로딩할 때는 연관 관계에 있는 객체들을 즉시 가져오지 않고, 해당 연관 객체에 접근하는 시점에 데이터를 로딩한다.

동작 과정 설명

@Entity
public class User {
    @Id
    private Long id;

    @OneToMany(fetch = FetchType.LAZY)
    private List<Post> posts;

    // getters and setters
}

@Entity
public class Post {
    @Id
    private Long id;

    @ManyToOne
    private User user;

    // getters and setters
}
  • User : Post = 1 : N 관계
  • 지연 로딩 시나리오 
    // 세션 시작
User user = entityManager.find(User.class, 1L);
// 이 시점에서는 User의 기본 필드만 로딩되고, posts는 프록시로 남아 있음
// posts에 접근하는 순간 데이터베이스에서 해당 데이터를 가져옴
List<Post> posts = user.getPosts();
// 세션 종료
  • 즉시 로딩 시나리오 
    @OneToMany(fetch = FetchType.EAGER)
private List<Post> posts;

// 세션 시작
User user = entityManager.find(User.class, 1L);
// 이 시점에서 User와 연관된 모든 posts가 즉시 로딩됨
// 세션 종료

N+1 문제

기본적으로 한 번의 쿼리로 해결할 수 있는 작업이 여러 번의 쿼리로 분할되어 실행되면서 불필요한 데이터베이스 호출이 발생하는 현상이다.

예시 상황

  • User와 Post라는 두 개의 엔티티가 있고, 각 User는 여러 개의 Post를 가질 수 있다고 가정합시다. 모든 사용자와 그들의 게시물을 가져오고 싶을 때 다음과 같은 코드가 있을 수 있다.
List<User> users = entityManager.createQuery("SELECT u FROM User u", User.class).getResultList();
for (User user : users) {
    System.out.println(user.getPosts());
}
  • 첫 번째 쿼리는 모든 사용자 정보를 가져온다.
  • 그러나 user.getPosts()를 호출할 때마다 해당 사용자의 게시물을 가져오기 위한 추가적인 쿼리가 발생한다.
  • 따라서 총 실행되는 쿼리 수는 1(사용자 조회) + N(각 사용자의 게시물 조회)로 N+1이 된다.

문제점

  • 성능 저하: 불필요한 쿼리 호출로 인해 응답 시간이 길어지고 데이터베이스 부하가 증가한다.
  • 리소스 낭비: 네트워크 트래픽과 데이터베이스 리소스를 불필요하게 사용한다.

해결 방법

  1. 페치 조인(Fetch Join) 사용 
    List<User> users = entityManager.createQuery(
    "SELECT u FROM User u JOIN FETCH u.posts", User.class).getResultList();
    • JOIN FETCH 구문을 사용하여 관련 엔티티를 한 번의 쿼리로 가져올 수 있다.
  2. 엔티티 그래프(Entity Graph) 활용 
    EntityGraph<User> graph = entityManager.createEntityGraph(User.class);
graph.addAttributeNodes("posts");
List<User> users = entityManager.createQuery("SELECT u FROM User u", User.class)
    .setHint("javax.persistence.fetchgraph", graph)
    .getResultList();
    • 엔티티 그래프를 사용하여 필요한 연관 관계를 명시적으로 로딩할 수 있다.
  3. 배치 사이즈(Batch Size) 조정 
    <property name="hibernate.default_batch_fetch_size" value="16" />
    • ORM 프레임워크의 설정을 통해 한 번에 가져오는 엔티티 수를 조정하여 쿼리 수를 줄일 수 있다.

LazyInitializationException

LazyInitializationException는 Hibernate와 같은 ORM 프레임워크에서 지연 로딩(Lazy Loading)된 엔티티를 초기화하려 할 때 해당 세션이 이미 종료된 경우 발생하는 예외이다.

서비스 계층에서 트랜잭션이 끝난 후 컨트롤러나 뷰 계층에서 지연 로딩된 필드에 접근하려고 할 때 발생할 수 있다.

// 서비스 계층
@Transactional
public User getUser(Long id) {
    return entityManager.find(User.class, id);
}

// 컨트롤러 계층
public String showUserPosts(Model model, Long id) {
    User user = userService.getUser(id);
    // 여기서 LazyInitializationException 발생 가능
    model.addAttribute("posts", user.getPosts());
    return "userPosts";
}

문제점

  • 지연 로딩된 필드 접근 불가: 세션이 종료되어 지연 로딩된 필드에 접근할 수 없다.
  • 예기치 않은 예외 발생: 런타임 시 예외가 발생하여 애플리케이션이 중단될 수 있다.

해결 방법

  1. 즉시 로딩(Eager Loading) 사용
    1. 연관 필드를 즉시 로딩하도록 설정하여 세션이 열려 있을 때 데이터를 가져온다. → 하지만 성능 저하 일으킴. 
      @OneToMany(fetch = FetchType.EAGER)
private List<Post> posts;
  2. DTO(Data Transfer Object) 사용
    1. 필요한 데이터만을 포함하는 DTO를 생성하여 서비스 계층에서 데이터를 모두 로딩하고, 세션 종료 후에도 데이터에 접근할 수 있게 한다
  3. 페치 조인(Fetch Join) 사용
    1. 필요한 연관 데이터를 미리 로딩하여 세션 종료 전 엔티티를 완전히 초기화 
      public User getUserWithPosts(Long id) {
    return entityManager.createQuery(
        "SELECT u FROM User u JOIN FETCH u.posts WHERE u.id = :id", User.class)
        .setParameter("id", id)
        .getSingleResult();
}
