NCP Disk 마운트

NCP Disk 마운트 — Naver Cloud Camp 정리 노트.

프로젝트Naver Cloud Camp
  • ncp에서 20GB → 40GB 증설 후 모습
  • 서버 디스크 vda는 40GB를 할당 받았지만, 기존에 사용하고 있는 디스크 vda2 는 20GB이다
  • 디스크 크기가 40GB인데, 파티션 합계는 20GB(vda2) + 1MB(vda1)로 나머지 약 20GB는 아직 할당되지 않은 상태
  1. fdisk 명령어를 통해 디스크 /dev/vda의 파티션을 수정한 과정을 진행한다.
  2. p 명령: 현재 디스크 파티션 정보 확인
    1. /dev/vda 디스크 크기: 40GB
      1. /dev/vda1: 크기 1MB, BIOS 부팅 파티션
      2. /dev/vda2: 크기 20GB, 리눅스 파일 시스템
  3. d 명령: 기존 파티션 삭제
    1. 파티션 번호 2(/dev/vda2)를 삭제
    2. 이 작업은 메모리에서만 반영되며, 실제로 디스크에 적용된 것은 아닙니다. w 명령을 실행해야 디스크에 저장된다.
  4. n 명령: 새로운 파티션 생성
    1. 새 파티션 번호: 2 (삭제된 /dev/vda2를 대체)
    2. 시작 섹터: 기본값(4096)
    3. 마지막 섹터: 기본값(83886046, 즉 전체 디스크 크기를 사용)
    4. 크기: 40GB (디스크 전체 사용)
  5. N (No) 선택: 파티션의 기존 파일 시스템 시그니처 유지
    1. 파티션을 생성할 때, 기존 파티션(/dev/vda2)의 파일 시스템 시그니처(ext4)를 발견
      1. N: 기존 파일 시스템 시그니처를 유지.
      2. 시그니처 제거
  6. w 명령: 변경 사항 저장
    1. 새로운 파티션 테이블이 디스크에 저장되고, 디스크 동기화가 완료
  • 파티션 크기를 40GB로 확장했지만, 파일 시스템 크기를 동기화(확장)하지 않았기 때문에 추가적인 20GB 공간이 사용되지 않고 있다.
  • 따라서 resize2fs 명령을 사용하여 파일 시스템 크기를 확장해야 한다.
  • 이후 lsblk를 보면 정상적으로 마운트된 것을 볼 수 있다.
