JPA Specification

  • JPA를 쓸 때 동적 쿼리를 짜야 하는 경우가 많다.
    • 예를 들면 frontend에서 input을 select 로 선택을 할 때마다 api를 호출한다던지 등등..
  • 이럴 때 쿼리문을 복잡하게 문자열로 이어 붙이는 대신, JPA Specification을 사용하면 좀 더 객체지향적으로 조건을 조합할 수 있다.

Why JPA Specification?

  1. 가독성
    1. 코드로 조건을 기술하니까 SQL 문자열로 직접 이어 붙이는 것보다 훨씬 깔끔하다
      1. 쿼리문은 너무 더러워져.. ㅇㅅㅇ;
  2. 유연성
    1. 조건을 분리해서 여러 개로 만들어놓고, 필요할 때만 붙여 써도 됨. 예를 들어 AND, OR 연산 같은 걸 자유롭게 쓸 수 있다.
  3. 재사용성
    1. 특정 조건을 하나의 메서드로 만들어두면, 이후 여러 Repository에서 쉽게 재사용할 수 있다.

기본적인 사용 방법

  • User 엔티티 
    @Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String name;

    @Column(nullable = false, unique = true)
    private String email;

    @Column(nullable = false)
    private Boolean active;

    @ManyToMany(fetch = FetchType.LAZY)
    @JoinTable(
        name = "user_roles",
        joinColumns = @JoinColumn(name = "user_id"),
        inverseJoinColumns = @JoinColumn(name = "role_id")
    )
    
    private Set<Role> roles = new HashSet<>();
    
}
  1. Specification 인터페이스 구현 
    public class UserSpecifications {

    public static Specification<User> hasName(String name) {
        return (root, query, criteriaBuilder) ->
                criteriaBuilder.equal(root.get("name"), name);
    }

    public static Specification<User> isActive() {
        return (root, query, criteriaBuilder) ->
                criteriaBuilder.equal(root.get("active"), true);
    }

    public static Specification<User> hasRole(String role) {
        return (root, query, criteriaBuilder) ->
                criteriaBuilder.equal(root.join("roles").get("name"), role);
    }
}
    • root: 현재 엔티티를 가리키는 Root 객체 (엔티티 속성 접근)
      • Specification<User> 를 해줬으므로 root 가 User 엔티티를 가르키게 된다.
    • query: 쿼리를 작성하는 CriteriaQuery 객체
    • cb: CriteriaBuilder 객체 (조건, 정렬, 집계 등 기능 제공)
  1. 구현한 Specification을 Repository에서 사용
    1. Repository에 JpaSpecificationExecutor<User> 추가
      1. JpaSpecificationExecutor<T> 인터페이스를 같이 상속해야 findAll(Specification<T>)를 쓸 수 있음.
      public interface UserRepository extends JpaRepository<User, Long>, JpaSpecificationExecutor<User> {
}
  1. 실제 호출 예시 
    import org.springframework.data.jpa.domain.Specification;

public class UserSpecifications {

    public static Specification<User> hasName(String name) {
        return (root, query, criteriaBuilder) ->
                criteriaBuilder.equal(root.get("name"), name);
    }

    public static Specification<User> isActive() {
        return (root, query, criteriaBuilder) ->
                criteriaBuilder.equal(root.get("active"), true);
    }

    public static Specification<User> hasRole(String role) {
        return (root, query, criteriaBuilder) ->
                criteriaBuilder.equal(root.join("roles").get("name"), role);
    }
}
    • hasName(String name)
      • User 엔티티의 name 필드가 주어진 name 값과 같은지를 확인하는 조건을 생성
      • criteriaBuilder.equal: 두 값을 비교하는 = 조건을 생성.
      • 쿼리
        • SELECT u FROM User u WHERE u.name = :name
  • hasRole(String role)
    • User 엔티티와 연관된 Role 엔티티의 name 필드가 주어진 role 값과 같은지를 확인하는 조건을 생성.
    • root.join("roles"): User와 연관된 roles 컬렉션에 조인.(roles는 @ManyToMany로 매핑된 필드일 가능성이 높음.)
    • criteriaBuilder.equal: 두 값을 비교하는 = 조건을 생성.
  1. AND/OR 연산 활용 
    import org.springframework.stereotype.Service;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;

@Service
public class UserService {

    private final UserRepository userRepository;

    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    public Page<User> searchUsers(String name, String role, Pageable pageable) {
        Specification<User> spec = Specification.where(UserSpecifications.hasName(name))
                .and(UserSpecifications.isActive())
                .or(UserSpecifications.hasRole(role));

        return userRepository.findAll(spec, pageable);
    }
}
  1. 여러 조건을 DTO로 묶어서 관리

  1. 추가 팁: fetch를 통한 관계 조회
    1. Specification을 사용할 때 fetch join을 활용하면, 지연 로딩으로 인해 발생하는 N+1 문제를 방지할 수 있음.
    public static Specification<User> fetchRoles() {
    return (root, query, criteriaBuilder) -> {
        root.fetch("roles", JoinType.LEFT);
        return criteriaBuilder.conjunction();
    };
}

Query DSL

  • Query DSL은 주로 Java 기반 프로젝트에서 사용하는 타입 안전(type-safe) 쿼리 빌더 라이브러리이다.
  • 데이터베이스나 JPA, MongoDB 등 다양한 스토어에 대해, 컴파일 시점에 오류를 잡을 수 있는 형식의 쿼리를 작성하도록 도와주는 게 핵심이다.
  • JPQL이나 SQL을 문자열로 작성할 때는 오타나 컬럼 이름 변경 같은 문제를 컴파일 시간에 발견하기 어려운데, Query DSL에서는 엔티티 필드를 기반으로 쿼리를 작성하니까 컴파일 시점에 에러를 찾을 수 있다.

  3. 기본 쿼리 
    import com.querydsl.jpa.impl.JPAQueryFactory;
import java.util.List;

public class UserRepository {

    private final JPAQueryFactory queryFactory;

    public UserRepository(EntityManager entityManager) {
        this.queryFactory = new JPAQueryFactory(entityManager);
    }

    public List<User> findUsersByAgeGreaterThan(int age) {
        QUser user = QUser.user;

        return queryFactory
                .selectFrom(user)
                .where(user.age.gt(age)) // 나이가 age보다 큰 사용자 조회
                .fetch(); // 리스트로 결과 가져오기
    }
}
  4. 동적 쿼리 작성 
    import com.querydsl.core.BooleanBuilder;
import com.querydsl.jpa.impl.JPAQueryFactory;
import java.util.List;

public class UserRepository {

    private final JPAQueryFactory queryFactory;

    public UserRepository(EntityManager entityManager) {
        this.queryFactory = new JPAQueryFactory(entityManager);
    }

    public List<User> findUsers(String name, Integer minAge, Integer maxAge) {
        QUser user = QUser.user;

        BooleanBuilder builder = new BooleanBuilder();
        if (name != null) {
            builder.and(user.name.eq(name)); // 이름 조건 추가
        }
        if (minAge != null) {
            builder.and(user.age.goe(minAge)); // 최소 나이 조건 추가
        }
        if (maxAge != null) {
            builder.and(user.age.loe(maxAge)); // 최대 나이 조건 추가
        }

        return queryFactory
                .selectFrom(user)
                .where(builder) // 동적 조건 추가
                .fetch();
    }
}
  5. 페이징 처리 
    import com.querydsl.jpa.impl.JPAQueryFactory;
import com.querydsl.core.types.dsl.NumberPath;
import com.querydsl.core.QueryResults;
import java.util.List;

public class UserRepository {

    private final JPAQueryFactory queryFactory;

    public UserRepository(EntityManager entityManager) {
        this.queryFactory = new JPAQueryFactory(entityManager);
    }

    public List<User> findUsersWithPagination(int page, int size) {
        QUser user = QUser.user;

        return queryFactory
                .selectFrom(user)
                .orderBy(user.age.desc()) // 나이 기준 내림차순 정렬
                .offset(page * size) // 시작 위치
                .limit(size) // 가져올 데이터 개수
                .fetch();
    }
}

      public class PostRepository {

    private final JPAQueryFactory queryFactory;

    public PostRepository(EntityManager entityManager) {
        this.queryFactory = new JPAQueryFactory(entityManager);
    }

    public List<Post> findPostsByUserName(String userName) {
        QPost post = QPost.post;
        QUser user = QUser.user;

        return queryFactory
                .selectFrom(post)
                .join(post.user, user) // Post와 User 조인
                .where(user.name.eq(userName)) // 사용자 이름 조건
                .fetch();
    }
}
