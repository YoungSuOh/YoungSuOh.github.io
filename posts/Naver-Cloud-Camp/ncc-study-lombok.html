Lombok @Data

Lombok @Data — Naver Cloud Camp 정리 노트.

프로젝트Naver Cloud Camp
  • @Data 는 @Getter , @Setter , @ToString, @EqualsAndHashCode , @RequiredArgsConstructor를 자동으로 적용해준다
  • @EqualsAndHashCode → 이놈은 멀까요?

@EqualsAndHashCode

  • equals()와 hashCode() 메서드를 생성해주는 역할을 한다.
  • 각각 객체의 동등성(equality) 및 해시코드 계산에 사용된다.

hashCode() : 객체를 숫자 값으로 매핑하는 역할을 하는 메서드

  • 두 객체가 내용이 같다면 hashCode()도 같아야 한다.
  • 하지만 hashCode()가 같다고 해서 내용이 반드시 같은 건 아니다!!
  • 이게 해시 충돌(hash collision)이다.

equals()

  • equals() 메서드는 두 객체의 내부 값이 정확히 같은지를 비교한다.
  • 객체의 실제 동등성을 확인하는 데 사용된다.
💡 equals() 메서드가 true를 반환하는 두 객체는 반드시 같은 hashCode()를 가져야 해. 그러나 같은 hashCode()를 가진 객체들이 equals() 메서드에서 서로 다른 결과를 반환할 수도 있다.

예제

public class Person {
    private String name;
    private int age;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Person person = (Person) o;
        return age == person.age && Objects.equals(name, person.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age); // name과 age를 기반으로 해시코드를 계산
    }
}
  • hashCode()는 두 객체의 내부 값을 숫자로 변환하는 메서드지만, 이 숫자는 객체의 동등성을 직접 비교하기 위한 것이 아니라 해시 기반 자료구조의 성능을 최적화하기 위한 것
  • equals() 메서드는 두 객체의 내용을 직접 비교해서 동등성을 판단하고, hashCode()는 그 비교를 효율적으로 수행하기 위한 해시코드를 제공한다.

hashCode() 메서드를 오버라이드할 때 해시 충돌을 줄이는 전략

  • 해시코드의 가중치(weight) 설정
    • 필드들을 조합할 때 각 필드에 적절한 가중치를 곱해서 더하는 방식을 사용해. 보통 소수(31, 37 등)를 곱하는 방식이 흔히 사용됨
    @Override
public int hashCode() {
    int result = 17;
    result = 31 * result + (name != null ? name.hashCode() : 0);
    result = 31 * result + age;
    return result;
}
