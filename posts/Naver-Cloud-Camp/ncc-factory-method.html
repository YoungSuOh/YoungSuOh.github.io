팩토리 메서드

팩토리 메서드 — Naver Cloud Camp 정리 노트.

OOPNaver Cloud Camp

팩토리 메서드(Factory Method)는 객체 생성 패턴 중 하나로, 객체 생성 방식을 서브클래스에서 결정하도록 하여 객체 생성에 대한 책임을 부모 클래스가 아닌 서브클래스가 가지게 만드는 디자인 패턴이다.

이 패턴을 사용하면, 구체적인 클래스 인스턴스를 직접 생성하지 않고, 팩토리 메서드를 통해 생성된 객체를 반환함으로써 객체 생성 방식을 캡슐화할 수 있다.

팩토리 메서드 패턴의 구조

  1. Product: 생성될 객체의 타입을 정의한 인터페이스 또는 추상 클래스.
  2. ConcreteProduct: Product를 구현하는 실제 객체.
  3. Creator: 팩토리 메서드를 선언하는 클래스. 일반적으로 인터페이스나 추상 클래스로 정의되며, 팩토리 메서드를 통해 Product를 반환함.
  4. ConcreteCreator: Creator를 상속한 구체적인 클래스. 팩토리 메서드를 오버라이드하여 실제로 생성할 객체를 정의.

팩토리 메서드 패턴의 예시

아래는 팩토리 메서드 패턴의 간단한 예시입니다. Product 인터페이스와 이를 구현한 ConcreteProductA, ConcreteProductB 클래스가 있고, 팩토리 메서드를 정의한 Creator와 이를 구현하는 ConcreteCreatorA, ConcreteCreatorB 클래스가 있습니다.

// Product 인터페이스 정의
interface Product {
    void use();
}

// ConcreteProductA 클래스
class ConcreteProductA implements Product {
    @Override
    public void use() {
        System.out.println("Product A 사용 중...");
    }
}

// ConcreteProductB 클래스
class ConcreteProductB implements Product {
    @Override
    public void use() {
        System.out.println("Product B 사용 중...");
    }
}

// Creator 클래스
abstract class Creator {
    // 팩토리 메서드
    public abstract Product createProduct();

    public void doSomething() {
        Product product = createProduct();
        product.use();
    }
}

// ConcreteCreatorA 클래스
class ConcreteCreatorA extends Creator {
    @Override
    public Product createProduct() {
        return new ConcreteProductA();
    }
}

// ConcreteCreatorB 클래스
class ConcreteCreatorB extends Creator {
    @Override
    public Product createProduct() {
        return new ConcreteProductB();
    }
}
  • main에서 사용 예시
public class Main {
    public static void main(String[] args) {
        Creator creatorA = new ConcreteCreatorA();
        creatorA.doSomething();  // Product A 사용 중...

        Creator creatorB = new ConcreteCreatorB();
        creatorB.doSomething();  // Product B 사용 중...
    }
}

팩토리 메서드 패턴의 장점

  1. 객체 생성 로직 캡슐화: 객체를 생성하는 코드를 감추어, 클라이언트는 구체적인 객체 생성 방식에 대한 정보가 없어도 사용이 가능합니다.
  2. 확장성: 새로운 제품 클래스가 추가되더라도 기존 코드를 수정하지 않고 새로운 서브클래스를 추가하기만 하면 됩니다.
  3. 의존성 감소: 부모 클래스에서 구체적인 클래스에 의존하지 않고 인터페이스에 의존하게 되어, 객체 생성에 대한 유연성이 증가합니다.

팩토리 메서드 패턴의 단점

  1. 클래스 수 증가: 패턴 구현을 위해 서브클래스를 만들어야 하므로, 클래스 수가 늘어날 수 있습니다.
  2. 구현 복잡성 증가: 팩토리 메서드 패턴은 객체 생성 방법을 변경하는 데 유리하지만, 객체 생성이 복잡하지 않은 경우 불필요하게 복잡한 구조를 만들 수 있습니다.

팩토리 메서드 패턴 vs 빌더 패턴

  • 팩토리 메서드 패턴: 구체적인 클래스의 인스턴스 생성을 서브클래스에서 결정하게 함으로써 객체 생성 로직을 캡슐화하는 데 중점을 둡니다.
  • 빌더 패턴: 객체 생성 과정을 단계별로 진행할 수 있게 하여, 필수 필드와 선택적 필드를 구분하고 복잡한 객체 생성을 쉽게 만듭니다.

팩토리 메서드는 객체 타입을 결정하는 데 유용하고, 빌더 패턴은 복잡한 객체를 유연하게 구성하는 데 더 적합합니다.
