[Spring] DI (Dependency Injection)

객체 생성 책임을 컨테이너로 분리해 결합도를 낮추고, 테스트/확장성을 높이는 의존성 주입(DI)을 정리합니다.

SpringDIOOPTestability

DI 란?

  • 객체 간 의존 관계를 개발자가 직접 묶는 것이 아니라, 외부 컨테이너(Spring)가 주입하는 방식

DI의 핵심 목적

  • 객체 간 결합도를 낮춤(Loosely Coupled)
  • 유지보수/확장성 향상(High Maintainability & Extensibility)
  • 단위 테스트 용이(Easier Unit Testing)

DI가 왜 필요한가?

직접 객체를 생성해도 동작은 하지만, 변경 요구가 생길수록 비용이 커진다.

DI 이전 방식의 문제

public class OrderService {
    private PaymentService paymentService = new PaymentService(); // 직접 객체 생성

    public void processOrder() {
        paymentService.pay();
    }
}
  • 강한 결합: OrderService가 구현체 생성까지 책임
  • 확장성 저하: 결제 구현체 변경 시 호출부도 수정 (OCP 위반 가능)
  • 테스트 어려움: mock 대체가 어려워 단위 테스트가 무거워짐

DI를 통한 해결

public interface PaymentService {
    void pay();
}
@Service
public class KakaoPayService implements PaymentService {
    public void pay() {}
}
class OrderService {
    private final PaymentService paymentService;

    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
  • 객체 생성 책임을 외부로 분리
  • 구체 클래스가 아닌 추상(인터페이스)에 의존하도록 전환

의존성 주입 방법

1) 생성자 주입 (Constructor Injection)

생성자를 통해 의존성을 주입하는 방식

  • 불변성: 필드를 final로 두기 쉬움
  • 순환 참조 감지: 애플리케이션 시작 시점에 문제 노출
  • 테스트 용이: 생성자 인자로 mock 주입이 쉬움
@Component
public class OrderService {
    private final PaymentService paymentService;

    @Autowired // Spring 4.3+ 에서는 단일 생성자면 생략 가능
    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}

2) 필드 주입 (Field Injection)

필드에 @Autowired를 직접 붙이는 방식

  • 코드는 짧지만 의존성이 숨겨져 구조 파악이 어렵다.
  • 컨테이너 없이 객체를 생성하기 어려워 순수 단위 테스트가 불편하다.
@Component
public class OrderService {
    @Autowired
    private PaymentService paymentService;
}

단점

  1. 의존성 교체/제어가 어렵다 (private 필드)
  2. new OrderService() 시 주입이 없어 null 문제 가능
  3. 생성자 주입 대비 설계 결함이 늦게 드러날 수 있다

3) 세터 주입 (Setter Injection)

@Autowired를 붙인 setter 메서드로 주입하는 방식

  • 객체 생성 후에도 의존성 변경 가능
  • 선택적 의존성 처리에 유용
  • 대신 가변성이 커지고, 호출 순서에 따라 null 상태가 생길 수 있음
@Component
public class OrderService {
    private PaymentService paymentService;

    @Autowired
    public void setPaymentService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
  • @Autowired는 기본적으로 주입 대상이 없으면 오류
  • 대상이 없어도 동작시키려면 @Autowired(required = false) 사용 가능

단점

  1. 의존성이 완전히 세팅되기 전 객체가 사용될 위험
  2. setter 노출로 객체 상태 변경 가능성이 증가
