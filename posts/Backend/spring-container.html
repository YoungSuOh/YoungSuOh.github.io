[Spring] Spring Container

스프링 컨테이너는 객체(Bean)의 생성, 관리, 생명주기를 책임지는 핵심입니다.

SpringDIApplicationContext

애플리케이션에서 필요한 객체를 직접 만들지 않고, 스프링 컨테이너가 대신 객체를 생성·관리하며 필요한 시점에 주입해 줍니다.

스프링 컨테이너의 역할

  1. 객체(Bean) 생성
    @Component, @Service, @Repository, @Controller, @Bean 설정을 기반으로 Bean을 생성
  2. 의존성 주입(DI)
    @Autowired, @Qualifier, @Resource 등을 통해 필요한 객체를 자동 주입
  3. 객체 생명주기 관리
    생성 → 초기화 → 사용 → 소멸 과정을 관리하며 @PostConstruct, @PreDestroy 사용 가능
  4. 객체 조회 및 제공
    필요 시 ApplicationContext.getBean()으로 조회 가능

ApplicationContext: 스프링 컨테이너

1) 생성자 주입

  1. 생성자를 통해 의존 관계를 연결하는 방식
  2. XML 설정 파일에서는 <bean> 하위에 <constructor-arg>를 사용
    1. 전달 인자가 기본 타입이면 value 속성 사용
    2. index 속성으로 순서 지정 가능
    3. type 속성으로 타입 지정 가능
    4. 객체 전달은 ref 속성 사용

2) Setter 주입

  1. setter 메서드를 이용해 의존 관계를 연결하는 방식
  2. <property> 요소의 name 속성으로 주입 대상 필드를 지정
    1. 기본값 전달 가능
    2. 객체 전달 시 ref 사용 (예: Foo 빈이 Bar 빈을 참조)

스프링 컨테이너를 사용하는 이유

  1. 객체 생명주기를 스프링이 관리해 필요 시 생성·소멸 제어가 쉽다.
  2. DI로 결합도를 낮출 수 있어 유지보수에 유리하다.
  3. 싱글톤 패턴이 기본 적용되어 같은 Bean을 반복 생성하지 않고 공유한다.
  4. AOP 적용이 쉬워 로깅·트랜잭션 같은 공통 관심사를 분리할 수 있다.

스프링 컨테이너와 메모리

스프링 컨테이너는 Bean 메타데이터와 인스턴스를 메모리에 보관·관리합니다. Bean 인스턴스 자체는 일반적으로 JVM Heap에 존재합니다.

Bean 저장 관점 정리

  • Singleton (기본): 컨테이너당 1개 인스턴스를 공유. (Spring Bean Registry에서 참조 관리)
  • Prototype: 요청할 때마다 새로운 인스턴스 생성
  • Request / Session / Application: 웹 스코프 기준으로 요청·세션·애플리케이션 범위에서 관리
