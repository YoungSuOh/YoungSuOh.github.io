[Spring] Spring MVC (DispatcherServlet)

Spring MVC의 핵심인 DispatcherServlet이 요청을 받아 컨트롤러 실행, 뷰 선택, 응답 반환까지 이어지는 흐름을 정리합니다.

SpringMVCDispatcherServlet
  • 스프링 MVC도 컨트롤러를 사용하여 클라이언트 요청을 처리한다.
  • 스프링에서는 DispatcherServlet이 MVC에서 C(Control) 흐름의 중심을 담당한다.

스프링 MVC의 구성 요소

  1. 클라이언트 요청 (HTTP Request)
  2. DispatcherServlet이 요청 수신
    • DispatcherServlet은 Spring MVC의 Front Controller로, 모든 HTTP 요청을 받아 적절한 컨트롤러로 전달하고 응답 생성을 조율한다. 
    <servlet>
    <servlet-name>dispatcher</servlet-name>
    <servlet-class>org.springframework.web.servlet.DispatcherServlet</servlet-class>
</servlet>

<servlet-mapping>
    <servlet-name>dispatcher</servlet-name>
    <url-pattern>/</url-pattern> <!-- 모든 요청을 받음 -->
</servlet-mapping>
  3. HandlerMapping에서 요청을 처리할 컨트롤러를 찾음
  4. Controller 실행
    • HandlerAdapter가 해당 컨트롤러 메서드를 실행하고 결과를 반환한다.
    @GetMapping("/hello")
public String hello() {
    return "helloView";
}

    컨트롤러는 보통 String 형태의 뷰 이름(View Name)을 반환한다.

  5. ViewResolver로 View 찾기
    • 컨트롤러가 반환한 뷰 이름을 기준으로 적절한 View를 찾는다.
    return "helloView"; // ViewResolver가 해당 뷰를 찾음

    일반적으로 .jsp, .html 같은 뷰 파일 경로를 조합한다.

    <bean class="org.springframework.web.servlet.view.InternalResourceViewResolver">
    <property name="prefix" value="/WEB-INF/views/" />
    <property name="suffix" value=".jsp" />
</bean>
  6. View 렌더링 후 응답 반환: 최종 렌더링 결과가 HTTP Response로 클라이언트에 전달된다.
