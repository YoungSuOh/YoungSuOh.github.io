Java 정리 ② — 람다·스트림·어노테이션·리플렉션

람다·함수형 인터페이스, Stream 중간·최종 연산, 어노테이션·메타 어노테이션, 리플렉션과 프레임워크 연결을 정리합니다.

JavaLambdaStreamReflection

① 문자열·예외·제네릭 · ② 람다·스트림·어노테이션 · ③ System.out 심화

Q1) 람다란?

메서드를 값처럼 전달하기 위한 문법으로, 함수형 인터페이스의 단일 추상 메서드를 구현하는 코드를 짧게 씁니다.

(매개변수) -> { 실행 코드 }
Runnable r1 = new Runnable() {
  @Override public void run() { System.out.println("익명 클래스"); }
};
Runnable r2 = () -> System.out.println("람다");
  • @FunctionalInterface — 추상 메서드가 하나인 인터페이스(디폴트·정적 메서드는 제외 규칙 참고).
  • 컬렉션·API와 함께 쓰면 반복문 대신 선언적으로 동작을 조합하기 좋습니다.

Q2) Stream이란?

요소의 흐름에 대해 중간 연산(filter, map, sorted …)과 최종 연산(forEach, collect, reduce …)을 체이닝하는 API입니다. 지연 평가는 최종 연산 시점에 일어납니다.

List<String> names = Arrays.asList("Alice", "Bob", "Charlie");
names.stream()
    .filter(n -> n.startsWith("A"))
    .forEach(System.out::println);
List<String> upper = names.stream()
    .map(String::toUpperCase)
    .sorted()
    .collect(Collectors.toList());

Q3) 람다와 스트림이 생긴 이유

  1. 가독성 — “무엇을 할지”에 가까운 표현.
  2. 간결함 — 보일러플레이트 감소.
  3. 병렬 스트림 등과 결합한 처리(주의해서 사용) 등 확장 여지.
List<Integer> result = numbers.stream()
    .filter(n -> n % 2 == 0)
    .map(n -> n * n)
    .sorted()
    .collect(Collectors.toList());

Q4) 어노테이션(Annotation)

코드에 붙는 메타데이터입니다. 컴파일러·런타임·프레임워크가 읽고 동작을 바꿉니다.

어노테이션 역할
@Override 부모 메서드 오버라이드 검증
@Deprecated 사용 중단 경고
@SuppressWarnings 특정 컴파일 경고 억제
@FunctionalInterface 함수형 인터페이스 명시

메타 어노테이션

이름 설명
@Retention SOURCE / CLASS / RUNTIME 유지 범위
@Target 적용 위치(TYPE, METHOD, FIELD …)
@Documented Javadoc 포함
@Inherited 클래스 상속 시 전달
@Repeatable 동일 요소에 반복 적용

Q5) 어노테이션이 필요한 이유

  • 설정을 코드 옆에 두어 가독성·응집도 향상
  • 프레임워크가 스캔해 보일러플레이트 감소(Spring, JPA 등)
  • 컴파일 타임 검사(@Override 등)

리플렉션(Reflection)

런타임에 클래스·메서드·필드 정보를 읽고, 객체 생성·메서드 호출·필드 접근을 동적으로 수행하는 API입니다.

사례 설명
Spring, JPA 빈 등록, 프록시, 엔티티 매핑 등에 활용
Jackson / Gson 필드·getter 기반 직렬화
동적 프록시 AOP 등

어노테이션과의 관계 어노테이션은 그 자체로 로직이 없고, RUNTIME으로 유지된 경우 리플렉션으로 읽어 실제 동작(프레임워크)이 연결됩니다.

직접 리플렉션으로 어노테이션을 파싱하는 유틸을 만든 경험이 없더라도, Spring이 컨텍스트 기동 시 클래스패스를 스캔해 빈을 등록한다는 흐름은 같은 계열 개념으로 이해할 수 있습니다.
