Java 정리 ③ — System.out.println과 성능

표준 출력의 I/O 비용, flush·synchronized, BufferedWriter·로깅 프레임워크 대안을 정리합니다.

JavaI/OPerformanceLogging

① 문자열·예외·제네릭 · ② 람다·스트림·어노테이션 · ③ System.out 심화

Q1) System.out.println이 성능이 좋지 않다고 하는 이유

  1. I/O는 상대적으로 비쌉니다. System.out은 PrintStream이고, 콘솔·터미널로 넘기는 과정에서 OS·인코딩 처리 등이 겹칩니다.
  2. 라인 단위로 flush에 가깝게 동작하는 경향 — 구현에 따라 다르지만, 매번 즉시 보이게 하려는 특성 때문에 버퍼를 크게 쌓아 두지 못하는 경우가 많아 호출 빈도가 곧 I/O 빈도가 됩니다.
  3. PrintStream의 출력 메서드는 synchronized로 동기화되어 있어, 멀티스레드에서 락 경합이 날 수 있습니다.

대안

1) BufferedWriter 등으로 버퍼링

BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(System.out));
bw.write("Hello, World!");
bw.newLine();
bw.flush(); // 필요할 때만
bw.close();

2) SLF4J + Logback 등 로깅 프레임워크

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

class Example {
  private static final Logger log = LoggerFactory.getLogger(Example.class);
  void run() {
    log.info("메시지");
  }
}

비동기 어펜더·레벨 필터·파일 롤링 등을 쓰면 운영·성능 모두 유리한 경우가 많습니다. 애플리케이션 로그는 System.out 대신 로거가 일반적입니다.
