[GC] GC 로그

JVM GC 로그를 활성화하고 읽는 법 — Pause Young/Full, G1 Evacuation, Allocation/Promotion Failure 등 이벤트 종류와 Memory Leak 징후를 판별하는 실전 패턴을 정리합니다.

JavaJVMGCLoggingPerformance

GC 로그는 "언제 GC가 발생했고, 얼마나 메모리를 회수했고, 애플리케이션이 얼마나 멈췄는지"를 기록한 실행 이력이다.

실무에서는 GC 로그만 잘 읽어도 다음을 판단할 수 있다.

  • Minor GC가 너무 자주 발생하는가?
  • Promotion이 과도한가?
  • Full GC가 발생하는가?
  • Memory Leak이 있는가?
  • Heap 크기가 적절한가?
  • Pause Time이 SLA를 위반하는가?

GC 로그 활성화

Java 9 이상에서는 Unified Logging 방식으로 활성화한다.

-Xlog:gc*:file=gc.log:time,uptime,level,tags
  • gc* — GC 관련 세부 로그 출력
  • file=gc.log — 파일 저장
  • time — 실제 시각
  • uptime — JVM 시작 후 경과 시간
  • level — info/debug 수준
  • tags — 로그 종류

기본적인 로그 예시

[2.345s][info][gc] GC(12) Pause Young (Normal) (G1 Evacuation Pause) 256M->84M(512M) 18.7ms
  • [2.345s] — JVM 시작 후 2.345초 시점
  • GC(12) — 12번째 GC 이벤트
  • (G1 Evacuation Pause) — G1 GC가 살아있는 객체를 다른 Region으로 복사하는 단계
  • 256M->84M(512M)
    • GC 전 사용량: 256MB
    • GC 후 사용량: 84MB
    • 전체 Heap 크기: 512MB
    • 즉, 약 172MB를 회수했다.
  • 18.7ms — 애플리케이션이 약 18.7ms 동안 일시 중지되었다.

주요 GC 이벤트 종류

  • Pause Young — Young Generation 수집
  • Pause Full — Heap 전체 수집
  • Concurrent Mark Cycle — Old 영역의 동시 마킹
  • Mixed GC — Young + 일부 Old Region 동시 수집 (G1)

1. Full GC 로그 예시

Pause Full (G1 Compaction Pause) 2.8s
  • Full GC 수행
  • 압축 (compaction 포함)
  • 2.8초 동안 STW 수행

2. G1 특화 로그 예시

Concurrent Mark Cycle
Pause Young (Prepare Mixed)
Pause Young (Mixed)
  • Concurrent Mark Cycle — Old Generation 전체의 생존 객체를 추적
  • Prepare Mixed — Mixed GC 준비 단계
  • Mixed — Young + 일부 Old Region 함께 수집

3. Allocation Failure

Pause Young (Allocation Failure)
  • 새 객체를 생성할 공간이 부족해 Minor GC가 즉시 발생했다는 의미

4. Promotion Failure

  1. Young에서 살아남은 객체를 Old로 이동할 공간이 부족한 상황이다.
  2. 이 경우 Full GC로 이어질 수 있다.

로그에서 가장 중요한 지표

  1. Pause Time — 응답 지연과 직접 연결됨
  2. GC Frequency — 얼마나 자주 발생하는지
  3. Reclaimed Memory — 얼마나 많이 회수했는지
  4. Full GC 여부 — 심각한 문제 신호일 수 있음
  5. Heap After GC — GC 후에도 사용량이 높은지 확인

정상적인 패턴 예시

Pause Young 5ms ~ 30ms
Minor GC는 주기적으로 발생
Full GC 거의 없음
Heap after GC가 충분히 감소

비정상적인 패턴 예시

1. Full GC 반복

Pause Full ... 3.5s
Pause Full ... 4.1s

2. GC 후 메모리 감소 거의 없음

7.8G -> 7.7G

3. Pause Time 지속 증가

  1. 메모리 압박 또는 누수 가능성.

✅ Memory Leak 징후

GC 후 사용량이 점진적으로 증가:

1.2G -> 0.8G
1.8G -> 1.4G
2.4G -> 2.1G
3.0G -> 2.8G
  • 최저점이 계속 상승하면 누수를 의심한다.
