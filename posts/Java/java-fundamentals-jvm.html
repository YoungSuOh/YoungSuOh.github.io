📌 자바 기본

Java는 객체 지향 프로그래밍 언어로, 안정성과 확장성이 뛰어나며 다양한 OS 환경에서 사용할 수 있습니다.

Java의 특징

  1. OOP
    1. Java는 클래스와 객체 개념을 기반으로 하는 객체 지향 언어입니다.
    2. OOP의 특징인 캡슐화, 상속, 다형성, 추상화를 지원합니다.
      1. 캡슐화: 객체의 데이터와 이를 조작하는 메서드를 하나의 단위로 묶고, 외부에서 직접 접근하지 못하게 제한하는 기법입니다. (클래스 내부 데이터를 private으로 숨기고 getter / setter 등으로 접근)
      2. 상속: 부모 클래스의 필드와 메서드를 자식이 물려받는 개념으로, 코드 재사용과 유지보수에 유리합니다.
      3. 다형성: 하나의 클래스나 메서드가 여러 형태를 가질 수 있게 하는 개념으로, 오버로딩과 오버라이딩이 대표적입니다.
      4. 추상화: 불필요한 세부 정보를 숨기고 핵심 기능만 노출하는 개념으로, 추상 클래스와 인터페이스로 구현합니다.
  2. JVM
    1. Java 코드는 바이트코드(.class)로 변환된 뒤 JVM에서 실행됩니다.
    2. JVM이 설치된 환경에서는 OS와 관계없이 동일한 방식으로 프로그램을 실행할 수 있습니다.
  3. Garbage Collection
    1. 개발자가 직접 메모리를 해제하지 않아도 GC가 사용하지 않는 객체를 정리합니다.
  4. 멀티스레딩 지원
    1. 내장 Thread 등을 통해 멀티스레드 프로그래밍을 구현할 수 있습니다.
    2. 실제 경험: GUI 게임 프로젝트에서 캐릭터가 사라지는 문제가 있었는데, Runnable과 Thread.sleep()으로 프레임 간격을 맞춰 화면 갱신을 안정화한 경험이 있습니다.

Java의 단점

  1. 상대적으로 느림
    1. JVM 위에서 동작하므로 C/C++ 같은 네이티브 언어보다 실행 속도가 느릴 수 있습니다.
    2. 바이트코드를 해석·JIT 컴파일하는 과정에서 추가 오버헤드가 발생할 수 있습니다.
  2. 메모리 소비
    1. 기본형을 제외한 대부분의 데이터가 힙에 올라갑니다.
    2. GC가 편리하지만, GC 동작 자체가 CPU를 사용해 성능에 영향을 줄 수 있습니다.
  3. 클래스 다중 상속 미지원
    1. C++과 달리 Java는 클래스의 다중 상속을 지원하지 않습니다.
    2. 다이아몬드 문제(Diamond Problem)와 메서드 충돌을 피하기 위한 설계입니다.
      • 두 부모가 같은 조상을 물려받을 때, 자식이 둘 다 상속하면 어느 쪽 메서드를 쓸지 모호해지는 문제입니다. 
    #include <iostream>

class A {
public:
    void show() { std::cout << "A 클래스" << std::endl; }
};

class B : public A {};
class C : public A {};
class D : public B, public C {};

int main() {
    D d;
    d.show();  // B의 show인지 C의 show인지 모호 → 컴파일 오류
    return 0;
}

    다중 상속이 필요하면 인터페이스 구현 등으로 우회합니다.

Java의 실행 과정

기본 흐름은 네 단계로 정리할 수 있습니다.

  1. 소스 작성 — .java 파일
  2. 컴파일 — javac가 바이트코드 .class 생성
  3. JVM 실행 — OS에 무관하게 바이트코드 해석(JIT 등)
  4. OS와 연동 — JVM이 OS와 상호작용하며 프로그램 실행

JVM의 구조와 동작 흐름

  1. 메모리 할당
    프로그램이 시작되면 JVM 프로세스가 생성되고, OS로부터 Heap·Stack·Method Area 등 필요한 메모리를 할당받습니다.
  2. 컴파일
    javac가 .java를 읽어 .class 바이트코드로 변환합니다.
  3. 클래스 로더 — JVM 메모리(Runtime Data Area)로 로드. 단계는 로딩 → 링킹 → 초기화입니다.
    • 로딩: 바이트코드를 찾아 Method Area에 적재
    • 링킹: 검증(바이트코드 형식) → 준비(static 필드 메모리·기본값) → 해석(심볼릭 레퍼런스를 실제 주소로)
    • 초기화: static 필드에 명시된 값 반영
  4. 실행 엔진 — 인터프리터(한 줄씩 해석)와 JIT(자주 쓰는 코드를 네이티브로 캐싱)로 바이트코드를 실행합니다.
  5. GC — 사용하지 않는 객체를 정리합니다.
  6. 최종적으로 프로그램 결과가 출력됩니다.
