0. 이 문서를 읽는 법

이 가이드는 Anthropic의 두 가지 주요 개발자 접점인 Claude(대화형 AI 어시스턴트, 웹/데스크톱/모바일/API)와 Claude Code(터미널과 IDE에서 동작하는 에이전트형 코딩 도구)를 처음 도입하는 개발자에게 필요한 모든 기초를 한 권에 담는 것을 목표로 합니다. 단순한 "이런 게 있다" 수준이 아니라, 실제 업무에 들이기 전에 알아두면 좋은 모델 특성, 컨텍스트 다루는 법, 권한 관리, 비용·보안 트레이드오프까지 포함합니다.

전제하는 환경

독자는 git, 터미널 기본 명령(cd, ls, cat), 자신의 주력 언어에 익숙하며, macOS 또는 Linux 셸을 사용한다고 가정합니다. Windows 사용자는 WSL2 환경을 권장합니다.

버전 차이에 대한 주의
이 문서는 2026년 4월 기준 최신 모델 라인업(Opus 4.6 / Sonnet 4.6 / Haiku 4.5)과 Claude Code 최신 안정 버전을 전제로 합니다. 명령어 이름이나 플래그는 마이너 업데이트로 바뀔 수 있으므로, claude --help와 공식 문서를 항상 함께 참조하세요.

이 문서를 다 읽고 나면 할 수 있는 일

  1. Claude와 Claude Code 중 업무에 맞는 도구를 선택할 수 있다.
  2. 두 도구 모두를 자신의 컴퓨터에 설치하고 첫 작업을 끝낼 수 있다.
  3. 모델 선택(Opus / Sonnet / Haiku)의 트레이드오프를 이해하고 비용을 통제할 수 있다.
  4. 슬래시 명령·MCP·훅(hook)을 활용해 자기 워크플로우에 맞게 도구를 확장할 수 있다.
  5. 팀에 안전하게 도입하기 위한 권한·시크릿·CI 정책을 설계할 수 있다.

1. Claude란 무엇인가

"Claude"는 사람마다 가리키는 것이 조금씩 다릅니다. 어떤 사람에게는 모델 자체를, 어떤 사람에게는 웹사이트(claude.ai)를, 또 어떤 사람에게는 API를 의미합니다.

1.1 세 가지 층위 — 모델, 제품, 인터페이스

  • ① 모델 (Model) — 실제로 텍스트를 생성하는 신경망 그 자체. Anthropic이 학습·배포하며 이름으로 식별됩니다 (예: claude-opus-4-6, claude-sonnet-4-6, claude-haiku-4-5).
  • ② 제품 (Product) — 모델을 감싸 사용자에게 전달하는 패키지. 대화형 챗(claude.ai), Claude Code, Claude in Chrome, Claude in Excel 등.
  • ③ 인터페이스 (Interface) — 같은 제품을 어떤 입출구로 만나는가. 웹, 데스크톱 앱, 모바일 앱, REST API, SDK 등.

1.2 모델 라인업 — Opus, Sonnet, Haiku

모델대표 식별자특징주된 용도
Opusclaude-opus-4-6가장 추론력이 강하고 복잡한 작업에 강함. 비용·지연 시간이 가장 큼.설계, 마이그레이션, 깊은 디버깅, 연구
Sonnetclaude-sonnet-4-6품질·속도·비용의 균형이 좋아 "기본 모델"로 가장 자주 쓰임.일상 코딩, 리뷰, 문서화
Haikuclaude-haiku-4-5가장 빠르고 저렴. 짧은 작업·도구 호출·라우팅에 강점.분류, 요약, 라이트한 자동화
실무 가이드
개인 개발자라면 90%의 작업을 Sonnet으로 처리하고, 어려운 마이그레이션이나 아키텍처 토론에서만 Opus로 "승급"시키는 패턴이 비용 대비 효율이 가장 좋습니다.

1.3 Claude(대화형 제품)가 잘하는 일

  • 긴 문서 이해 — 사양서·논문·계약서·로그 수만 줄을 읽고 핵심을 정리.
  • 설계와 검토 — 시스템 설계 검토, 트레이드오프 토론, 아키텍처 다이어그램 글로 설명.
  • 코드 생성과 리뷰 — 새 모듈 초안 작성, 리팩터 제안, PR 리뷰의 1차 패스.
  • 데이터 정리 — CSV·JSON·표를 받아 변환·요약·시각화 코드까지 묶어 제공.
  • 커뮤니케이션 — 이슈 글, 사후 분석, 기술 블로그, 이메일 톤 다듬기.

1.4 인터페이스별 차이

인터페이스특징언제 쓰면 좋은가
claude.ai (웹)가장 빠르게 시작할 수 있는 진입점. 파일 업로드, 프로젝트 단위 컨텍스트 보관, 아티팩트(코드/문서 미리보기) 지원.탐색·학습·문서 작업
데스크톱 앱웹과 거의 동일한 기능에 더해 OS 단축키·파일 시스템 권한·로컬 도구 연동 가능.매일 쓰는 메인 도구
모바일 앱이동 중 짧은 질문, 음성 입력, 사진을 찍어 바로 묻기.아이디어·메모·번역
APISDK(Python/TS/Go 등)로 직접 호출. 스트리밍, 도구 호출(tool use), 비전 입력 등 세밀한 제어.제품 빌딩·자동화
Claude in Chrome브라우저 안에서 페이지를 읽고 양식을 채우거나 작업을 수행.웹 리서치·반복 업무

1.5 "스킬"과 "프로젝트" — 컨텍스트를 재사용하는 두 축

  • 프로젝트 (Project) — 대화 묶음 + 공유 시스템 프롬프트 + 첨부 파일을 한 묶음으로 보관하는 단위. "회사 코드베이스 Q&A", "블로그 작성"처럼 도메인을 분리하면 매 대화에서 같은 맥락이 자동으로 들어갑니다.
  • 스킬 (Skill) — 특정 작업 유형(예: PDF 처리, pptx 생성)에 대해 베스트 프랙티스를 모아둔 폴더 형식의 "플레이북". 작업 종류만 인식되면 알아서 해당 스킬의 지침을 읽고 따라옵니다.

1.6 토큰, 컨텍스트 윈도우, 비용의 관계

모든 LLM은 입력과 출력을 토큰(token) 단위로 다룹니다. 한국어는 대체로 1자당 1.5~2토큰, 영어는 1단어당 약 1.3토큰 수준입니다.

  • 입력 토큰 — 시스템 프롬프트 + 대화 이력 + 첨부 파일 텍스트.
  • 출력 토큰 — 모델이 새로 만들어내는 응답.
  • 비용은 보통 입력보다 출력이 더 비싼 구조이며, Opus > Sonnet > Haiku 순으로 비쌉니다.
실전 팁 — 컨텍스트 다이어트
같은 답을 받기 위해 굳이 파일 전부를 넣을 필요는 없습니다. 관련된 함수·테스트·관련 문서 일부만 전달하면 답 품질은 거의 같으면서 비용이 절반 이하가 되는 경우가 흔합니다.

1.7 도구 사용(Tool Use)과 멀티모달

Claude는 외부 도구를 호출해서 결과를 받아 다시 추론에 쓰는 것이 가능합니다. 검색, 계산기, 사내 API, 파일 시스템 등 어떤 함수든 도구로 등록하면 모델이 필요할 때 알아서 호출합니다.

// (개념 예시) TypeScript SDK
const response = await client.messages.create({
  model: "claude-sonnet-4-6",
  tools: [
    { name: "search_orders", input_schema: { /* JSON Schema */ } },
    { name: "refund_order",  input_schema: { /* JSON Schema */ } },
  ],
  messages: [{ role: "user", content: "주문번호 1234 환불해줘" }],
});

1.8 흔한 오해 정리

  • 오해 1. "Claude = 단일 모델"이다. → 아닙니다. Opus/Sonnet/Haiku 등 라인업이 있고 버전이 갱신됩니다.
  • 오해 2. claude.ai에서 본 답과 API 답이 같다. → 시스템 프롬프트·도구·온도 설정이 다르므로 같은 모델이라도 차이가 납니다.
  • 오해 3. Claude Code는 별도 모델이다. → 같은 Claude 모델을 쓰지만 "에이전트 루프 + 도구"로 감싼 별개의 제품입니다.
  • 오해 4. 토큰은 글자 수다. → 단어/형태소 기반의 BPE 단위라 한글은 자모/음절 단위로 분리되어 한 글자가 2토큰 이상이 되기도 합니다.

2. Claude Code란 무엇인가

한 줄로 말하면 Claude Code는 "당신의 코드베이스 안에서 일하는 에이전트 형태의 Claude"입니다. 터미널에서 claude 명령으로 띄우거나, IDE 통합으로 띄울 수 있습니다. 채팅 한 번에 답을 받고 끝나는 게 아니라, 여러 단계의 도구 호출(파일 읽기·쓰기·검색·테스트 실행)을 직접 수행하면서 일을 끝냅니다.

2.1 "에이전트"라는 단어가 뜻하는 것

모델이 한 번의 응답만 내고 끝나는 것이 아니라, 관찰 → 계획 → 행동 → 다시 관찰의 루프를 자기 주도로 도는 형태입니다. Claude Code는 다음과 같은 도구를 기본 장착하고 있습니다.

  • 파일 도구 — Read / Write / Edit / Glob / Grep
  • 실행 도구 — Bash (셸 명령 실행)
  • 웹 도구 — WebFetch / WebSearch
  • 태스크/서브에이전트 — 큰 작업을 하위 에이전트에 위임
  • MCP 도구 — 외부 시스템(깃허브, 슬랙, Linear, 자체 API 등)을 자유롭게 연결

2.2 어디서 어떻게 동작하는가

  • 실행 위치 — Claude Code는 당신의 컴퓨터(또는 컨테이너) 위에서 직접 동작합니다. 모델 호출은 Anthropic 서버에 가지만, 파일과 명령은 모두 로컬에서 실행됩니다. 즉, 코드가 어디에도 업로드되지 않고도 분석할 수 있습니다.
  • 인터페이스 — 기본은 터미널 TUI입니다. JetBrains/VS Code 플러그인이 있어 IDE 사이드바에서도 같은 세션을 다룰 수 있고, 워크플로우 자동화를 위한 SDK(에이전트 SDK)도 제공됩니다.

2.3 핵심 기능을 한 번에 보기

기능설명
슬래시 명령(/...)자주 쓰는 작업을 짧은 키워드로 호출. /init, /review, /security-review 등.
플랜 모드 (Plan Mode)실행 없이 "무엇을 할지"의 계획만 출력시키고 사용자가 승인하면 실행으로 넘어가는 안전 모드.
훅 (Hooks)특정 이벤트(예: 도구 사용 전후, 세션 시작) 시 자동 실행될 셸 스크립트를 연결.
MCP 서버외부 도구(깃허브, 슬랙, 노션 등)를 표준 프로토콜로 연결.
서브에이전트대규모 탐색·검토를 별도 에이전트에 위임해 메인 컨텍스트를 깨끗하게 유지.
세션 재개·분기작업을 중단하고 다음 날 이어서, 또는 분기하여 다른 시도를 진행 가능.

2.4 안전 모델 — 권한, 샌드박스, 승인

에이전트가 여러분의 컴퓨터에서 셸 명령을 실행한다는 건 강력하지만 위험할 수 있습니다. Claude Code는 다음 세 가지 장치로 이를 통제합니다.

  1. 권한 프롬프트 — 파괴적이거나 외부에 영향을 주는 명령(예: rm, git push, 네트워크 호출)은 실행 전에 사용자 확인을 요청합니다.
  2. 허용 목록(allowlist) — 자주 쓰는 안전한 명령(npm test 등)은 ~/.claude/settings.json에 미리 등록해 묻지 않게 할 수 있습니다.
  3. 플랜 모드 / 드라이런 — 실제 실행 없이 "했다면 어떻게 됐을지" 계획만 보여주고 끝냅니다.
// ~/.claude/settings.json (예시)
{
  "permissions": {
    "allow": ["Bash(npm test)", "Bash(npm run lint)", "Read(./**/*)"],
    "deny":  ["Bash(rm -rf *)", "Bash(git push --force*)"]
  },
  "model": "claude-sonnet-4-6"
}

2.5 컨텍스트와 메모리

Claude Code는 현재 디렉터리를 작업 컨텍스트의 출발점으로 삼습니다. 그리고 두 종류의 "기억"을 가집니다.

  • 프로젝트 메모리 — CLAUDE.md : 리포지토리 루트의 CLAUDE.md는 매 세션 시작 시 자동으로 읽힙니다. 코드베이스 개요, 테스트 명령, 코딩 컨벤션 등을 적어두면 모든 작업의 "북극성" 역할을 합니다.
  • 사용자 메모리 — ~/.claude/CLAUDE.md : 모든 프로젝트에 공통으로 적용되는 개인 선호(언어, 스타일, 기본 모델 등)를 적어 둡니다.

2.6 Claude Code가 잘 어울리는 작업

  • 여러 파일에 걸친 리팩터·이름 변경: 의존성과 테스트까지 함께 갱신.
  • 대형 마이그레이션: ESM 전환, Webpack→Vite 같은 다단계 작업.
  • 디버깅: 로그를 받아 원인을 찾고, 패치를 적용하고, 테스트로 검증까지.
  • 테스트 작성: 누락된 분기에 대한 단위/통합 테스트 자동 작성.
  • 코드베이스 탐색·문서화: 새로 합류한 리포에서 "이 모듈이 뭐 하는 거야?"에 답하기.
  • 리뷰: /review, /security-review로 PR 1차 검토.

2.7 잘 어울리지 않는 작업

  • 의도가 모호한 "알아서 해줘" 류 — 사람이 한 번 의도를 정리해 넘기는 편이 효율적.
  • 도메인 지식이 매우 좁고 비공개여서 컨텍스트 제공이 어려운 경우.
  • 실행 가능한 검증(테스트·타입체크·빌드)이 전혀 없는 환경 — 에이전트는 "피드백 루프"에 강합니다.

3. Claude vs Claude Code — 한눈에 보는 비교

둘은 "어느 쪽이 더 좋다"의 문제가 아니라 역할이 다릅니다. 같은 모델을 다른 운반체에 실은 셈입니다.

주된 인터페이스웹·데스크톱·모바일·API터미널 TUI·IDE 플러그인·SDK
입력 형태자연어 + 첨부 파일자연어 + 코드베이스(파일 시스템)
실행 환경Anthropic 측 서버당신의 컴퓨터/컨테이너
파일 권한업로드한 파일에 한해 읽기현재 디렉터리 읽기/쓰기
셸 명령 실행제한적(샌드박스 내에서만)로컬 셸 직접 실행 (권한 모델로 통제)
장기 작업한 응답 단위여러 단계 자동 진행, 세션 재개 가능

3.1 어떤 도구를 골라야 하는가 — 결정 트리

(시작) — 작업이 코드베이스 안에서 "여러 파일/명령"을 만지나?
         ├─ 예 → Claude Code
         └─ 아니오 → 작업이 "한 번의 응답"으로 끝나는가?
                       ├─ 예 → Claude (웹/데스크톱)
                       └─ 아니오 → 자동화/제품화가 필요한가?

                                       └─ 아니오 → Claude (프로젝트로 묶어 반복 사용)

3.2 같이 쓰는 "이중 무대" 패턴

  1. 설계는 Claude(데스크톱)에서 — 화이트보드에 그림 그리듯 토론, 트레이드오프 정리, ADR 초안 작성.

  3. 리뷰는 다시 Claude에서 — PR을 첨부해 "놓친 보안 이슈는 없는가?"와 같은 별도 시점의 점검.

4. 시작하기 — Claude (웹·데스크톱·API)

4.1 계정 만들기와 플랜 고르기

  1. claude.ai에 접속해 회사 이메일 또는 Google 계정으로 가입합니다.
  2. 개인은 Free → Pro, 팀은 Team, 큰 조직은 Enterprise를 검토합니다. Pro부터는 모델 선택과 사용량이 넉넉해져 본격적으로 일에 쓰기 좋습니다.
  3. 회사 도메인 SSO가 필요하다면 Team/Enterprise 플랜에서 관리자에게 초대를 요청하세요.

4.2 첫 대화 — 효과적인 프롬프트의 모양

좋은 첫 프롬프트는 역할 + 목표 + 제약 + 형식의 네 박자를 갖춥니다.

역할: 당신은 시니어 백엔드 엔지니어입니다.
목표: 아래 첨부된 access.log에서 비정상 트래픽 패턴을 찾아주세요.
제약: 200줄 이상은 인용하지 말고, 발견 사항은 표로 정리.
형식: (1) 요약, (2) 발견 사항 표, (3) 권장 조치 3가지

4.3 API로 처음 호출해 보기

# macOS / Linux
export ANTHROPIC_API_KEY="sk-ant-..."

# Python
import anthropic
client = anthropic.Anthropic()

msg = client.messages.create(

const client = new Anthropic();

4.4 비용 통제 — 첫 주에 해 둘 일

  1. 워크스페이스 단위로 월 사용 한도(usage limit)를 설정합니다.
  2. 모델별로 알림 임계치(예: 한도의 50%, 80%)를 켭니다.
  3. 가능한 곳은 Sonnet로 시작해 "필요할 때만 Opus"로 승급하도록 코드에서 모델을 변수화합니다.
  4. 긴 시스템 프롬프트는 프롬프트 캐싱을 적용해 입력 토큰 비용을 줄입니다.
주의: API 키는 클라이언트 코드(브라우저, 모바일 앱)에 절대 임베드하지 마세요. 키가 새는 가장 흔한 경로는 깃허브 퍼블릭 리포의 .env.example입니다.

  2. API 키 인증: ANTHROPIC_API_KEY 환경 변수 사용 (Workspace 단위 과금).

5.3 슬래시 명령 — 자주 쓰는 작업 단축

명령하는 일
/init현재 코드베이스를 분석해 CLAUDE.md를 자동 생성.
/review현재 브랜치의 변경 사항(PR)을 리뷰.
/security-review대기 중인 변경에 대한 보안 관점 리뷰.
/clear현재 세션의 대화 컨텍스트를 비움.
/compact대화 이력을 요약본으로 압축해 토큰 절약.
/cost지금까지 세션의 토큰·비용 추정치 출력.
/model현재 세션의 모델 변경(예: Sonnet ↔ Opus).
/help사용 가능한 명령 전체 목록.

5.4 훅(Hook) 설정으로 안전망 깔기

훅은 특정 이벤트(예: 도구 호출 전, 도구 호출 후, 세션 시작)에서 실행되는 셸 스크립트입니다.

// ~/.claude/settings.json (일부)
{
  "hooks": {
    "afterToolUse": [
      {
        "match": { "tool": "Write|Edit" },
        "command": "npm run -s lint:fix && npm run -s format"
      }
    ]
  }
}

5.5 MCP 서버 등록 — 외부 시스템 연결

MCP(Model Context Protocol)는 "이 도구는 이런 함수를 가진다"를 표준화한 규약입니다.

# 자주 쓰는 MCP 서버 예시
claude mcp add github   npx @modelcontextprotocol/server-github
claude mcp add slack    npx @modelcontextprotocol/server-slack
claude mcp add linear   npx @modelcontextprotocol/server-linear
claude mcp add postgres npx @modelcontextprotocol/server-postgres
claude mcp list   # 등록 현황 확인

5.6 권장 초기 설정 체크리스트

  1. ~/.claude/CLAUDE.md에 "나의 기본 설정"을 적습니다.
  2. ./CLAUDE.md에 프로젝트 규칙을 적습니다.
  3. ~/.claude/settings.json에 모델·권한·훅을 명시합니다.
  4. 자주 쓰는 작업은 슬래시 명령으로 만들어 둡니다(예: /changelog).
  5. git 사용자 이름·이메일을 점검합니다 — 에이전트가 만들 커밋의 작성자가 됩니다.
실전 팁: 처음 1주일은 새 브랜치(git switch -c claude/sandbox)에서만 Claude Code를 돌리세요. 무엇을 어떻게 바꾸는지 감을 잡고 나서 메인 워크플로우로 들이는 게 안전합니다.

7.3 시나리오 ③ — CI에서 자동 PR 리뷰

# .github/workflows/claude-review.yml
name: Claude PR Review
on: { pull_request: { types: [opened, synchronize] } }
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - name: Install Claude Code
        run: npm i -g @anthropic-ai/claude-code
      - name: Run review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          claude --print --no-tty \
            --command "/review" \
            --output-format markdown > review.md
      - name: Comment PR
        uses: marocchino/sticky-pull-request-comment@v2
        with: { path: review.md }

7.4 좋은 작업 단위의 모양

  • 1시간 단위: 너무 크면 컨텍스트가 흩어지고, 너무 작으면 사람이 직접 하는 편이 빠름.
  • 피드백 루프 존재: 단위 테스트, 타입체크, 린트, 빌드 — 자동으로 "맞다/틀리다"를 알려주는 기준이 있어야 한다.
  • 한 번에 하나의 의도: "리팩터 + 새 기능"보다 "리팩터"→"새 기능"이 거의 항상 더 빠르다.

8.1 슬래시 명령 만들기

슬래시 명령은 본질적으로 이름이 붙은 프롬프트입니다. ~/.claude/commands/ 또는 ./.claude/commands/에 마크다운 파일을 두면 자동 등록됩니다.

# ~/.claude/commands/changelog.md
---
description: 현재 브랜치의 변경 사항으로 CHANGELOG 항목을 만든다

당신은 이 리포의 릴리즈 매니저이다.
git diff main...HEAD 의 변경을 읽고
- 추가된 기능
- 수정된 버그
- 호환성 깨지는 변경
세 섹션의 마크다운 항목을 만들어라.

8.2 MCP — Model Context Protocol

MCP는 "모델이 호출할 수 있는 도구"를 표준 JSON-RPC로 정의한 규약입니다. 한 번 등록하면 Claude·Claude Code·Claude in Chrome 등 어떤 인터페이스에서도 같은 방식으로 쓰입니다.

8.3 자체 MCP 서버 만들기 (예시)

// my-time-mcp/server.ts (TypeScript, 약식)
import { Server } from "@modelcontextprotocol/sdk/server";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio";

const server = new Server({ name: "time", version: "1.0.0" });

server.tool("now", { description: "현재 ISO-8601 시각 반환" }, async () => {
  return { content: [{ type: "text", text: new Date().toISOString() }] };
});

await server.connect(new StdioServerTransport());

8.4 자동화 원칙

"두 번째로 같은 짓을 할 때"에 자동화한다.
한 번이면 그냥 하고, 두 번이면 슬래시 명령, 세 번이면 플러그인 또는 MCP로 승격.

9.2 팀 도입 — 단계별 로드맵

  2. 2~4주차 — 팀 표준화: 리포에 CLAUDE.md·./.claude/commands를 커밋. PR 자동 리뷰를 도입.
  3. 5주차+ — 사내 플러그인: 도메인 MCP·플러그인을 만들어 마켓플레이스에 게시. 신입 온보딩에 활용.

9.3 측정 — 도입 효과를 어떻게 볼 것인가

지표측정 방법

10. 프롬프트 작성과 컨텍스트 관리 베스트 프랙티스

10.1 프롬프트의 황금 4요소

역할: 당신은 [구체적 직무]이다.
목표: [한 문장으로 끝나는 결과물].
제약: [반드시 지킬 사실/금기].
형식: [표/JSON/3단 마크다운/코드 블록 등].

10.2 "예시(few-shot)"의 힘

모호한 지시 100자보다 잘 만든 예시 1개가 답을 빠르게 좋게 만듭니다. 예시 입력→예시 출력 형태로 1~3개를 보여주고 실제 입력은 마지막에 붙이세요.

10.3 "생각 단계"를 분리하기

복잡한 문제는 한 번에 답을 시키기보다 단계를 따로 출력하게 시키면 정확도가 오릅니다.

1) 문제를 한 문장으로 다시 표현.
2) 가능한 접근 방법 3가지 비교(장단점).
3) 가장 좋은 방법을 골라 의사코드.
4) 코드 작성.
5) 테스트 시나리오 5가지.

10.4 "좋은 프롬프트 vs 나쁜 프롬프트" 5선

  • 코드 리뷰 — 나쁜: "이 코드 봐줘." / 좋은: "시니어 백엔드 리뷰어 시점으로 정확성/가독성/테스트/보안 4축에서 '수정 필수/제안/좋음' 3단으로 봐줘."
  • 디버깅 — 나쁜: "이 에러 고쳐줘." / 좋은: "아래 스택트레이스를 분석해 가능한 원인 3가지를 가능성 순으로 정렬, 1번 원인을 좁힐 수 있는 가장 작은 재현 코드를 만들어 줘."
  • 새 기능 — 나쁜: "OTP 도입해줘." / 좋은: 대상 사용자, 기존 시스템 상태, 원하는 흐름과 출력 형식을 모두 명시.
  • 데이터 변환 — 나쁜: "이 CSV를 정리해줘." / 좋은: 변환 규칙을 단계별로 명시하고 결과 스키마를 먼저 보여달라고 요청.
  • 회의록 — 나쁜: "요약해줘." / 좋은: "결정/액션아이템/책임자/마감 4열 표로만. 모호한 발언은 '그 외' 섹션에 분리."

10.5 한국어 작업을 위한 팁

  • 코드 식별자는 영어로, 설명은 한국어로 — 모델은 이를 매우 자연스럽게 처리합니다.
  • 고유명사가 자주 등장하면 시스템 프롬프트에 "용어집"을 작은 표로 적어두세요(번역 흔들림 방지).
  • 존댓말/평어, 톤(브랜드 가이드)을 명시하세요. 예: "문서는 ~다 체, 슬랙 메시지는 ~요 체".

11. 보안·비용·한계

11.1 보안의 3가지 축

  • 데이터 — 무엇을 모델에 보내는가. PII·시크릿은 마스킹/제거 후 전달.
  • 실행 — 누가 어디서 명령을 실행하는가. 권한 모델·플랜 모드·훅으로 통제.
  • 아이덴티티 — API 키·토큰의 발급/회수가 빠르게 되는가.

11.3 비용 통제

  1. 모델 변수화: process.env.MODEL ?? "claude-sonnet-4-6"으로 코드를 두면 라인업 갱신·승급이 한 줄.
  2. 캐싱: 시스템 프롬프트·자주 첨부되는 문서는 프롬프트 캐싱으로 입력 토큰 비용 절감.
  3. Haiku로 라우팅: 분류·간단 변환은 Haiku → 필요 시 Sonnet/Opus로 핸드오프.

11.4 한계 — 솔직히 말해 두는 것

  • 최신 정보: 모델 자체의 학습 데이터는 시점이 있습니다. 최신 라이브러리 시그니처는 항상 공식 문서로 검증.
  • 수치 계산: 큰 숫자/금융 계산은 모델에만 맡기지 말고 도구(파이썬, 계산기 MCP)로 검증.
  • 비결정성: 같은 프롬프트에 약간 다른 답이 나올 수 있음. 자동화에서는 출력 검증 단계를 두세요.
  • 책임: 머지·배포 결정은 사람의 책임. 에이전트는 어시스턴트이지 결정권자가 아닙니다.
주의: 회사 코드를 모델에 보낸다는 사실은 "내부 데이터의 외부 노출"에 해당합니다. 회사의 데이터 보호 정책과 보안팀 검토를 함께 진행하세요.

12. FAQ

Q1. Claude와 ChatGPT의 차이는?

둘 다 대화형 AI 어시스턴트라는 점은 같지만, Claude는 긴 컨텍스트 처리와 형식이 정해진 출력의 일관성이 강점으로 평가받습니다. Claude Code처럼 로컬 코드베이스에서 동작하는 에이전트형 도구를 같은 모델 라인업으로 함께 제공한다는 점도 특징입니다.

Q2. Claude Code는 인터넷이 끊겨도 동작하나요?

아니오. 모델 호출 자체가 Anthropic 서버와의 통신이라 네트워크는 필요합니다. 다만 코드와 명령은 모두 로컬에서 실행됩니다.

Q3. Opus와 Sonnet, 언제 골라야 하나요?

대부분 Sonnet이 답입니다. Opus는 긴 추론·여러 단계의 설계·미묘한 코드 마이그레이션처럼 "생각"을 많이 해야 하는 작업에서 차이를 보입니다.

Q4. Claude Code의 Plan Mode를 항상 켜야 하나요?

익숙해지기 전 1~2주는 권장합니다. 이후에는 "파괴적 작업(파일 삭제·git push·외부 네트워크)에만 켜기"가 일반적인 균형점입니다.

Q5. Plugin과 MCP는 무엇이 다른가요?

MCP는 "도구를 모델에 어떻게 노출할지의 프로토콜"이고, Plugin은 "슬래시 명령·MCP·스킬을 묶어 배포하는 패키지 단위"입니다. MCP는 '부품', Plugin은 '완제품'에 가깝습니다.
