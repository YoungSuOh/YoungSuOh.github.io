캐시는 자주 조회되는 데이터를 메모리 저장소(예: Redis)에 두어 DB 부하를 줄이고 응답 시간을 단축하는 전략이다.

대표 전략

  • Cache Aside: 읽을 때 캐시 미스면 DB 조회 후 캐시 저장
  • Write Through: 쓰기 시 DB+캐시 동시 반영
  • Write Back: 캐시 우선 반영 후 비동기 DB 반영

핵심 운영 이슈

  • 무효화 정책: 업데이트 시 캐시 삭제/갱신
  • TTL: 너무 길면 stale data, 너무 짧으면 hit ratio 저하
  • 스탬피드: 동시 만료로 DB 급증 (락/랜덤 TTL로 완화)
// Cache Aside pseudo
String key = "user:" + userId;
User user = redis.get(key);
if (user == null) {
    user = userRepository.findById(userId);
    redis.setex(key, 300, user);
}
return user;
