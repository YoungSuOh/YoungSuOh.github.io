Java Serialization

직렬화는 객체를 바이트 스트림으로 바꿔 저장·전송 가능하게 하는 과정이고, 역직렬화는 그 스트림을 다시 객체로 복원하는 과정입니다.

OS마다 메모리 주소 체계가 다르므로, 참조만 전달할 수 없고 바이트 형태로 옮깁니다.

직렬화가 필요한 이유

  • 서로 다른 시스템 간에도 바이트 스트림이면 주소에 의존하지 않고 데이터를 주고받을 수 있습니다.
  • 파일 저장, 네트워크 전송, 세션·캐시 영속화(RMI 등)에 활용됩니다.

객체는 그대로는 파일/네트워크로 보낼 수 없고, byte[] 등으로 변환해야 합니다.

JSON 등 텍스트 포맷과 비교하면, 자바 직렬화는 타입·메타정보를 포함해 크기가 커질 수 있어 트래픽 비용이 이슈가 될 수 있습니다.

예제: 직렬화

class Customer implements Serializable {
    int id;
    String name;
    String password;
    int age;
    // 생성자, toString ...
}
Customer customer = new Customer(1, "John", "Doe", 30);
String fileName = "Customer.ser";
try (FileOutputStream fos = new FileOutputStream(fileName);
     ObjectOutputStream oos = new ObjectOutputStream(fos)) {
    oos.writeObject(customer);
} catch (IOException e) {
    e.printStackTrace();
}

예제: 역직렬화

try (FileInputStream fis = new FileInputStream(fileName);
     ObjectInputStream in = new ObjectInputStream(fis)) {
    Customer deserialized = (Customer) in.readObject();
    System.out.println(deserialized);
} catch (IOException | ClassNotFoundException e) {
    e.printStackTrace();
}

요약·주의

  • 통신·저장을 위해 직렬화/역직렬화를 사용합니다.
  • serialVersionUID는 클래스 변경과 호환성 관리에 중요합니다.
  • 스키마가 자주 바뀌거나 외부 라이브러리 객체는 직렬화를 피하는 편이 안전합니다.
  • 역직렬화 실패·보안 예외 처리는 필수입니다.
  • 용량이 크면 JSON 등 다른 포맷을 검토합니다.

JSON 포맷이 직렬화 바이너리보다 용량·호환 측면에서 유리한 경우가 많습니다.
