• Java Flight Recorder (JFR)
    • JVM 내부에서 발생하는 성능 이벤트를 매우 낮은 오버헤드로 기록하는 프로파일링 기능
    • 항공기의 Flight Recorder(블랙박스)와 유사하게 동작한다.
  • JDK Mission Control (JMC) — JFR 파일을 시각적으로 분석하는 GUI 도구
JFR = 데이터 수집기
JMC = 데이터 분석기

🤔 왜 필요한가?

운영 환경에서 다음과 같은 문제가 발생할 수 있다.

  • CPU 사용률 급증
  • GC pause 증가
  • 메모리 누수
  • 스레드 데드락
  • 특정 메서드가 느림
  • Allocation 폭증

이러한 문제를 파악하려면 JVM 내부 이벤트를 관찰해야 하는데, 일반적 프로파일러는 오버헤드가 커서 운영 환경에서 부담이 될 수 있어 만들어졌다.

JFR이 수집하는 이벤트

1. CPU 관련

  • Method Profiling
  • Hot Methods
  • Execution Samples

2. Memory 관련

  • Object Allocation
  • TLAB Allocation
  • Outside TLAB Allocation

3. GC 관련

  • Young GC
  • Full GC
  • Heap Usage
  • Pause Time

4. Thread 관련

  • Thread Sleep
  • Monitor Enter
  • Thread Park
  • Deadlock

5. I/O 관련

  • File Read/Write
  • Socket Read/Write

6. Lock 관련

  • Contended Lock

7. Exception 관련

  • Exception Throw

JFR의 장점

  1. 매우 낮은 오버헤드
  2. JVM 내부 통합 — 별도 Java Agent 없이 JVM 자체 기능으로 동작.
  3. 운영 환경 사용 가능 — 실서비스에서 장시간 켜 둠.
  4. 이벤트 기반 — 샘플링과 이벤트 기록을 통해 필요한 정보만 저장.

JMC (JDK Mission Control)

JMC는 JFR 파일을 분석하는 GUI 도구다.

.jfr 파일을 열어서 다음 정보를 시각적으로 확인할 수 있다.

  • CPU Hotspots
  • Memory Allocation
  • GC Activity
  • Thread 상태
  • Lock Contention
  • Exception 발생 빈도

시각적 분석

✅ 자주 쓰는 jcmd JFR 명령

# 현재 활성 기록 목록
jcmd <pid> JFR.check

# 1분 프로파일 (트러블슈팅용)
jcmd <pid> JFR.start name=adhoc duration=60s settings=profile \
  filename=/tmp/profile.jfr

# 무제한 시작 (운영용)
jcmd <pid> JFR.start name=continuous settings=default \
  maxage=1h maxsize=500m

# 진행 중인 기록의 현재 시점 스냅샷
jcmd <pid> JFR.dump name=continuous filename=/tmp/now.jfr

# 중지
jcmd <pid> JFR.stop name=continuous

# 사용 가능한 설정/이벤트 목록
jcmd <pid> JFR.configure
