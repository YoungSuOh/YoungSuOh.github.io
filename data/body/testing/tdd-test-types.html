테스트 종류 한눈에

테스트 종류 목적 범위 속도 대표 도구
단위 테스트 (Unit Test)클래스/메서드 하나 검증매우 작음매우 빠름JUnit, Mockito
통합 테스트 (Integration Test)여러 컴포넌트 협력 검증중간느림Spring Boot Test
인수 테스트 (Acceptance Test)요구사항 만족 여부 검증전체 시스템더 느림Rest Assured
E2E 테스트 (End-to-End Test)사용자 시나리오 전체 검증전체 시스템 + 외부 의존가장 느림Selenium
회귀 테스트 (Regression Test)기존 기능이 깨지지 않았는지 확인다양한 범위상황별모든 테스트
성능 테스트 (Performance Test)응답 시간/처리량 검증시스템 전체별도 환경k6
계약 테스트 (Contract Test)서비스 간 API 계약 검증서비스 간중간Spring Cloud Contract

테스트 피라미드

  • 위로 갈수록 느리고 유지비가 큼

1. 단위 테스트 (Unit Test)

하나의 클래스 또는 메서드가 독립적으로 올바르게 동작하는지 검증

예시: 할인 계산기

public class DiscountCalculator {
    public int apply(int price, int discountPercent) {
        return price - (price * discountPercent / 100);
    }
}

JUnit 테스트

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class DiscountCalculatorTest {

    @Test
    void shouldApplyDiscount() {
        DiscountCalculator calculator = new DiscountCalculator();

        int result = calculator.apply(10000, 10);

        assertEquals(9000, result);
    }
}
  • DB 없음
  • 네트워크 없음
  • 매우 빠름

2. 통합 테스트 (Integration Test)

여러 컴포넌트가 함께 제대로 동작하는지 검증
  • Service + Repository
  • Repository + Database
  • Controller + Service

예시

@Entity
public class User {
    @Id @GeneratedValue
    private Long id;
    private String email;
}

public interface UserRepository extends JpaRepository<User, Long> {
    Optional<User> findByEmail(String email);
}

import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;

@DataJpaTest
class UserRepositoryTest {

    @Autowired
    private UserRepository userRepository;

    @Test
    void shouldFindUserByEmail() {
        User user = new User();
        user.setEmail("test@example.com");
        userRepository.save(user);

        Optional<User> found =
                userRepository.findByEmail("test@example.com");

        assertTrue(found.isPresent());
    }
}
  • 실제 DB 사용 (보통 H2 Database)
  • 단위 테스트보다 느림

3. 인수 테스트 (Acceptance Test)

비즈니스 요구사항을 만족하는지 검증

예시

  • "사용자는 회원가입할 수 있어야 한다."

회원 가입 API

@RestController
@RequestMapping("/users")
public class UserController {

    @PostMapping
    public ResponseEntity<Void> signup(
            @RequestBody SignupRequest request) {
        // 회원가입 처리
        return ResponseEntity.status(201).build();
    }
}

Rest Assured 테스트

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class UserAcceptanceTest {

    @LocalServerPort
    int port;

    @Test
    void userCanSignup() {
        RestAssured.given()
            .port(port)
            .contentType("application/json")
            .body("""
                {
                  "email": "test@example.com"
                }
                """)
        .when()
            .post("/users")
        .then()
            .statusCode(201);
    }
}
  • 실제 HTTP 요청
  • 사용자 관점
  • 요구사항 검증

이외 여러 테스트

1. E2E 테스트 (End-to-End)

  • 프론트엔드 → 백엔드 → DB → 외부 시스템까지 전체 흐름 검증

2. 회귀 테스트 (Regression Test)

  • 새 기능 추가 후 기존 기능이 깨지지 않았는지 검증

3. 성능 테스트 (Performance Test)

  • 시스템이 목표 처리량과 응답 시간을 만족하는지 검증
  • 대표 도구: k6, Apache JMeter
