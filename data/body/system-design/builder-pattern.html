빌더 패턴(Builder Pattern)은 객체 생성 패턴 중 하나로, 객체의 생성 과정과 표현 방법을 분리하여 복잡한 객체를 단계적으로 생성할 수 있게 해주는 디자인 패턴입니다.

주로 생성자나 setter를 사용해 객체의 속성을 설정하는 방식이 직관적이지 않거나, 너무 많은 파라미터로 인해 코드가 복잡해질 때 유용하게 쓰입니다.

빌더 패턴의 기본 개념

빌더 패턴은 객체 생성 시 필요한 다양한 속성을 한 단계씩 설정해가며 최종 객체를 생성하는 방식입니다.

생성하려는 객체의 클래스와 별도의 빌더 클래스를 만들어 사용자가 빌더 객체에 필요한 속성을 설정하면, 빌더가 이를 모아 최종적으로 객체를 생성합니다.

빌더 패턴 사용 구조

public class Person {
    private final String name;
    private final int age;
    private final String address;

    private Person(Builder builder) {
        this.name = builder.name;
        this.age = builder.age;
        this.address = builder.address;
    }

    public static class Builder {
        private String name;
        private int age;
        private String address;

        public Builder setName(String name) {
            this.name = name;
            return this;
        }

        public Builder setAge(int age) {
            this.age = age;
            return this;
        }

        public Builder setAddress(String address) {
            this.address = address;
            return this;
        }

        public Person build() {
            return new Person(this);
        }
    }
}
  • 위 예시에서 Person 객체는 Builder 클래스를 통해 생성됩니다.
  • Builder는 필드별 setter 형태의 메서드를 제공하고, 각 메서드는 Builder를 반환해 메서드 체이닝이 가능합니다.
  • 최종적으로 build()를 호출하면 Person 객체가 반환됩니다.
  • 필수 필드와 선택 필드를 구분하기 쉽고, 생성 코드 가독성도 좋아질 수 있습니다.

필수 필드(생성자) + 선택 필드(체이닝) 예시

public class Person {
    private final String name;
    private final int age;
    private final String address;

    private Person(Builder builder) {
        this.name = builder.name;
        this.age = builder.age;
        this.address = builder.address;
    }

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }

    public String getAddress() {
        return address;
    }

    public static class Builder {
        private String name;
        private int age;
        private String address;

        public Builder(String name) {
            this.name = name;
        }

        public Builder age(int age) {
            this.age = age;
            return this;
        }

        public Builder address(String address) {
            this.address = address;
            return this;
        }

        public Person build() {
            return new Person(this);
        }
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + ", address='" + address + "'}";
    }
}

main

public class Main {
    public static void main(String[] args) {
        Person person = new Person.Builder("John Doe")
                .age(25)
                .address("123 Main St")
                .build();

        System.out.println(person);
    }
}

출력 결과

Person{name='John Doe', age=25, address='123 Main St'}

빌더 패턴의 장점

  1. 가독성: 생성자나 setter만 쓸 때보다 의도가 드러나게 작성할 수 있습니다.
  2. 불변 객체 생성 가능: 생성 시점에 필드를 모두 채운 뒤 외부에서 바꾸지 않으면 불변 객체에 잘 맞습니다.
  3. 유연성: 필수·선택 파라미터를 나누고 필요한 필드만 단계적으로 설정할 수 있습니다.
  4. 복잡한 객체 생성: 필드가 많을 때 생성 절차를 단계별로 쌓아가기 쉽습니다.

빌더 패턴의 단점

  1. 클래스가 복잡해짐: 빌더 클래스를 따로 두므로 코드량이 늘고 초기 구성 비용이 있습니다.
  2. 자원·성능: 빌더 인스턴스가 추가로 생기며, 매우 빈번한 생성 경로에서는 오버헤드를 고려해야 할 수 있습니다.
  3. 유지보수성: 필드가 자주 바뀌면 빌더와 본 클래스를 함께 수정해야 합니다.
