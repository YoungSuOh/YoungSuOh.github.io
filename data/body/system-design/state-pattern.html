한 줄 정의

객체의 내부 상태를 클래스로 분리해 상태별 행위를 캡슐화하는 패턴.

문제 상황

  • 주문 상태(결제완료/배송중/배송완료/취소)에 따라 가능한 동작이 달라질 때
  • if-else/switch 분기가 계속 증가하는 상황

Java 예제

interface OrderState {
    void next(OrderContext ctx);
    String name();
}

class PaidState implements OrderState {
    public void next(OrderContext ctx) { ctx.setState(new ShippingState()); }
    public String name() { return "PAID"; }
}

class ShippingState implements OrderState {
    public void next(OrderContext ctx) { ctx.setState(new DeliveredState()); }
    public String name() { return "SHIPPING"; }
}

class DeliveredState implements OrderState {
    public void next(OrderContext ctx) { throw new IllegalStateException("already delivered"); }
    public String name() { return "DELIVERED"; }
}

class OrderContext {
    private OrderState state = new PaidState();
    void setState(OrderState state) { this.state = state; }
    void proceed() { state.next(this); }
    String currentState() { return state.name(); }
}

장점 / 단점

  • 장점: 상태별 책임 분리, 전이 규칙 명확화
  • 단점: 상태 클래스 수 증가
