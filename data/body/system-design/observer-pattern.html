한 줄 정의

Subject의 상태 변화가 발생하면 등록된 Observer들에게 자동으로 알림을 전파하는 패턴.

문제 상황

  • 주문 완료 시 알림, 쿠폰, 포인트 등 후속 작업이 계속 늘어나는 상황
  • 핵심 로직이 부가 로직에 강하게 결합되는 문제

Java 예제

import java.util.*;

interface OrderObserver {
    void onCreated(long orderId);
}

class SmsObserver implements OrderObserver {
    public void onCreated(long orderId) { System.out.println("sms: " + orderId); }
}

class PointObserver implements OrderObserver {
    public void onCreated(long orderId) { System.out.println("point: " + orderId); }
}

class OrderSubject {
    private final List<OrderObserver> observers = new ArrayList<>();

    void subscribe(OrderObserver observer) { observers.add(observer); }

    void createOrder(long orderId) {
        // 핵심 비즈니스
        System.out.println("create order: " + orderId);
        // 이벤트 전파
        for (OrderObserver observer : observers) observer.onCreated(orderId);
    }
}

장점 / 단점

  • 장점: 발행자-구독자 결합도 감소, 확장 쉬움
  • 단점: 이벤트 흐름 추적이 어려워질 수 있음

실무 포인트

  • Spring에서는 ApplicationEventPublisher + @EventListener로 구현 가능
  • 트랜잭션 경계를 고려해 동기/비동기 이벤트를 분리하는 것이 중요
