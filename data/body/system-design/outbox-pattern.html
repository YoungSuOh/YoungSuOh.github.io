Outbox 패턴

1. Outbox

DB 트랜잭션과 메시지 브로커의 일관성을 유지하기 위해 사용되는 패턴이다.

  1. 서비스에서 DB에 변경을 저장하는 동시에 메시지 브로커에 이벤트를 발행해야 할 때, 두 작업이 원자적으로 수행되지 않으면 정합성이 깨질 수 있다.
  2. 예시
    1. 사용자가 주문을 생성(order 테이블에 INSERT)
    2. 이벤트 브로커(Kafka)에 “주문 생성됨” 이벤트 발행
    3. 주문 데이터는 DB에 반영됐는데 브로커에는 메시지가 나가지 않은 경우 → 이벤트 유실 가능
    4. 반대로 이벤트 발행 후 DB 커밋 전에 장애가 나면? → 이벤트와 실제 데이터 불일치
  3. 그래서 메시지를 브로커에 바로 보내지 않고, 먼저 DB(Outbox 테이블)에 기록한 뒤 별도 프로세스가 읽어 브로커로 전달한다.
  4. 동작 흐름
    1. 애플리케이션이 비즈니스 데이터와 함께 이벤트를 아웃박스 테이블에도 저장한다.
    2. DB 트랜잭션이 커밋되면 이벤트 행도 함께 영속화된다.
    3. 별도 프로세스(폴링 또는 CDC)가 Outbox에서 이벤트를 읽어 메시지 브로커로 전송한다.
    4. 전송이 끝나면 해당 레코드를 삭제하거나 전송 완료 상태로 갱신한다.
