Isolation Level
여러 트랜잭션이 동시에 DB에 접근할 때, 서로 간의 작업에 대해 어느 정도 격리를 해줄지 결정하는 설정
⚖️
격리 수준이 낮으면 동시성↑/일관성↓, 높으면 일관성↑/동시성↓. 트레이드오프를 이해해야 한다.

4단계 격리 수준

Level 0: Read Uncommitted

특징
다른 트랜잭션이 커밋하지 않은 수정 내용까지 읽을 수 있음
문제
Dirty Read 발생 가능
실무
거의 사용 안 함

Level 1: Read Committed

특징
커밋된 데이터만 읽을 수 있음
문제
Dirty Read 방지, but Non-Repeatable Read 가능
실무
Oracle, PostgreSQL 기본값

Level 2: Repeatable Read

특징
트랜잭션 시작 시점 스냅샷 기준, 같은 SELECT 반복해도 동일 결과 보장
문제
Non-Repeatable Read 해결, but Phantom Read 가능

Level 3: Serializable

특징
가장 엄격. 트랜잭션이 순차적으로 실행된 것과 동일한 효과(직렬화)
장단
Phantom Read도 방지, but 동시성 성능 크게 저하

3가지 문제 현상

Dirty Read
커밋되지 않은 수정 중 데이터를 다른 트랜잭션이 읽음
Non-Repeatable Read
같은 SELECT를 두 번 실행했는데, 다른 트랜잭션이 변경·커밋해서 결과가 달라짐
Phantom Read
같은 조건의 범위 조회 사이에 INSERT/DELETE가 발생해 새 행이 나타남
