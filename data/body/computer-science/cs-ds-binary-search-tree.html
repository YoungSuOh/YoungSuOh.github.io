BST
이진 탐색 + 연결 리스트. 이진탐색의 O(logN) 탐색 + 연결리스트의 O(1) 삽입/삭제를 모두 가지는 자료구조

특징

  • 각 노드의 자식이 2개 이하
  • 왼쪽 자식 ⟨ 부모 ⟨ 오른쪽 자식
  • 중복된 노드 없어야 함

중복이 없어야 하는 이유?

💭
검색 목적 자료구조인데 중복이 많으면 검색 속도 저하. 중복은 노드에 count 값을 두어 처리하는 게 효율적.

BST의 순회는 중위 순회 (왼쪽 → 루트 → 오른쪽) — 정렬된 순서로 읽을 수 있음.

핵심 연산

  • 검색·삽입·삭제
  • 트리 생성·삭제

시간 복잡도

균등 트리
O(log N)
편향 트리
O(N) — 한쪽으로만 뻗음

삽입·검색·삭제 시간복잡도는 트리의 Depth에 비례

삭제의 3가지 Case

1leaf 노드
그냥 삭제
2자식 1개
자식을 위로 올리기
3자식 2개
오른쪽 서브트리의 최솟값 or 왼쪽 서브트리의 최댓값으로 대체
⚠️
정렬된 상태 값을 트리로 만들면 한쪽으로만 뻗는 편향 트리가 되어 O(N). 트리 사용 이유 사라짐 → AVL Tree, Red-Black Tree로 해결
