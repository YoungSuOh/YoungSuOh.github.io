Hash
키(key)와 값(value)을 매핑하여 데이터를 저장하는 구조. 빠른 검색·삽입·삭제 가능. HashMap, HashTable, Dictionary 등

구성 요소

해시 함수
키를 일정 범위 인덱스로 변환
해시 테이블
해시 함수로 데이터를 저장하는 배열
해시 충돌
서로 다른 키가 동일 인덱스로 매핑

좋은 해시 함수의 조건

빠른 계산
고유한 값
충돌 최소화
균등한 분포
눈사태 효과
입력이 비슷해도 해시값은 크게 다름

충돌 해결

1. 체이닝 (Chaining)

같은 해시값이면 연결 리스트로 저장

장점
유연한 저장, 테이블 부족해도 OK
단점
추가 메모리(포인터), 탐색 속도 저하

2. 오픈 어드레싱 (Open Addressing)

충돌 시 다른 빈 공간을 찾아 저장

선형 탐사
index = (hash + i) % size
이차 탐사
index = (hash + i²) % size
이중 해싱
index = (hash1 + i × hash2) % size

시간 복잡도

연산평균최악 (충돌 많을 때)
검색O(1)O(n)
삽입O(1)O(n)
삭제O(1)O(n)

해시 버킷 동적 확장

Load Factor
Load Factor = 저장 데이터 / 버킷 개수. 보통 0.7~0.8 초과 시 버킷 확장

Rehashing

1버킷 크기 증가
보통 2배
2모든 데이터 다시 해싱
새 크기에 맞춰 재배치
⚠️
버킷 크기가 바뀌면 해시 값도 달라짐 → 모든 기존 데이터를 새 테이블에 다시 해싱해야 함

Java HashMap은 load factor 0.75 초과 시 자동 리해싱.
