Index
데이터를 효율적으로 검색하기 위해 테이블의 특정 열(또는 조합)에 대해 생성되는 데이터 구조. 책의 색인처럼 동작

1. 기본 개념

검색 속도
순차 탐색 없이 빠르게 데이터를 찾음
저장 공간
인덱스 저장을 위한 추가 디스크 공간 필요
수정 비용
삽입/삭제/업데이트 시 인덱스도 갱신 → 성능 영향

Index 생성 예제

-- 단일 열 인덱스
CREATE INDEX idx_user_name ON users(name);

-- 복합 인덱스
CREATE INDEX idx_user_name_email ON users(name, email);

-- 고유 인덱스
CREATE UNIQUE INDEX idx_unique_email ON users(email);

2. Index 종류

B-Tree
대부분의 RDBMS 기본. 정렬된 상태로 저장, 탐색·삽입·삭제 효율적
Hash
정확한 매칭 검색에 유리, 범위 검색 부적합
Bitmap
값 범위가 작거나 중복 많은 경우. 데이터 웨어하우스에서 사용
Full-text
텍스트 검색에 최적화, 긴 텍스트의 키워드 검색

3. 장단점

장점
검색·정렬·그룹화 성능 향상, 중복 데이터 방지(UNIQUE)
단점
인덱스 많으면 INSERT/DELETE/UPDATE 성능 저하, 추가 저장 공간, 너무 많으면 오히려 성능 저하

4. Sequence와의 차이

특징IndexSequence
역할빠른 검색고유 순차 숫자 생성
대상특정 열테이블 독립
속도검색 속도 향상직접 영향 없음
관리테이블 연관독립 객체
실무: Sequence로 PK 생성 → PK에 자동으로 인덱스 생성. 시퀀스는 값 생성, 인덱스는 빠른 조회

5. 실전 예시: 쇼핑몰 상품 테이블

-- 상품명 단일 인덱스
CREATE INDEX idx_product_name ON products (name);
SELECT * FROM products WHERE name = 'Laptop';  -- 빠른 조회

-- 카테고리 + 가격 복합 인덱스
CREATE INDEX idx_category_price ON products (category, price);
SELECT * FROM products
WHERE category = 'Electronics' AND price BETWEEN 500 AND 1500;
