HTTP

HTTP
서버/클라이언트 모델을 따라 데이터를 주고 받기 위한 프로토콜. 인터넷에서 하이퍼텍스트를 교환하는 통신 규약. 80번 포트 사용
  • 애플리케이션 레벨 프로토콜, TCP/IP 위에서 작동
  • Stateless 프로토콜
  • Method, Path, Version, Headers, Body
🚨
HTTP는 평문 데이터 전송 → 비밀번호·주민등록번호 등을 주고받으면 제3자가 조회 가능. 이 문제 해결 위해 HTTPS 등장

HTTPS

HTTPS
HTTP에 데이터 암호화가 추가된 프로토콜. 443번 포트 사용. 중간 제3자가 정보를 볼 수 없도록 암호화

대칭키 vs 비대칭키

대칭키
클라이언트와 서버가 동일한 키로 암호화·복호화. 키 노출 시 위험, 연산 속도 빠름
비대칭키
공개키 + 개인키 쌍. 키 노출되어도 안전, 연산 속도 느림

비대칭키 동작

공개키 암호화
공개키로 암호화 → 개인키로만 복호화. 나만 볼 수 있음
개인키 암호화
개인키로 암호화 → 공개키로만 복호화. 신뢰성 보장

HTTPS 동작 과정 (Hand-Shaking)

🔐
핵심: 처음 연결 성립하여 안전하게 세션키를 공유하는 과정에서 비대칭키 사용. 이후 데이터 교환에서 빠른 속도를 위해 대칭키 사용
1클라이언트 연결 시도
2서버 공개키 전달
인증서 형태로
3인증서 검증 + 세션키 발급
4공개키로 세션키 암호화 전송
5서버 개인키로 복호화
세션키 획득
6동일 세션키로 데이터 암호화 통신
