Tree
값을 가진 노드(Node)와 노드들을 연결해주는 간선(Edge)으로 이루어진 자료구조

특징

  • 사이클 존재할 수 없음 (사이클 있으면 그래프)
  • 모든 노드는 자료형으로 표현 가능
  • 루트에서 한 노드로 가는 경로는 유일
  • 노드 N개면 간선 N-1개

트리 순회 방식

전위 순회 (pre-order)
부모 → 왼쪽 → 오른쪽
중위 순회 (in-order)
왼쪽 → 부모 → 오른쪽 (정렬된 순서)
후위 순회 (post-order)
왼쪽 → 오른쪽 → 부모
레벨 순회 (level-order)
계층 별로 방문 (BFS)

트리를 사용하는 이유

1. 탐색 속도 향상 🚀

⚡
배열에서 탐색: O(n) / 이진 탐색 트리: O(log n)

예시: BST, B-Tree(DB 인덱스), Trie(문자열 검색)

2. 효율적 데이터 저장 & 구조화 📂

부모-자식 관계가 있는 계층적 데이터에 적합

Root ├── Users │ ├── Alice │ ├── Bob │ └── Charlie ├── Program Files └── Windows

예시: 파일 시스템, HTML DOM, 회사 조직도

3. 유연한 확장성 🔄

배열은 크기 고정·삽입/삭제 어렵지만 트리는 동적 크기 조절

예시: B-Tree, B+Tree (DB 인덱스), AI 의사결정 트리

4. 최적화된 경로 탐색 🛤️

경로 찾기에 최적

예시: 네트워크 라우팅, 다익스트라, A* 알고리즘
