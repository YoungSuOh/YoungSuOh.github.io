흐름 제어 (Flow Control)

흐름 제어
송신측과 수신측 사이의 데이터 처리 속도 차이를 제어하여 수신자 버퍼 오버플로우 방지

1. Stop & Wait

매번 패킷에 대해 ACK를 받으면 다음 패킷 전송. 하나씩 보내므로 비효율

2. Sliding Window

수신측 윈도우 크기만큼 송신측이 ACK 없이 패킷 전송. 데이터 흐름 동적 조절

📦
윈도우 크기: 송신자가 한 번에 전송 가능한 최대 패킷 개수. 수신자가 ACK에 담아 보낸 TCP 헤더(window size)

혼잡 제어 (Congestion Control)

혼잡 제어
데이터의 양이 라우터 처리량을 초과하면 손실 → 재전송 → 네트워크 혼잡. 송신측 전송 속도를 적절히 조절

1. AIMD (Additive Increase / Multiplicative Decrease)

합 증가 / 곱 감소. 패킷 하나씩 보내고 문제 없으면 윈도우 +1, 실패하면 ÷2.

단점: 모든 대역 활용까지 오래 걸림

2. Slow Start (느린 시작)

윈도우 크기를 1, 2, 4, 8... 지수적으로 증가시키다 혼잡 감지 시 윈도우를 1로

3. Fast Retransmit (빠른 재전송)

3 중복 ACK 받으면 타임아웃 전에 즉시 재전송

4. Fast Recovery (빠른 회복)

혼잡 시 윈도우를 1이 아닌 반으로 줄이고 선형 증가
