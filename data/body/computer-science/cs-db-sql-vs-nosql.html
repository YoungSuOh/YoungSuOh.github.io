프로젝트에 적합한 DB를 선택해야 한다. 단순히 프레임워크에 따라 결정하는 것이 아니다.

관계형 데이터베이스 (SQL)

RDBMS의 두 가지 핵심 특징
① 데이터는 정해진 스키마에 따라 테이블에 저장
② 데이터는 관계를 통해 여러 테이블에 분산
  • 스키마를 준수하지 않은 레코드는 추가 불가
  • 중복을 피하기 위해 '관계'를 이용
  • 한 테이블에서 중복 없이 하나의 데이터만 관리 → 부정확 위험 ↓

비관계형 데이터베이스 (NoSQL)

NoSQL
스키마도 없고, 관계도 없다. 레코드를 문서(documents)라 부름. JSON과 비슷한 형태
  • 다른 구조의 데이터를 같은 컬렉션에 추가 가능
  • 여러 테이블에 나누어 담지 않고 동일한 컬렉션에 넣음
  • JOIN 개념 없음 → 컬렉션 데이터 복제로 처리

확장 방식

수직 확장 (Scale-up)
서버 성능 향상 (CPU 업그레이드). SQL이 주로 사용
수평 확장 (Scale-out)
서버 추가 분산. NoSQL에서만 가능

SQL 사용이 적합한 경우

복잡한 관계
은행, ERP, CRM — 외래키·JOIN으로 관계 관리, ACID 보장
고정 스키마
회계, 재고 관리 — 정형 데이터, 무결성 보장
잦은 데이터 변경
전자상거래 — 중복 최소화, 일관성 유지
트랜잭션 중요
온라인 결제 — 원자성 보장

NoSQL 사용이 적합한 경우

스키마 불확실
스타트업 초기 — schema-less, 빠른 변경
대량 데이터
IoT, 로그 — 분산 처리, 수평 확장
읽기 중심
SNS 뉴스피드, 캐시 — 빠른 읽기 최적화
수평 확장
아마존, 넷플릭스 — 서버 추가로 확장
비정형 데이터
JSON API, 이미지 메타데이터 — Document-Oriented
