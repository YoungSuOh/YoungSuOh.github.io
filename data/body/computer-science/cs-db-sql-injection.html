SQL Injection
해커에 의해 조작된 SQL 쿼리문이 데이터베이스에 그대로 전달되어 비정상적 명령을 실행하는 공격 기법

공격 방법

1. 인증 우회

-- 정상 쿼리
SELECT * FROM USER WHERE ID = "abc" AND PASSWORD = "1234";

-- SQL Injection 공격
SELECT * FROM USER WHERE ID = "abc" AND PASSWORD = "1234" OR 1=1;
🚨
OR 1=1이 항상 TRUE이므로 WHERE 조건이 무조건 통과되어 비밀번호 없이 로그인 가능

2. 데이터 노출

의도적으로 에러를 유발시켜 응답 메시지로 DB 구조 유추.

방어 방법

1. 화이트리스트 입력 검증

String idPattern = "^[a-zA-Z0-9]{4,20}$";
if (!input.matches(idPattern)) {
    throw new IllegalArgumentException("Invalid input");
}

2. 권한 분리 (최소 권한)

DB 계정은 읽기 권한만, 수정 권한은 차단. 뷰(View) 활용.

3. PreparedStatement (가장 중요)

⚠️
문제 코드: 사용자 입력을 그대로 SQL에 연결
String query = "SELECT * FROM USERS WHERE username = '"
    + username + "' AND password = '" + password + "'";
✅
해결: PreparedStatement로 바인딩
String query = "SELECT * FROM USERS WHERE username = ? AND password = ?";
PreparedStatement pstmt = connection.prepareStatement(query);
pstmt.setString(1, username);
pstmt.setString(2, password);

특수문자 '는 SQL 문법의 의미를 잃고 데이터로 escape 처리됨.

4. ORM 사용

// JPA
return entityManager.createQuery(jpql, User.class)
    .setParameter("username", username)
    .getSingleResult();

// Spring Data JPA
User findByUsername(String username);

ORM은 기본적으로 SQL 바인딩과 escaping을 처리한다.
