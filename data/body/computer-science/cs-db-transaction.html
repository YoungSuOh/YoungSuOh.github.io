트랜잭션
데이터베이스의 상태를 변화시키기 위해 수행하는 작업 단위. SQL 질의어를 통해 DB에 접근하는 것

SELECT도 트랜잭션?

📌
데이터 변경(INSERT/UPDATE/DELETE)만 트랜잭션이라 생각하기 쉽지만, SELECT도 isolation level 안에서 수행되므로 DBMS 입장에선 트랜잭션 범위에 들어간다. REPEATABLE READ나 SERIALIZABLE에선 같은 SELECT를 여러 번 실행해도 동일 결과를 보장해야 함.

작업 단위 예시

사용자 A가 사용자 B에게 만원 송금

1A의 잔고 차감
UPDATE A
2B의 잔고 증가
UPDATE B

두 UPDATE가 모두 성공해야 Commit, 하나라도 실패하면 Rollback.

ACID — 트랜잭션의 4가지 특성

Atomicity
원자성 — 모두 반영되거나 전혀 반영되지 않아야 함
Consistency
일관성 — 처리 결과는 항상 일관성 있어야 함
Isolation
독립성 — 둘 이상의 트랜잭션이 동시 실행 시 서로 끼어들 수 없음
Durability
지속성 — 성공한 트랜잭션 결과는 영구 반영

Commit vs Rollback

Commit
하나의 트랜잭션이 성공적으로 끝났고 DB가 일관성 있는 상태임을 알림
Rollback
비정상 종료로 원자성이 깨진 경우, 마지막 일관성 상태(트랜잭션 시작 상태)로 복귀
