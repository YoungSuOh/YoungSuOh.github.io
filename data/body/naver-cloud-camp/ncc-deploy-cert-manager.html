다음처럼 값을 넣으면 된다.

각각 키의 의미

  • cert.pem
    • 역할: 도메인에 대한 SSL 인증서 (서버 인증서).
    • 설명: 인증 기관이 해당 도메인 소유를 확인한 후 발급한 인증서입니다. 웹 서버가 클라이언트와 통신할 때 자신의 신원을 증명하는 데 사용합니다.
  • chain.pem
    • 역할: 중간 인증서 (Certificate Chain).
    • 설명: 클라이언트가 신뢰할 수 있는 루트 인증 기관까지 인증 경로를 구축할 수 있도록 중간 인증서를 제공합니다.
  • fullchain.pem
    • 역할: 전체 인증서 체인.
    • 설명: 서버 인증서와 중간 인증서를 결합한 파일로, 보통 웹 서버 설정에서 사용됩니다. cert.pem과 chain.pem을 합친 형태입니다.
    • ⭐ 여기서 보통 원래 3가지 값이 나와야 한다. A → B (certbot이나 다른 중간자 역할)→ 나
      • 따라서 처음과 끝만 복사하면 된다.
      • ex) 
        -----BEGIN CERTIFICATE-----  => 처음
...
-----END CERTIFICATE-----

-----BEGIN CERTIFICATE-----
...
-----END CERTIFICATE-----

-----BEGIN CERTIFICATE-----   => 끝
...
-----END CERTIFICATE-----
    • 하지만 certbot에서는 ‘B → 나’ 의 정보밖에 주어지지 않았다. 따라서 우리는 A의 정보를 찾아 떠나야 했다.
  • privkey.pem
    • 역할: 개인 키 (Private Key).
    • 설명: 인증서 요청을 생성할 때 사용된 개인 키입니다. 이 키는 비밀로 유지되어야 하며, 인증서와 함께 SSL/TLS 연결을 설정할 때 사용됩니다. 절대로 유출되지 않도록 주의해야 합니다.

A를 찾아 떠나보자

  • certbot 홈페이지를 들어간다. 이후 버튼을 눌러 인증서를 확인한다.
  • 그러면 다음과 같이 인증서 뷰어 화면이 나온다.
  • 루트 인증서를 내보낸다.
  • 인증서의 값을 Certificate Chain의 2번째에 넣는다

인증서 체인이란 (Certificate Chain)

인증서 체인은 SSL/TLS에서 클라이언트(브라우저 등)가 서버의 인증서를 신뢰할 수 있도록 여러 개의 인증서를 연결한 구조를 의미한다.

이는 서버의 인증서에서 시작해, 신뢰할 수 있는 루트 인증 기관(Root CA)까지 인증 경로를 만드는 과정으로, 이를 통해 클라이언트는 서버가 신뢰할 수 있는 기관에서 발급한 인증서를 사용하는지 확인할 수 있다.

구성 요소

  1. 서버 인증(Server Certificate)
    1. 특정 도메인(ex : www.dr-rate.com)에 대해 발급된 인증서이다. 이 인증서는 도메인의 소유권을 확인한다
    2. 파일명 : cert.pem 또는 인증 기관에서 제공한 서버 인증서 파일
  2. 중간 인증서(Intermediate Certificate)
    1. 루트 인증서와 서버 인증서 간의 연결을 위한 중간 단계이다.
    2. 루트 인증서는 매우 중요하기 때문에 직접적으로 서버 인증서를 발급하지 않고, 중간 인증서를 통해 인증서를 발급한다.
    3. 중간 인증서는 루트 인증서에 의해 서명되었다
    4. 파일명 : chain.pem
  3. 루트 인증서(Root Certificate)
    1. 인증서 체인의 최상단에 위치하는 신로의 기준
    2. 웹 브라우저와 같은 클라이언트는 미리 루트 인증서를 신뢰하도록 설정되어 있다

인증서 체인의 동작 원리

  1. 서버는 클라이언트(브라우저)와의 HTTPS 연결을 시작할 때, 자신의 인증서(cert.pem)와 중간 인증서(chain.pem)를 제공한다.
  2. 클라이언트는 다음 과정을 통해 서버 인증서를 검증한다.
    1. 서버 인증서가 중간 인증서에 의해 서명되었는지 확인
    2. 중간 인증서가 루트 인증서에 의해 서명되었는지 확인
    3. 루트 인증서가 클라이언트의 신뢰 저장소(Trust Store)에 포함되어 잇는지 확인
  3. 모든 인증 경로가 유효하다면, 클라이언트는 서버가 신뢰할 수 있는 도메인이라는 것을 확인하고 SSL / TLS 연결을 허용한다.
