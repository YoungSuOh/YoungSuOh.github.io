리눅스 파일 시스템

1) 파일 이름

  • 파일을 식별하기 위한 이름.
  • 동일한 디렉터리 안에서는 파일 이름이 중복될 수 없음.
  • 대소문자를 구분함 (File과 file은 다름).

2) 파일 데이터

  • 파일이 실제로 저장하고 있는 내용.
  • 텍스트, 바이너리, 이미지 등의 데이터.

3) 메타데이터

  • 파일 자체에 대한 정보를 저장.
  • 파일의 속성을 포함하며, 이를 확인하려면 ls -l 명령어를 사용.
    • 예: 파일 크기, 권한, 소유자, 그룹, 생성/수정/접근 시간.

4) 아이노드(inode)

  • 파일의 메타데이터와 데이터가 저장된 위치 정보를 관리.
  • 아이노드 번호는 파일 시스템에서 파일을 고유하게 식별.

메타데이터 vs I-node

  • 메타데이터
    • 메타데이터는 파일 자체에 대한 정보를 말하며, 파일 내용과는 별개로 파일의 속성, 상태, 위치 등을 저장
    • 주요 요소
      • ls -l 명령어를 실행하면 아래와 같은 정보가 나오는데, 이것이 메타데이터의 일부다. 
        -rwxr-xr-- 1 user group 12345 Nov 25 12:00 file.txt
        • 파일 권한: 파일에 대한 읽기, 쓰기, 실행 권한 (rwxr-xr--).
        • 링크 수: 하드 링크의 개수 (1).
        • 소유자와 그룹: 파일의 소유 사용자와 소유 그룹 (user, group).
        • 파일 크기: 파일의 크기(바이트 단위, 12345).
        • 수정 시간: 마지막으로 수정된 날짜와 시간 (Nov 25 12:00).
        • 파일 이름: file.txt.
      • 메타데이터의 역할
        • 파일의 속성을 정의하여 파일에 대한 관리와 접근을 가능하게 함.
        • 예를 들어, 권한을 통해 누가 이 파일을 읽거나 쓸 수 있는지 제어.
  • 아이노드
    • 아이노드는 파일에 대한 구조적 정보를 포함하지만, 파일 이름은 포함하지 않아. 다음과 같은 항목이 아이노드에 포함됨
      • 파일 크기
      • 파일 유형 (일반 파일, 디렉터리, 심볼릭 링크 등)
      • 파일 권한 및 소유자 정보
      • 파일의 데이터 블록 위치 정보
      • 링크 수
      • 파일 생성, 수정, 접근 시간
💡

간단한 비유

파일 시스템을 도서관이라고 생각하면:

  • 아이노드: 책의 고유 번호 (책의 위치와 상세 정보를 담고 있음).
  • 메타데이터: 책 표지에 적힌 제목, 저자, 출판일 등의 정보.
  • 파일 이름: 책이 서가에 정리되어 있는 레이블.

파일 시스템 구조와 경로

리눅스 파일 시스템은 트리 구조로 구성되어 있으며, 파일의 위치는 절대 경로와 상대 경로로 접근할 수 있다.

  • 절대 경로: /부터 시작하는 경로. (/ 가 루트 경로)
    • 예: /home/user/file.txt
  • 상대 경로: 현재 디렉터리를 기준으로 한 경로.
    • 예: ../file.txt (상위 디렉터리의 파일).
  • 일반 파일 (ASCII 파일 & 바이너리 파일)

리눅스 디렉토리 계층

주요 디렉터리

  • /bin
    • 시스템의 기본적인 실행 파일(명령어)들이 위치합니다.
    • 예: ls, cp, mv 같은 필수 명령어.
  • /etc
    • 시스템 설정 파일들이 저장됩니다.
    • 예: 네트워크, 사용자 계정, 서비스 설정 파일.
  • /usr
    • 사용자가 설치한 프로그램과 라이브러리가 저장됩니다.
    • 하위 디렉터리로 bin, lib 등이 포함되어 있으며, 각종 실행 파일과 라이브러리가 여기 저장됩니다.
  • /home
    • 사용자별 데이터와 파일이 저장되는 디렉터리입니다.
    • 예: 각 사용자의 개인 디렉터리 (user1, user2 등).
  • /boot
    • 부팅과 관련된 파일이 저장됩니다.
    • 예: 커널 이미지 파일, 부트 로더 설정 파일.
  • /dev
    • 하드웨어 장치 및 기타 디바이스 파일이 저장됩니다.
    • 예: sda(디스크), tty(터미널).

파일 링크 - 하드 링크

  • ⭐ 파일은 하드 링크의 갯수가 0이 됐을 때 삭제된다.

파일 링크 - 심볼릭 링크

  • 하드 링크 vs 심볼릭 링크
    구분하드 링크심볼릭 링크
    정의대상 파일에 대한 복제대상 파일에 대한 참조(Shortcut)
    저장 방식원본 파일의 아이노드(inode)를 공유원본 파일 경로를 저장
    파일 시스템 제약같은 파일 시스템 내에서만 생성 가능서로 다른 파일 시스템에서도 생성 가능
    원본 삭제 시 영향원본 파일 삭제해도 데이터 유지원본 파일 삭제 시 링크가 깨짐
    디렉터리 링크 가능디렉터리 링크 불가능디렉터리를 링크 가능 (ln -s)
    아이노드 공유같은 아이노드를 공유공유하지 않음 (독립된 아이노드 할당)
    크기크기는 원본과 동일링크 파일 크기는 원본 경로 길이에 따라 결정
    속도원본과 동일한 속도원본 파일을 참조하므로 느릴 수 있음
    링크 수 제한파일 시스템의 링크 수 제한 적용링크 수 제한 없음
    관리 편리성원본 파일 이동해도 링크는 유지원본 파일 이동 시 링크 경로가 깨질 수 있음
