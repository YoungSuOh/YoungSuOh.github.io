  • StringBuilder
    • StringBuilder를 사용하는 주된 이유는 문자열을 조작할 때 성능을 향상시키기 위해서이다.
    • String 객체는 불변(immutable)이라서 문자열을 변경할 때마다 새로운 String 객체가 생성된다. → 메모리와 CPU 리소스 소모 多
    • StringBuilder는 가변(mutable) 객체로 문자열을 조작할 때 새로운 객체를 생성하지 않고 내부 버퍼를 수정하기 때문에 성능이 훨씬 더 좋다.
    • 예시
      • “25” + “36” 을 하려는데 각각 String 타입으로 만들면 “25”, “36”, “2535” 3개가 만들어지는데
      • String Builder를 사용하면 편집이 가능하기 때문에 “25”에 뒤에 “36”을 붙여서 편집하여 “2536” 하나가 완성이 된다.
    • 주요 용도
      • 문자열을 빈번하게 추가, 변경, 삭제하는 경우
        • ex) 반복문 내에서 문자열을 연결해야 하는 상황

📄 Final

  • final
    • 상수화 : 값을 변경하지 못하게 끔 한다
    • final 변수는 값을 변경할 수 없다. 따라서 초기 값이 주어져야 한다.
    • final 변수는 대문자로만 기술한다.
    • ⭐ final 메서드는 override할 수 없다 → 부모가 절대 안 물려주는 메서드
    • final 클래스는 자식 클래스를 가질 수 없다. → 상속이 안된다.
    • static final 필드는 static 구역에서 초기 값을 주어야 한다. 
          public static final String FRUIT4;  // static은 생성자로 초기화 x
    static {
        FRUIT4="기린";  // static 구역에서 초기화를 시켜줘야 한다.
    }
  • 예시 코드

📄 추상 클래스 (Abstract)

  • 추상 클래스 ( 만능 리모컨 )
    • sub class(자식 클래스) 제어
    • 자식한테 억압을 해주는 것 → ?? 뭔소리지..
      • 부모는 내 밑에 자식이 얼마나 있는지 모름 → 따라서 제어가 안됨
      • 따라서 abstract를 써줌으로써 자식한테 반드시 override를 해줘야 한다는 제어(억압)를 할 수 있다.
    • 이를 통해 통일성을 높일 수 있다.
  • 추상 메서드
    • 메서드에 body { }가없는 메서드를 추상 메서드 라고 한다.
    • abstract 키워드가 들어가야 함.
    • 추상메소드가 있는 클래스는 반드시 추상클래스이어야 한다.
    • 추상메소드가 없는 추상클래스를 의미상의 추상클래스라고 한다
      • 의미상의 추상클래스의 메소드는 모두 빈body로 되어 있다.
    • 추상클래스는 자신의 클래스로 메모리 생성을 할 수 없다
      • 생성 방법
        1. Sub Class를 이용 (반드시 Sub Class가 추상메소드를 Override 해야 한다)
        2. 메소드를 이용 (추후 nested class에서 다뤄볼 예정)
    • 추상메소드는 반드시 Sub Class에서 Override 꼭 해 주어야 한다. Override를 안하면 Sub Class 마저도 abstract 가 되어야 한다.

📄 Input/Output

  • 스트림이란 데이터가 이동하는 통로이다. 데이터가 출발지에서 도착지로 단일 방향으로 흘러가는 개념을 의미한다.
    • 데이터라는 것은 키보드 - 프로그램 / 프로그램 - 모니터 / 프로그램 - 파일 / 소켓 - 소켓으로 흐를 수 있다.
    • 이제까지 콘솔을 통한 출력은 System.out.println()을, 입력은 Scanner 객체를 당연하게 써왔는데, 사실 이것은 내부적으로 살펴봤을 때 스트림을 이용한 것이다.
  • 프로세스가 데이터의 도착지라면 입력 스트림(InputStream), 프로세스가 데이터의 출발지라면 출력 스트림(OutputStream) 이라고 불린다.

바이트 기반 스트림(숫자, 영문자)

최상위 바이트 기반 스트림 클래스, InputStream과 OutputStream

InputStream 은 바이트 기반 입력 스트림 최상위 추상 클래스이고, OutputStream 은 바이트 기반 출력 스트림 최상위 추상 클래스이다. 이들의 하위 클래스는 XXXInputStream , XXXOutputStream 이라는 네이밍을 가진다. 이를테면, FileInputStream 이 있다.

예제 코드

public class DataSteam {
    public static void main(String[] args) throws IOException {
        FileOutputStream fileOutputStream = new FileOutputStream("result.txt");  // 파일이 없으면 자동으로 생성
        DataOutputStream dataOutputStream = new DataOutputStream(fileOutputStream);

        dataOutputStream.writeUTF("홍길동");
        dataOutputStream.writeInt(25);
        dataOutputStream.writeDouble(12.5);
        dataOutputStream.close();

        DataInputStream dataInputStream = new DataInputStream(new FileInputStream("result.txt"));
        String name = dataInputStream.readUTF();
        int age = dataInputStream.readInt();
        double height = dataInputStream.readDouble();
        System.out.println("이름 = "+name+" 나이 : "+age+" 몸무게 : "+height);
        dataOutputStream.close();
    }
}

문자 기반 스트림(숫자, 영문자, 한글)

최상위 문자 기반 스트림 클래스, Reader와 Writer

Reader 는 문자 기반 입력 스트림 최상위 추상 클래스이고, Writer 는 문자 기반 출력 스트림 최상위 추상 클래스이다. 이들의 하위 클래스는 XXXReader , XXXWriter 이라는 네이밍을 가진다. 이를테면, FileReader 가 있다.

예제 코드

public class CharacterStreamExample {
    public static void main(String[] args) {
        // 파일에 데이터 쓰기
        try (FileWriter writer = new FileWriter("example.txt")) {
            writer.write("Hello, World!\n");
            writer.write("This is a test of character streams.\n");
        } catch (IOException e) {
            e.printStackTrace();
        }

        // 파일에서 데이터 읽기
        try (FileReader reader = new FileReader("example.txt")) {
            int data;
            while ((data = reader.read()) != -1) {
                System.out.print((char) data);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

바이트 기반 스트림과 문자 기반 스트림의 차이점

  • 데이터 처리 단위:
    • 바이트 스트림: 1바이트 단위로 데이터를 처리합니다. 주로 바이너리 데이터(예: 이미지, 오디오 파일)를 처리하는 데 사용된다.
    • 문자 스트림: 2바이트 유니코드 문자를 처리합니다. 주로 텍스트 데이터를 처리하는 데 사용된다.
  • 주요 클래스:
    • 바이트 스트림: InputStream과 OutputStream을 기본 클래스로 사용
    • 문자 스트림: Reader와 Writer를 기본 클래스로 사용
  • 성능 및 효율성:
    • 바이트 스트림: 모든 종류의 데이터를 처리할 수 있지만, 텍스트 데이터를 처리할 때는 문자 인코딩 문제를 신경 써야 합니다.
    • 문자 스트림: 텍스트 데이터를 처리할 때 더 적합하며, 자동으로 문자 인코딩을 처리합니다.
  • 사용 예:
    • 바이트 스트림: 이미지, 비디오, 오디오 파일 등 텍스트가 아닌 데이터 파일을 읽고 쓸 때 사용됩니다.
    • 문자 스트림: 텍스트 파일을 읽고 쓸 때 사용됩니다.

📄 객체 직렬화

  • 직렬화란?
    • 자바 언어에서 사용되는 Object 또는 Data를 다른 컴퓨터의 자바 시스템에서도 사용할 수 있도록 바이트 스트림 형태로 연속적인 데이터로 변환하는 포멧 변환 기술을 말한다.
    • JVM의 힙 혹은 스택 메모리에 상주하고 있는 객체 데이터를 직렬화를 통해 바이트 형태로 변환하여 DB 또는 파일과 같은 외부 저장소에 저장해두고, 다른 컴퓨터에 이 파일을 가져와 역직렬화를 통해 자바 객체로 변환해서 JVM 메모리에 적재하는 것으로 보면 된다.
  • 객체 직렬화
    • 객체는 파일 또는 네트워크로 전송이 안된다.
    • 객체를 byte[] 로 변환시켜서 전송해야 한다.
    • 객체를 파일에 직렬화(serialize)하여 저장하고, 저장된 객체를 다시 역직렬화(deserialize)하여 읽어오기
  • 직렬화 사용처
    • 휘발성이 있는 캐싱 데이터를 영구 저장이 필요할 때 사용할 수도 있다.
      • JVM의 메모리에서만 상주되어있는 객체 데이터가 시스템이 종료되더라도 나중에 다시 재사용이 될 수 있을 때 영속화 해두면 좋다.
      • ex) 서블릿 세션, 캐시, 자바 RMI
  • 직렬화 vs JSON
    • 자바 직렬화는 외부 파일이나 네트워크를 통해 클라이언트 간에 객체 데이터를 주고 받을 때 사용된다.
    • WHY 직렬화 instead of JSON, CSV??
    • 직렬화의 장점
      • 자바의 고유 기술인 만큼 자바 시스템에서 개발에 최적화되어 있다.

📄 Process & Thread

프로세스스레드(Thread)
운영체제로부터 자원을 할당 받은 작업의 단위프로세스가 할당받은 자원을 이용하는 실행 흐름의 단위
  • Program (Static Program)
    • 코드 덩어리임
    • 컴퓨터에서 실행할 수 있는 파일을 통칭한다.
  • 프로세스 (Process)
    • 프로세스는 프로그램을 실행시켜 정적인 프로그램이 동적으로 변하여 프로그램이 돌아가고 있는 상태이다.
    • ctrl + alt +del을 통해 돌아가고 있는 프로세스를 쉽게 확인할 수 있다.
    • 모든 프로그램은 운영체제가 실행되기 위한 메모리 공간을 할당해 줘야 실행될 수 있다. 그래서 프로그램을 실행하는 순간은 파일은 컴퓨터 메모리에 올라각 되고, 운영체제로부터 시스템 자원(CPU)을 할당 받아 프로그램 코드를 실행시켜 우리가 서비스를 이용할 수 있게 된다.
  • 정리
    프로그램프로세스
    어떤 작업을 하기 위해 실행할 수 있는 파일실행되어 작업중인 컴퓨터 프로그램
    파일이 저장 장치에 있지만 메모리에는 올라가 있지 않은 정적인 상태메모리에 적재되고 CPU 자원을 할당받아 프로그램이 실행되고 있는 상태
    쉽게 말해 그냥 코드 덩어리그 코드 덩어리를 실행한 것
  • 프로세스의 한계
    • 과거에는 프로그램을 실행할 때, 프로세스 하나만을 사용해서 프로그램을 실행하기에는 한계가 있었음.
      • 하나 다운이 완료될때까지 하루종일 기다려야 했음
    • 오늘날 컴퓨터는 파일을 다운 받으며 다른 일을 하는 멀티 작업은 너무나 당연한 기능이 됨
    • Thead는 프로세스 특성의 한계를 해결하기 위해 탄생하였다.
  • 쓰레드(Thread)
    • 하나의 프로세스 내에서 동시에 진행되는 작업 갈래, 흐름의 단위를 말한다.
      • 예를 들면 위와 같이 크롬 브라우저가 실행되면, 프로세스 하나가 생성될 것이다. 그런데 우리는 브라우저에서 파일을 다운 받으며 올라인 쇼핑을 하면서 게임을 하기도 한다.
      • 즉, 하나의 프로세스 안에서 여러가지 작업들 흐름이 동시에 진행되기 때문에 가능한 것인데, 이러한 일련의 작업 흐름들을 스레드라고 하며, 여러 개가 있다면 이를 멀티 쓰레드 라고 부른다.
    • 하나의 Process 내에 여러가지 쓰레드가 있는 모습이다.
      • 하나의 프로그램은 하나 이상의 프로세스를 가지고 있고, 하나의 프로세스는 반드시 하나 이상의 스레드를 갖는다.
      • 즉, 프로세스를 생성하면 기본적으로 하나의 main thread 가 생성이 되고, 나머지 그 이상의 스레드는 프로그래밍을 통해 개발자가 직접 프로그래밍 해줘야 한다.

        • 여기서 모니터 객체란?
          • 자바에서 모든 객체는 monitor를 가지고 있다.
          • monitor는 여러 스레드가 객체로 동시에 객체로 접근하는 것을 막는다
          • 여기서 모든 객체가 중요하다. heap 영역에 있는 객체는 모든 스레드에서 공유 가능하기 때문이다.
          • 스레드가 monitor를 가지면, monitor를 가지는 객체에 lock을 걸 수 있다
          • 그렇게 되면 다른 thread들이 해당 객체에 접근할 수가 없게된다.
      • 즉, 어떤 스레드가 이 블록을 실행하는 동안 다른 스레드는 이 블록에 들어갈 수 없다.

함수형 프로그래밍이란?

: 함수를 정의하고 이 함수를 데이터 처리부로 보내 데이터를 처리하는 기법을 말한다.

데이터 처리부는 데이터만 가지고 있을 뿐, 처리 방법이 정해져 있지 않아 외부에서 제공된 함수에 의존한다.

람다식

  • Java 8 부터 지원한다.
  • 데이터 처리부는 람다식을 받아 매개변수에 데이터를 대입하고 중괄호를 실행시킨다.
  • 자바는 람다식을 익명 구현 객체로 변환한다.
    • 인터페이스의 익명 구현 객체를 람다식으로 표현하려면 반드시 하나의 추상 메서드만 가져야 한다.
    • 인터페이스가 함수형 인터페이스임을 보장하기 위해서는 @FunctionalInterface 어노테이션을 붙이면 된다.
      • 컴파일 시 추상 메서드가 하나인지 검색하기 때문에 정확한 함수형 인터페이스를 작성할 수 있다.
      @FunctionalInterface  // 람다식이라는 어노테이션 -> 람다식은 추상 메서드 하나
public interface Compute {
    public void calc(int x, int y);
    // public void abc();  // 추상메서드 하나 이상으로 추가하면 어노테이션에 에러 뜸
}

  • 뭐하러 7 계층으로 나누어놨을까?
    • 통신이 일어나는 과정을 단계별로 파악할 수 있기 때문이다.
    • 7단계 중 특정한 곳에 이상이 생기면 다른 단계의 장비 및 소프트웨어를 건들이지 않고도 이상이 생긴 단계만 고칠 수 있기 때문이다.
    💡 문제 ) PC방에서 오버워치를 하는데 연결이 끊겼다.

    어디에 문제가 있는지 확인하기 위해서는

    모든 PC가 문제가 있다면

    라우터의 문제(3계층 네트워크 계층)이거나 광랜을 제공하는 회사의 회선 문제(1계층 물리 계층)

    한 PC만 문제가 있고

    오버워치 소프트웨어에 문제가 있다면(7계층 어플리케이션 계층)

    오버워치 소프트웨어에 문제가 없고, 스위치에 문제가 있으면(2계층 데이터링크 계층)

    있다고 판단해 다른 계층에 있는 장비나 소프트웨어를 건들이지 않는 것이다.

  1. 물리 계층(Physical Layer)
    1. 이 계층에서는 주로 전기적, 기계적, 기능적인 특성을 이용해서 통신 케이블로 데이터를 전송하게 된다.
    2. 통신 단위 : 비트 (0과 1)
    3. 데이터를 전달만 할 뿐, 전송하려는 데이터가 무엇인지, 어떤 에러가 있는지 등에는 전혀 신경쓰지 않는다.
    4. 허브: 다양한 기기들로부터 오는 전기 신호들을 받아서 그 신호들을 증폭시켜 다른 기기들로 뿌려주는 역할
    5. 리피터: 전기 신호를 정형(일그러진 전기 신호를 복원)하고 증폭하는 기능을 가진 네트워크 중계 장비.
  1. 데이터 링크 계층(Data Link Layer)
    1. 송수신되는 정보의 오류와 흐름을 관리 → 안전한 정보의 전달을 수행할 수 있도록 도와주는 역할
    2. MAC 주소를 가지고 통신
    3. 통신 단위 : 프레임(Frame)
    4. 물리 계층에서 발생할 수 있는 오류를 찾아내고, 수정하는데 필요한 기능적, 절차적 수단을 제공
    5. 브리지 : 허브와 마찬가지로 Eternet 장비를 물리적으로 연결하고 Frame의 전송거리 연장
    6. 스위치 : Mac주소와 해당 장비의 포트번호가 기록된 MAC Address 테이블을 보고 목적지에게만 Frame을 전송한다.
  1. 네트워크 계층 (Network Layer)
    1. 이 계층에서 가장 중요한 기능은 데이터를 목적지까지 가장 안전하고 빠르게 전달하는 기능(라우팅)이다. 
    2. 이 계층은 경로를 선택하고 주소를 정하고 경로에 따라 패킷을 전달해주는 것이 이 계층의 역할이다.
    3. 통신 단위 : 패킷(packet)
  1. 전송 계층(Transport Layer)
    1. 포트를 열어서 응용 프로그램들이 전송을 할 수 있게 한다.
    2. 전송 계층(Transport layer)은 양 끝단(End to end)의 사용자들이 신뢰성 있는 데이터를 주고 받을 수 있도록 해 주어, 상위 계층들이 데이터 전달의 유효성이나 효율성을 생각하지 않도록 해준다.
    3. 통신 단위 : 세그먼트(Segment)
    • port 번호, 전송방식(TCP/UDP) 결정 > TCP 헤더 붙음
      • TCP : 신뢰성, 연결지향적
      • UDP : 비신뢰성, 비연결성, 실시간
  1. 세션 계층(Session Layer)
    1. 지점간의 프로세스 및 통신하는 호스트 간의 연결 유지
    2. TCP/IP 세션 체결, 포트번호를 기반으로 통신 세션 구성
  1. 표현 계층(Presentation Layer)
    1. 전송하는 데이터의 표현방식을 결정(ex. 데이터변환, 압축, 암호화 등
    2. 파일인코딩, 명령어를 포장, 압축, 암호화
    3. JPEG, MPEG, GIF, ASCII 등
  1. 응용 계층(Application Layer)
    1. 최종 목적지로, 응용 프로세스와 직접 관계하여 일반적인 응용 서비스를 수행(ex. explore, chrome 등)
    2. HTTP, FTP, SMTP, POP3, IMAP, Telnet 등과 같은 프로토콜이 있다.

      public class ProtocolClient {
	Socket socket;  // 서버와 연결을 나타냄
	BufferedReader br;  // 서버로부터 데이터를 읽어오는데 사용
	BufferedWriter bw;  // 서버로 데이터를 보내는데 사용된다.
	Scanner sc;

	public ProtocolClient() {
		try {
			socket = new Socket("localhost", 9500);	//9500번 통로에 길 뚫어놓기
//			통신 간에 길 만들어놓기
			br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
			bw = new BufferedWriter(new OutputStreamWriter(socket.getOutputStream()));

			sc = new Scanner(System.in);

		} catch (UnknownHostException e) {
			System.out.println("서버를 찾을 수 없습니다");
			e.printStackTrace();
			System.exit(0);
		} catch (IOException e) {
			System.out.println("서버와 연결이 안되었습니다");
			e.printStackTrace();
			System.exit(0);
		}

//		한줄 단위로 읽기위해 line 생성
		String message, line;
		try {
			while(true) {
//				서버로 보내기
				System.out.println();
				System.out.print("입장은 100:대화명이라고 입력하세요 \n");
				System.out.print("퇴장하려면 200:대화명이라고 입력하세요 \n");
				System.out.print("메세지는 300:대화명:메세지라고 입력하세요 \n");
				message = sc.nextLine();

				bw.write(message + "\n");	//서버로 보내기
				bw.flush(); //io buffer에 있는 데이터값 비워주기

//				서버로부터 받기
				line = br.readLine();
				System.out.println(line);

//				200:apple -> "200", "apple" - 200 = 퇴장, apple = 대화명
				String[] ar = message.split(":");	//  :을 기준으로 분해  // line으로 해보기
				if(ar[0].equals(Protocol.EXIT)) {	// Protocol.EXIT = "200"
					br.close();
					bw.close();
					socket.close();
					System.exit(0);
				}
			}
		} catch (IOException e) {
			e.printStackTrace();
		}
	}

	public static void main(String[] args) {

	}

      public class ProtocolServer {
	ServerSocket serverSocket;  // 클라이언트와의 연결을 기다리는 소켓
	Socket socket; // 클라이언트와의 연결을 나타냄
	BufferedReader br;  // 클라이언트로부터 데이터를 읽어오는데 사용된다.
	BufferedWriter bw;  // 클라이언트로 데이터를 보내는 데 사용된다.

	public ProtocolServer() {
		try {
			serverSocket = new ServerSocket(9500);	//클라이언트 9500번 요청이 올 때까지 기다린다
			System.out.println("서버 준비 완료");

			socket = serverSocket.accept();	//클라이언트를 낚아챈 후 소켓을 생성

			br = new BufferedReader(new InputStreamReader(socket.getInputStream()));
			bw = new BufferedWriter(new OutputStreamWriter(socket.getOutputStream()));


		} catch (IOException e) {
			System.out.println("클라이언트와 연결이 안되었습니다");
			e.printStackTrace();
			System.exit(0);
		}

		String line;

		try {
			while(true) {
//				클라이언트로부터 받기
				line = br.readLine();

//				클라이언트로 보내기
				String[] ar = line.split(":");
				if(ar[0].equals(Protocol.ENTER)) {	//입장 => 100:대화명
					bw.write(ar[1] + "님이 입장하였습니다.\n");
					bw.flush();
				} else if(ar[0].equals(Protocol.EXIT)) { //퇴장 => 200:대화명
					bw.write(ar[1] + "님이 퇴장하였습니다.\n");
					bw.flush();

					bw.close();
					br.close();
					socket.close();

					System.out.println("서버 종료");
					System.exit(0);
				} else if(ar[0].equals(Protocol.SEND_MESSAGE)) { //메세지 => 300:대화명:메세지
					bw.write("[" + ar[1] + "] : " + ar[2] + "\n");
					bw.flush();
				}
			}
		} catch(IOException e) {
			e.printStackTrace();
		}
	}

	public static void main(String[] args) {
		new ProtocolServer();
	}

}
